## 3. Attribute 模块已落地内容

### 3.1 第一阶段热点收敛

当前已落地的 `Attribute` 优化主要集中在“不改核心执行语义前提下，缩小处理面与收紧热路径开销”这一目标上。

已完成的主要调整包括：

1. `ApplyModifier()` 仍然保留原有的输入分组、时间戳写入，以及 `BaseValue / CurrentValue` 分流语义，没有为了优化改写主行为边界。
2. `RecalculateAttributeBaseValues()` 与 `RecalculateAttributeCurrentValues()` 保留“合并 -> 排序 -> 执行 -> Clamp -> 事件记录 -> 约束传播”的主计算链，但加入了 `CollectTouchedAttributes()` 驱动的局部差异记录路径。
3. `EnforceAttributeRangeConstraints()` 增加了基于 `CollectDependentAttributes()` 的局部传播路径；只要依赖声明不完整或局部传播不收敛，就自动回退到原有全局 fixpoint。
4. `RemoveModifiersBySourceHandle()` 的第一阶段退化风险已收敛到批量删除 + 运行时缓存一次性重建路径：
   - `SourceHandleIdToModifierInstIds` 从 `TArray` 桶切换为 `TSet` 桶。
   - 删除路径改为 `RemoveStoredModifiersByInstIds()`，末尾统一 `RebuildModifierRuntimeCaches()`。
5. 热路径已补 `TRACE_CPUPROFILER_EVENT_SCOPE` 与 `VeryVerbose` 统计日志，后续可以直接用真实场景做 `Insights` 观测。

### 3.2 当前归档判断

1. `Attribute` 仍然是当前最值得优先继续做 Profiling 的热点模块。
2. 但它已经不再处于“只有热点判断、还没落代码”的阶段，而是已经完成第一轮保守实现。
3. 这一轮优化本质上属于“在正确性边界内缩小处理面”，而不是改写 `Attribute` 的主执行语义。

### 3.3 仍待补的数据

1. 还没有真实战斗场景下的 CPU Trace / Unreal Insights 数据，当前只能确认实现已就位，收益幅度待量化。
2. 还没有专门 benchmark 或自动化性能用例，后续仍需靠真实场景 Profile。
3. 自定义 `ClampStrategy` 如果不声明完整依赖，仍会落回全局传播；这不是缺陷，但会直接影响未来性能上限。

## 4. State / Buff / 调试路径已落地内容

### 4.1 `6.1` StateTree 状态变化 Diff 路径

1. `OnStateTreeStateChanged()` 仍然保留原有入口语义，但 `AreStateNamesEqual()` 已改为基于状态名计数表的无序比较，不再复制数组并排序。
2. `RefreshSlotsForStateChange()` 已改成差量路径：先计算 Added / Removed，再只收集受影响槽位并重算对应 Gate。
3. 组件内新增 `StateTreeStateName -> SlotTag` 反向绑定缓存；若缓存不可用，仍会保守回退到正向绑定表扫描。
4. 这条路径已经完成实现与编译验证，后续剩余工作主要是量化真实高频场景下的收益。

### 4.2 `6.2` 槽位刷新批处理

1. `RequestUpdateStateSlotActivation()` 已支持显式批处理作用域；批处理期间只累计 `PendingSlotActivationUpdates`，不立即执行刷新。
2. `BeginStateSlotActivationBatch()` / `EndStateSlotActivationBatch()` 已形成明确的批处理深度控制面。
3. `RefreshSlotsForStateChange()` 与批量移除入口现在都会在同帧内延迟重复刷新请求，并在批次末统一结算。
4. 这次实现没有引入“延迟到下一帧”的更重框架，仍然保持当前帧内完成结算，只是压掉同批次里的重复刷新。

### 4.3 `6.3` 小槽位排序短路

1. `SortStatesByPriority()` 已在入口处对 `0 / 1` 元素槽位做短路。
2. 这项调整不改变任何排序规则，只是剪掉本来不可能发生重排的场景。

### 4.4 `6.4` 批量移除优先走索引

1. `RemoveStatesByDefId()` 已不再扫描全部 `RuntimeStateSlots`。
2. 当前实现先通过 `StateInstanceIndex` 的定义名索引命中候选状态实例，再按槽位分组移除。
3. 这条路径会继续复用 `6.2` 的槽位刷新批处理，因此同槽位多状态移除只在批次末做一次最终结算。

### 4.5 `6.5` 同槽位多状态移除后只做一次最终刷新

1. `BuffComponent` 中原先直接循环 `RequestStateRemoval()` 的高频路径，已经接入既有的槽位刷新批处理。
2. `TickBuffLifecycles()` 在同一轮处理多个到期 Buff 时，会先进入批处理作用域，再逐个执行到期移除。
3. `RemoveMergedOutBuffs()` 在同一轮淘汰多个 Buff 时，也会复用同一段批处理作用域。
4. `EndStateSlotActivationBatch()` 已补上 teardown 安全收尾：如果组件或 Owner 已进入销毁流程，就不再强行排空待处理槽位请求。

### 4.6 `6.6` 调试字符串常驻路径收敛

1. 已新增模块级共享头文件 `TcsConsoleCommands.h`，统一承载最小控制台命名面。
2. 当前第一阶段只保留一个显式调试开关：`tcs.state.debug_evaluator.enable`。
3. `GetSlotDebugSnapshot()` / `GetStateDebugSnapshot()` 仍然保留为按需调试 API，但不再继续扩成 `dump / list` 型控制台查询面。
4. `FTcsSTEvaluator_SlotDebug::Tick()` 已不再默认构造槽位快照字符串；只有显式开启调试开关后，常驻路径才允许生成快照。
5. 面向目标的结构化运行时查询，后续已明确转交调试 UI 面板承担，而不是继续扩张控制台命令层。
