## 2. 族内引用的原文（逐字）

### 2.1 `TcsStateSnapshot.h:60-61`

被 `Documents/tcs-remake-v2/04-领域/Attribute.md:1068` 引用，用来论证「`Live` / `Snapshot` 这对语义归参数域」。

```
 * **命名**：实现名取设计名 `FTcsParamSnapshot`（`SPEC-02-states` §3.6 的 2026-09-14 命名批）——
 * 它是**参数域**的概念（修正器物化、技能侧参数行都要读它），不是状态模块专属。
```

类型本身的语义注释（同文件 :47-53，供核对上下文）：

```
 * 参数快照（D3-12）：状态**施加瞬间**把全部生效参数一次性求值并冻结的结果。
 *
 * **语义三条**（设计 §3.6）：
 * ① **施加那一刻求值**——施加上下文覆盖值优先、Def 默认兜底；`ValueConvention` 转换发生在写入点；
 * ② **实例生命周期内读快照**——MUST NOT 重算（"运行中升级不追溯"的既定语义；tooltip 的当前档
 *    高亮也取快照的 `Level`，而非查询时实体等级）；
 * ③ **修改 = 重新施加**（快照重建，新 payload 覆盖旧的）。
```

### 2.2 `TcsSkillOps_ParamRead.cpp:102`

被 `Documents/tcs-remake-v2/04-领域/Attribute.md:1085` 引用，用来论证「属性修正器从一开始就是实时折叠的」。

```
	// **`EPM_Live` / `EPM_Snapshot` 在本路径上同解**：两者都走实时折叠（快照只影响快照面）。
```

> ⚠️ **族内那处引用写错了出处**：`Attribute.md:1085` 写的是「`TcsCastOps_Snapshot.cpp` 注释原话」。实测 `TcsCastOps_Snapshot.cpp` 全文**不含「同解」二字**（该文件 :26-45 讲的是另一件事：「`EPM_Live` ⇒ 标记跳过，不进快照数值面」）。原话住 `TcsSkillOps_ParamRead.cpp:102`。两处的意思并不相同——**前者说「不进快照」，后者说「读口上同解」**。族内那句话若要保留，引用的应是后者，且要写明它讲的是**公共读口**而非**快照构建**。
