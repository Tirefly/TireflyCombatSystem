	Value = (有效基值 + ΣAdd) × (1 + ΣPercentAdd) × ΠMul + ΣFlatAdd

- 不恢复 Basic/Extra 两段、七带、OverrideSegment 或旧全局层公式。自身 core 是本轮对单一持久核心基值的简称，不是恢复双段。

### 3.1 两域责任与本次求值

**C6 — 同实体属性派生随动由 Attribute 维护。** 已声明力量到攻击力等关系后，力量变化应由属性能力侧继续维护。只裁能力责任，不据此要求长期图、特定缓存或结算算法；后续依赖约束见 C14–C16、C26、C71、C86–C87。

**C7 — 局部参数可撤销贡献是框架必备能力。** 不改实体攻击力和原始技能配置，仍能只给某技能数值施加可撤销额外贡献。例：攻击力 100、火球 50 + 1.2 × 攻击力 = 170，额外 +20 得 190。此项自身不裁账本、状态布局、托管生命周期。

**C8 — 可独立修正的 Parameter 必须有对应 GameplayTag 名称。** 仅必要条件：可独立修正 ⇒ 有 Tag。不能倒推任何有 Tag 的数都必须可修正，也不决定名称作用域、存储及目标匹配。

**C9 — 两域责任区分。** Attribute 负责实体共享数值状态及派生随动；Parameter 负责技能等消费者局部参数求值与独立修正语义。复用聚合算术不等于统一领域；责任区分也不等于两套账本、确定状态持有人或划成两个代码模块。

**C10 — 值描述求值与跨调用维护分离。** 单次求值仅完成本次计算，不自行建立持续依赖、保存业务快照或发布业务值变化通知；持续能力由相应框架维护者组织。允许临时状态、临时依赖信息和组合便利入口，不强制模块/入口物理拆分，不取消 Attribute 随动或 Parameter 修正状态，也不禁止读取内部按需结算。

**C11 — 本次调用提供属性读取能力。** 值描述求值不自行定位 Attribute 服务；组织求值的框架维护者可以完成接线，不要求宿主逐消费者手写适配。接口形态、角色表示和模块依赖尚未确定，不据此预建公共求值核心、注册中心或新模块。

**C12 — 必需读取失败即本次求值明确失败。** 区分失败与成功数值，不隐式用 0 或历史值；外层另行组织回退，本轮不加入描述内部的读取失败回退。例：读不到攻击力不是攻击力为 0，否则公式仍会误算出 50 伤害。错误表示与诊断细节未裁。

**C13 — 修改完成后的普通读取反映已完成修改。** 无未结束批处理且读取/计算可成功时，普通读必须反映此前完成修改及其派生影响，无需调用者额外刷新；Attribute 返回前保证。不是指定写时/读时重算，不裁批内读取或所有重入语义。

**C14 — 自动随动描述在求值前报告完整潜在属性读取集合。** 实体可待上下文绑定后确定；Attribute 经明确契约取得，不能窥探内部字段。内置描述从结构自动导出，不让用户重复写公式及依赖。不是要求所有 Parameter 描述都具备，也未确认共用类型或存图；后续完整性要求见 C87。

**C15 — 绑定后的潜在当前值计算依赖必须无环。** 含本次不执行的潜在读取，新建/变更不得建立环；不采用仅执行到环才报错的规则，不隐式联立求解。不要求长期保存依赖图；后续 C26/C71 将上下界维护关系一并纳入无环。

**C16 — 本轮必备自动随动限同实体。** 值描述仍可跨实体按次读取；不能由跨实体读取推出跨实体持续维护。本轮不要求后者，但非永久禁止。K2：周期伤害 Buff 只需每次伤害前读取 Instigator 当前攻击力；不要求两次触发间维护可查询伤害值或主动伤害变化通知。

**C17 — 派生当前值失败不回退旧成功缓存。** 普通当前读明确失败，内部可留旧缓存但不能当成功当前值；消费者回退由外层明确组织。恢复后仍遵守 C13，不要求用户额外刷新。不是规定资源持久存量遇到故障就删除，后者见 C27。

### 3.2 属性贡献、资源状态、核心基值

**C18 — Attribute 通用管理实体属性多来源贡献并存和独立撤销。** 宿主决定施加/撤销时机。来源身份、精确定位、类型、存储、托管及共用模块不由本项确定。

**C19 — 属性贡献量读取同实体其他属性时自动随动。** Attribute 维护计算贡献及其对目标的影响，撤销后该贡献关系不再影响目标。遵守完整潜在读取、无环、可见性、失败规则；不扩张 Parameter 维护责任或强制两域共用类型。

**C20 — Attribute 支持增减后持久保留的实体共享数值状态。** 宿主赋予业务含义和时机；不是只支持从配置及贡献每次重新算出的属性。此项不批准统一的“基值/当前值”双字段模型或资源分类枚举。**限定（C103）**：Def 须显式声明存储形态，在 core 型与存量型二者中选一；这只是形态声明，仍不批准双字段模型或细分资源类别的枚举。

**C21 — 资源持久扣补按最终可见量计量。** 可见 200 扣 30，目标语义是 170，不是把某聚合前 100 扣 30 后经 ×2 得 140。不是任意最终值写入，不批准逆解公式或暗加 OverrideFinal；也不证明“资源当前量受倍率贡献”必须支持，该假设后来被 C22 对生命/法力明确限缩。不能推广为 core +5 必须最终 +5。

**C22 — 当前生命/当前法力只承受持久扣补，不接受持续贡献。** 不能 30 秒 +300 当前生命；30 秒 +300 最大生命可以。HasDuration / Infinite 持续贡献不挂当前生命/法力；Heal 改的是持久状态，不是到期回收的贡献。不能把每种 Attribute 的能力都做笛卡尔积组合。上限变化是否调整存量由后续规则决定，不从“最大值贡献存在”自动推导。

**C23 — Damage / Heal 在此指通用扣减/补充方向。** 法力消耗不必经过“受伤”语义；业务流程先确定操作量及许可，再调用状态增减。并非要求所有业务都归 Damage 域。

**C24 — 当前生命随最大值下降截断，上升不自动补满。** 例：800/1000，上限升 1300 仍 800；降 600 成 600；再升不返还损失。即使下降再恢复期间没人读取，也必须保留已发生的截断，不能只读时临时 clamp。最初是生命场景，不自动扩大所有资源；C25/C71 给通用可选边界机制，Disabled 由 C58 例外处理。

**C25 — Attribute 维护宿主声明的可选同实体上限约束。** 宿主声明关联/启用，框架不内置生命法力名称；不是每个属性自动有上限。后由 C71 扩展为所有属性可配置双侧边界。

**C26 — 计算与约束维护关系合并后必须无环。** 不能只查表达式计算环。最大值依赖当前量、当前量又受最大值维护，会形成反馈；即使某公式当前可稳定也拒绝潜在环，不承诺迭代求解，不指定存图算法。

**C27 — 必需上限故障时资源当前读失败，保留存量。** 不把读不到上限当 0、不因此清零截断；持久存量不同于派生旧缓存。恢复维护细节与通知由后续规则/未决补齐。

**C28 — 单看必需上限故障，本次资源增减明确失败。** 不因缺上限仍实施扣补。用户自定义答只确认这一点，不能连带批准当时方案的全部恢复、重放或生命周期细节。

**C29 — 区分三种变更语义。** ①资源持久扣补；②已有属性核心基值 core 的变更；③可撤销来源贡献。攻击力、伤害加成、防御、攻速、移速也有如等级成长的 core 增减，不全是 Buff。例 core100 + Add20 = 120，core +5 后 125，撤贡献后 105。业务操作量的聚合是 Buff / Skill / Parameter / Damage 等消费者使用 NumericAggregator，不统统搬入 Attribute，也不据此预定调用链。

**C30 — TCS 提供宿主直接可用的四类核心基值读取/设置入口。** 支持 JSON、CSV、DataTable、CurveTable 来源，不能要求宿主为这些标准来源重复手写读取器。成长流程显式更新 core；不是自动建立数据绑定或等级随动。具体标准布局由 C31/C80–C83 补充。

### 3.3 数据入口与基本通知语义

**C31 — 首批采用 TCS 约定格式的标准数据入口。** 不要求任意宿主布局映射。调用明确记录、曲线及输入，不自动绑定成长。字段/包装与类型尚未确定，不能回填为旧类型。

**C32 — 一次多项核心基值导入整组原子。** 全部成功才生效，失败不留部分 core 更新或永久状态副作用。不是通用事务，不允许恢复以后任意时点的历史操作。合法输入引起下游求值/约束失败是否使本次更新整体失败，原留 U3；**已由 C95 收口**：通过合法性校验即整组接纳，下游按既有失败状态表现。

**C33 — 标准更新入口只更新已建立属性。** 目标缺失整组失败，创建初始化另流程；未来可有组合便利入口，但本次不隐式创建。Disabled 已建立属性的 core 写入由 C55 明确允许。

**C34 — 通用属性值变化订阅是必备能力。** Attribute 提供通知，业务响应归宿主。不因 C10 单次求值不发通知就取消维护者通知。

**C35 — 通知对外当前值实际变化，不是输入可能变化。** 例 OverrideFinal200 时 core100 改 105，当前值仍 200 不发数值变化通知。可用性另见 C40/C74；贡献明细改变不自动变成当前值变化。

**C36 — 本次关联维护完成后才进入外部通知。** 回调读到更新后的当前值或明确失败，不能看到内部维护一半的旧态；不是所有失败都必须回滚，也不是回调期间冻结状态。

**C37 — 普通独立修改返回前送达通知。** 多项 core 导入按整组处理，不逐项提前通知。不是攒到帧末；重入修改后来由 C75 给出明确例外。

**C38 — 原则允许通知回调引发后续修改。** 用户指出实际常经过成长、Buff、ApplyAttrMod、Damage 等复杂步骤，但“步骤复杂”不等于异步，仍可能同步重入。用户当时没有批准全部嵌套通知细节；后由 C75 收口。依赖无环不保证业务回调链终止，防护细节已由 C102 收口（归宿主责任）；这些消费路径不恢复旧 API 签名。

**C39 — 数值变化携带属性身份、旧值、新值。** 反映历史变化，不冻结当前状态，不表达受伤/治疗业务因果。具体载荷类型与事件 Tag 未裁。

**C40 — 可用性变化主动通知，且与数值变化分开。** 成功到失败、失败到成功不能当成变为 0，也不只等消费者下次读取发现。错误分类、生命周期边界和具体载荷未全部裁。

### 3.4 成组修正与 Parameter 暂停点

**C41 — 显式成组属性修正是必备能力。** 换旧贡献为新贡献，按成功整组结果维护派生、边界及通知，不产生组内独立生效中间态。例基础最大700+旧300=1000、当前800；组内撤旧加新300，仍800。若独立先撤再加则截成700且不返还。不是任意混合操作事务，不批准通用 Begin/Commit 接口。

**C42 — 任一请求合法性校验失败，整组修正拒绝。** 不留部分修改、持久副作用或未生效数值通知；目标非法、潜在依赖环等不能部分放行。

**C43 — 已有属性的合法成组贡献可接纳，即使当前值求不出。** 其他必需输入故障导致求值失败，不等于合法贡献不能接纳；接纳成功与当前值可用分开。非法目标/依赖仍按 C42 拒绝。不能把此规则扩为首次建立/唤醒可失败生效，也不能自动套到 core 导入。

**C44 — 同时支持实时求值与指定时点求值后保留结果。** 消费者明确选择，单次求值仍不自建持久状态。火球发射时攻击100得170，命中前变150：实时可得230，发射定值保持170。**谁持有结果尚未裁**：消费者运行态持有与 Parameter 专门存储只是已提出方案，用户暂停了该问题，并未选定任何旧冻结/Born/State结构。

### 3.5 属性身份、首次建立、Disabled 与唤醒

**C45 — 实体身份 + 属性 GameplayTag 唯一确定已建立属性。** 同实体同 Tag 同时最多一份状态。贡献/撤销身份单独判断，不因此新增属性实例句柄或确定 Tag 词表。

**C46 — 启用属性严格重复建立失败。** 不重置、不更新、不隐式引用计数。C49 后明确例外：Disabled 同 Tag 是唤醒原实例，不是违反本项的新建；首次建立与显式更新是不同操作。

**C47 — 显式成组建立，按完整候选状态校验。** 任一非法整组拒绝，无部分新属性；同组无环依赖不受声明排列影响。组内重复/已启用目标拒绝。不批准属性集资产或通用事务入口；C77 后补充混合首次建立与唤醒。

**C48 — 初始当前值及必要约束可用，整组才建立成功。** 失败无新属性及本次持久副作用，不发新属性生效值通知；不回滚此前独立完成的既有状态变更，也不保证以后不会故障。不同于 C43 已有属性合法贡献的接纳规则。

**C49 — 实体存活期属性不直接移除，只标 Disabled。** 再添加同 Tag 唤醒原实例；启用中重复仍失败，首次才创建。不能推出实体销毁后仍保留，也不恢复历史引用计数方案。

**C50 — Disabled 保留 core 和资源存量，唤醒不重新初始化。** core 已成长120不回配置100；存量600唤醒若有效上限500，可维护为500。不交付旧最终缓存冒充当前值。

**C51 — 停用不清已有贡献，正常撤销仍可执行。** 唤醒不复活停用期间已撤销条目，也不强迫有效来源重新施加。定义内贡献的普通撤销权限后来由 C66 限制；不能据本项把定义内容当动态可撤条目。

**C52 — Disabled 普通当前值读取明确失败。** 不返回0或旧最终值。保留状态查询接口未批准；core 写入/新贡献另由 C55/C56 裁定。

**C53 — 拒绝破坏启用属性必需依赖的停用。** 保持原状态，检查完整潜在计算及约束维护关系，不因本次分支未读取放行；不自动级联停用。需先明确停用依赖者才能停被依赖者。不是恢复“常驻”标记。

**C54 — 唤醒在求值和必要约束维护成功后才生效。** 失败继续 Disabled，不留本次 core/存量/贡献副作用，不发成功/恢复通知；不撤销此前独立操作，例如已经撤销的 Buff 不复活。不重新应用初值，不自动唤醒未列出的依赖；成组唤醒后见 C77。

### 3.6 停用期主动写入与资源扣补

**C55 — Disabled 可显式更新保留 core，但不启用。** 唤醒使用新值；多项导入仍整组成功/失败。允许 core 写入不等于允许普通资源扣补。**限定（C89）**：本项只对 core 型属性有意义；存量型属性没有 core，任何 core 写入都按 C89 拒绝。

**C56 — Disabled 可接纳合法新动态贡献，但不启用。** 唤醒使用仍未撤销的条目。没有因此承诺停用期间持续重算或内部自动计时。

**C57 — Disabled 普通资源扣补失败。** 保留存量，不在唤醒时补执行这些失败请求。

**C58 — Disabled 期间边界变化不调整保留存量。** 唤醒按当时有效边界维护，不补做停用期间的短暂下降/上升。最初针对上限，后双侧边界遵循同一停用规则；这是 C24 启用期持续保全截断后果的明确例外。

**C59 — 补充可部分生效到上限。** 当前800、上限1000，请求+300实际+200，最终1000；请求量不等于实际变化量。

**C60 — 资源下界为可选约束，由宿主声明、Attribute 维护。** 最初裁常量下界，不是全部资源自动0；C71 已明确扩展为可引用同实体属性当前值，不再保留“下界只能常量”的限制。**限定（C91）**：存量型属性未声明下界时，契约默认下界为常量 0；本项“不是全部资源自动0”的默认口径由此改写。宿主仍可声明其他下界或显式声明无下界，所以下界仍不是强制的。

**C61 — 普通扣减可部分生效到下界。** 当前10、下界0，请求扣30，实际扣10、最终0。不是足额支付成功；是否允许施法、是否足额等业务先行判断，不改写业务伤害量为实际变化量。

### 3.7 core、基值计算与定义内派生贡献接合

**C62 — 派生量可位于运算带贡献，且受对应覆盖语义。** 确认例：core100、力量派生 Add20，OverrideBase200 后220，力量变化仍随动。只确认该配置的语义，不是框架唯一接合方式，后见 C63。

**C63 — 基值计算与运算带贡献两种位置均可配置。** 不改持久 core，不改聚合器。不能把 agent 早先推荐基值路线当唯一已裁，也不能把用户质疑误作只选贡献路线。未裁布尔字段、任意公式无损转换、任意混合粒度或运行中切换。 **恢复会话推翻（C105）**：两种位置不再并存，BaseValue 恒为 CoreValue，派生只落运算带；本条仅作历史保留。

**C64 — 基值计算返回完整 BaseValue，不隐式加 core。** 无基值计算则直接用 core；有计算时：core100、力量10，描述写 core + 力量×2 得120，只写力量×2 得20。读自身 core 不等于读自身最终当前值，也不因提及 core 就自动形成自环。 **恢复会话推翻（C105）**：基值计算已取消，BaseValue 恒为 CoreValue；“只写力量×2 得20”的需求改为 core 配 0、派生贡献写力量×2。

**C65 — 建立描述可声明基值计算及定义内派生贡献。** Attribute 一并校验、建立、维护，建立成功包含完整定义，遵守 C47/C48；外部动态贡献仍保留。不据此确定表达式类型、两域共用类型、定义替换或去重结构。 **恢复会话限定（C105）**：Def 只声明定义内派生贡献（字段 DerivedAttrMods，见 C107），不再声明基值计算。

**C66 — 定义内派生贡献不接受普通动态撤销。** 普通撤销仅管理动态贡献；停用/唤醒保留定义内容，未来改定义另裁。禁止靠特殊 Source 或内置号码绕过正常发号，权限由领域入口控制。

**C67 — 同属性允许完整基值计算与定义内运算带贡献共存。** 各部分位置明确，不是多个基值计算叠加，不增加额外聚合层。C63 未裁任意混合的部分，被本项对这一个具体组合补齐，不能倒推任意组合全获批。 **恢复会话推翻（C105）**：基值计算已取消，本条所述共存组合不再存在。

**C68 — 所有已配置计算成功，当前值才可用。** 即使固定 OverrideFinal200，已配置基值计算的力量读取失败仍使属性不可用；不能用覆盖遮蔽失败。是 Attribute 聚合前可用性要求，不改聚合器跳过被覆盖算术的规则；初建、唤醒、可用性通知同样遵守。潜在依赖不因覆盖而消失。 **恢复会话限定（C105）**：“所有已配置计算”指已配置的派生贡献计算描述（基值计算已取消），其余不变。

**C69 — 显式更新已有动态贡献数值或计算描述，保留施加身份及 OrderSeq。** 新描述引入非法依赖时拒绝并保留旧条目；不是同来源重新施加就隐式猜成更新。未批准改目标、运算带、施加方、撤销锚点或借此改定义内贡献。**限定（C92/C93/C104）**：更新只按撤销锚点整组进行，不建单条句柄；锚点未命中则更新失败；整组替换必须同形，按组内序号一一对应，目标与运算带不变，只换数值或计算描述，全部保留 OrderSeq。

### 3.8 双侧边界、数值故障与通知恢复

**C70 — 空有效区间使当前读及资源扣补失败，保留存量。** 如下界0、上界-10，不隐式抬上界、不清零。已合法接纳的上限修改不因下游故障自动回滚；初建/唤醒仍要求整体可用。不改变 Disabled 规则。

**C71 — 所有 Attribute 都可配置双侧边界。** 每侧可无界、常量或同实体其他属性当前值；统一纳入潜在计算/维护无环检查。不是所有属性都有边界或默认零下界，不把此选项扩成跨实体持续随动。**限定（C91）**：只有存量型属性在未声明下界时默认常量 0；core 型普通属性仍不默认任何边界。资源的持久维护见 C73，普通属性最终值钳制见 C72。

**C72 — 普通属性在聚合后按有效区间 clamp 对外值。** 不改 core 或贡献；OverrideFinal 也不能绕过领域边界。边界不可读取、区间为空仍失败。只钳制缓存显示不能替代资源持久维护。

**C73 — 启用资源下界上升可永久补高存量。** 下界20升30，存量20变30；再降不扣回，是约束维护而非 Heal。与上限降低截断对称，但不意味着生命/法力可以承受持续贡献；Disabled 仍不维护，唤醒才按当时边界调整。

**C74 — 故障恢复只发可用性恢复，不补跨故障数值变化。** 120 → 不可用 → 150，恢复时不制造120→150数值通知；数值变化要求前后均可用。不是取消此前已经形成的历史通知。

**C75 — 重入修改立即生效，其通知延至当前通知轮结束。** 新通知仍在最外层修改调用返回前送完，不延帧；重入调用自己返回时，其通知可能尚未送达，是 C37 明确例外。载荷是历史变化，回调再读可见更后状态。无限业务回调链防护由 C102 收口：不保证终止、归宿主；不可宣称无环依赖保证终止。

**C76 — 同实体同轮按属性 GameplayTag 全名稳定非本地化排序。** 进入该轮通知前确定顺序，不因回调重入重新排序当前轮；不要求依赖拓扑序。跨实体、数值/可用性两类间顺序或合并策略不能从本项推出。

**C77 — 成组添加可混合首次建立与 Disabled 唤醒。** 按整体候选状态校验维护后一起生效；任一失败不留本次新建、唤醒或存量副作用。不重新初始化旧实例，不自动唤醒未列依赖，已启用目标仍重复失败。不是任意操作混合事务。

**C78 — 通知值判等为无容差的精确数值相等，正负零相等。** 不复用聚合器用于确定排序的位型全序；消费者可自己过滤微小变化。非有限值先按 C79 失败，不参与成功值比较。

**C79 — 非有限结果在 clamp 前明确失败。** 输入或中间/最终计算产生非有限值，不靠上下界变成伪成功有限值，不做静默饱和；资源持久存量按既有失败规则保留，不据此改变 core 或贡献的接纳/回滚边界。聚合器有限输入仍可溢出，领域承担检查，不修改基线。

### 3.9 四来源布局、贡献生命周期与依赖完整性

**C80 — JSON / CSV / DataTable 每条一属性，以记录标识分组。** 每项语义含记录标识、属性 GameplayTag、core 值；同一记录是一组更新。各来源可有不同外包装，不先定字段拼写或 C++ 类型，不采用每属性增列或 CSV 内嵌整集合的既定布局。

**C81 — 只更新明确列出的目标，未列出保持不变。** 不要求每次导入列齐实体全部属性；仍受目标已建立及整组原子性约束，不自动清零缺项。

**C82 — CurveTable 的行名就是属性 GameplayTag。** 一张表组织一组属性曲线，调用方明确求值输入，不增加显式“曲线行→属性”映射清单，不自动绑定成长。行名校验及具体错误表示、字段和入口签名未裁。

**C83 — 同记录同属性重复项整组拒绝，即使值相同。** 不静默覆盖、求和或以排列取赢家；不同记录出现同一属性正常。

**C84 — 施加者销毁不自动撤贡献。** 本次施加的管理能力决定结束，并按精确撤销锚点清理；施加方来源不等同生命期拥有者。不是批准贡献永远泄漏不清理，目标实体销毁时的通知与订阅行为后由 C98/C99 收口；锚点定位见 C92–C94。

**C85 — Attribute 动态贡献不自带计时。** Buff 等管理者到期撤销；属性 Disabled 不暂停外部管理时长。不因保留停用贡献复活已经到期撤销的条目。

**C86 — 自动随动只接纳 Attribute 可掌握变化的输入。** 固定配置、自身 core、同实体属性当前值可作为输入；其他外部变化须先显式写入后参与，不建立无法掌握的外部持续依赖。不是扩大 Parameter 的持续维护职责。

**C87 — Def 描述自动导出依赖，并同时使用编辑器校验和运行时读取守卫。** Def 中计算描述是依赖来源，不重复手填清单；编辑器能分析的部分先验证，运行期超过声明集合读取使本次失败并诊断，不靠实际执行补全依赖。不能声称检测任意隐藏全局访问，也不为假设的任意自定义计算新造机制。不强制与 Parameter 共用类型。

**C88 — 资源首次建立应初始化为满值。** 用户明确要求首次满值，并让关卡特殊规则在初始化之后执行；不是省略初值时才默认满值。已有有效上限时满值取该上限。**限定（C90/C91）**：没有有效上限时，首次值为契约默认 max(0, 有效下界)；未声明下界时下界默认 0，显式无下界时按 0 计。关卡特殊规则仍在初始化之后执行。**Disabled 唤醒仍保留存量，不重新补满。** 之前 agent 推荐显式当前初值，已撤回，不得作为获批默认。

### 3.11 恢复会话续编：U1–U4 收口与整体审核（C89–C104）

来源为 2026-11-26 恢复会话中用户已答的问答卡 question-1 至 question-16。各项受影响的旧条目已在 §3 原条目后补“限定”，或在本节写明收口了哪个旧未裁点。

**C89 — 存量型属性没有 core，只有持久存量。** 存量只由首次建立初值（C88/C90）与此后的扣补（C21/C59/C61）和约束维护（C24/C73/C50/C58）改变。core 更新及 JSON/CSV/DataTable/CurveTable 四类入口只要列出存量型目标，整组拒绝（受 C32 原子性约束）。资源依赖的公式输入放在边界属性上，例如最大生命是有 core 的普通属性，成长表写在最大生命上。不能把 core 导入当作任意设置当前存量的入口。收口 U1 的存量与 core 共存问题，限定 C30/C33/C55。

**C90 — 无有效上限的存量型属性，首次值为契约默认 max(0, 有效下界)。** 例：护盾类资源默认下界 0、不强制上限，首次值为 0；下界 20 则首次值为 20。不因此要求资源必须有上限，也不退回宿主显式初值作为默认。关卡特殊规则仍在初始化之后执行。限定 C88。

**C91 — 存量型属性未声明下界时，契约默认下界为常量 0。** 宿主可声明其他下界（常量或同实体属性当前值，C71），也可显式声明无下界。C61 的部分扣减因此默认落在 0。core 型普通属性的边界规则不变。限定 C60/C71。

**C92 — 动态贡献只按撤销锚点整组定位。** 撤销会清掉该锚点下的全部条目；更新是对该锚点整组做原子替换。不为单条贡献建句柄（未决-核心基线 §1 的句柄门槛）。收口 U2 的定位问题，限定 C69。

**C93 — 锚点未命中时的结果。** 锚点已撤销、已被级联清理或从未施加时，撤销是无操作，返回“未命中”，不报错、不发通知（与统一时钟 Cancel、事件总线 Unsubscribe 的未命中语义一致）；更新则失败，不隐式变成一次新施加。

**C94 — 一个撤销锚点只属于一个目标实体。** 批量清理由宿主传入一组锚点逐个撤销；整组原子性只在单实体内成立，不提供跨实体事务。收口 U2 的批清范围。

**C95 — 合法 core 更新或整组替换导致下游失败时，仍整组接纳。** 合法性校验指：数值有限、目标是已建立的 core 型属性、组内无重复，整组替换还须满足 C104。通过校验后，如果新状态令派生、边界或约束维护失败，本次写入仍整组接纳，不回滚；下游按 C27/C68/C70/C79 已定义的失败状态表现，可用性变化另行通知（C96）。先例是 C70“已合法接纳的上限修改不因下游故障自动回滚”。用户指出 C53 已排除“被依赖属性被停用”这一失败来源；下游失败仍可来自上限故障、计算失败（含 C87 越声明读取）、空有效区间和非有限值。收口 U3，补上 C32 留下的问题；初建与唤醒仍按 C48/C54 要求整体可用。

**C96 — 已建立属性在可读与不可读之间跃迁时，发可用性通知。** 原因无关：故障、恢复、Disabled、成功唤醒用同一种信号。C54 唤醒失败没有发生跃迁，不发通知。细化 C40。

**C97 — 首次建立成功发一次可用性通知（不可读→可读），不发数值通知。** 成组建立按 C76 排序，在调用返回前送达；建立失败不发任何通知。

**C98 — 实体销毁不算属性跃迁。** 属性随实体清除，不发可用性或数值通知；订阅者依据实体层或宿主信号配对注销。依据战斗实体基线 §2.2 的级联清理保证与“在途回调不保证存活”，避免在级联清理中重入。与 C75 不冲突。收口 C84 留下的目标实体销毁问题。

**C99 — 订阅目标是实体句柄加属性 Tag。** 实体须存活，否则订阅失败；属性未建立、Disabled 或已建立都可以订阅。实体注销后不再派发。订阅者配对注销，未命中时无操作（事件总线 §1.1.4/§1.1.9）。Tag 写错的订阅永远收不到派发，由编辑器校验发现。 **恢复会话限定（C109）**：属性 Tag 只用于可用性订阅；数值订阅只按实体句柄，与 C100 的实体级数值事件对应，属性筛选由订阅者读取载荷变化集完成。实体存活、注销后不派发、配对注销规则同时适用两类订阅。

**C100 — 两类通知的形态与同轮顺序。** 可用性通知逐属性立即分发，不合并。数值通知在实体级按通知轮发出：每轮每个实体一个数值事件，包含本轮全部变化属性的 Tag、旧值和新值，按 C76 的 Tag 顺序排列，在修改调用返回前送达。同一轮内先发逐属性可用性通知，再发实体数值事件。推导：同一轮同一属性最多出现在一类通知里，因为数值通知要求前后都可读，可用性通知要求其中一侧不可读。用户曾提出帧末合并分发；讨论后改选本方案，因为帧末会违反 C37/C75 的“不延帧”，并吞掉中间状态（如 1000→0→500 被合并成 1000→500，丢掉归零信号），且事件总线 §1.2 不建帧末通道。跨实体顺序未裁。

**C101 — 边界故障恢复时按当时有效边界维护存量，只发可用性恢复通知。** 例：存量 800，上限故障期间变为 600，恢复时存量持久维护为 600，只发可用性恢复，不发跨故障的数值通知（C24/C58/C74）。收口 U4 的故障恢复维护与通知边界。

**C102 — 无限业务回调连锁不保证终止，责任归宿主。** 实现可以在开发构建中做嵌套深度诊断，但不写入契约，也不改变操作成败。收口 C38/C75 的防护问题。

**C103 — Def 显式声明存储形态，core 型或存量型二选一。** 不细分资源类别，不引入基值/当前值双字段。限定 C20。

**C104 — 按锚点整组替换只允许同形。** 新旧两组按组内序号一一对应，目标和运算带不变，只换数值或计算描述，全部保留 OrderSeq；形状不符则整组失败，旧组不变。要改变形态，就撤销后用新锚点重新施加。这是把 C69 原样提升到整组层面。用户备注：Buff 升级一般不会改 AttrMod 的计算公式，真有这种需求应施加新 Buff。

### 3.12 恢复会话续编：派生结构与命名（C105–C109）

来源：恢复会话问答卡 base-structure-2、naming-n1 至 naming-n5-suffix。命名条目只确认符号名；参数与返回类型形态、持有者与编辑器校验子系统名称、事件频道 Tag 均未裁。03-词汇与命名 §1 的语义修订已获用户授权方向（C106），但尚未落文。

**C105 — BaseValue 恒为 CoreValue，派生只经定义内派生贡献落在运算带。** 不设基值公式，也不设派生位置枚举。推翻 C63/C64/C67，限定 C65/C68。用户要求按真实业务场景检验，而不是为保住已裁而推荐方案。检验结论：派生位于 Base 或 Add 带都会被 PercentAdd/Mul 放大，差别只在 OverrideBase 是否一并覆盖派生、明细里归为基值还是贡献；线性派生（力量→最大生命）、乘法派生、无自身 core 的非线性派生（core 配 0）以及变身后保留属性加成（C62）都能由运算带表达；“只作用于基础部分”的百分比（如额外攻击力、基础攻击光环）两种位置都做不到，靠属性分层（声明独立属性再派生）；“派生须被 OverrideBase 一并覆盖”未找到真实消费者。

**C106 — 存储形态、core、存量与运行态命名。** 存储形态枚举 ETcsAttributeStorage { Core, Resource }（限定 C103；Storage 指形态，不是业务分类，不违 C20）；core 字段 CoreValue（不叫 BaseValue：BaseValue 是聚合器公式起点，可被 OverrideBase 替换，与持久 core 不是同一物）；存量字段 Amount，如 ResourceAmount（不用 Current：当前值是所有属性的求值结果；不用 Pool：撞 TTcsInstancePool）。属性运行态 FTcsAttributeInstance，每实体属性集合 FTcsEntityAttributes。用户授权把 03 §1 修订为“XxxInstance 指 Def 的运行时对应物，是否走池另看”（属性不入池）。持有者与编辑器校验子系统本轮不命名。

**C107 — 修正粒度与 Def 字段命名。** 一个 UTcsAttrModDef 只修改单个属性（一个目标 Tag、一个运算带、一个数值或计算描述，对应一条 FTcsAggregateEntry），施加后对应一个 FTcsAttrModInstance；不设 Entry 类型；同一撤销锚点下的多个 Inst 组成整组，这一层不建类型。用户依据：一个 Def 对应一个属性收益最高、界限最清晰；多属性效果用多个 Def，复杂机制靠属性分层与监听更新实现。UTcsAttributeDef 字段：DerivedAttrMods（定义内派生贡献）、LowerBound / UpperBound，边界种类 ETcsAttributeBoundKind { Unbounded, Constant, Attribute }（存量型未声明下界按 C91 取常量 0）。运行时计算动词统一 Evaluate（与 EvaluateAggregatedValue/EvaluateAggregatedDetail 一致；只返回值、不写入；不用 Get，因为每次真算且可能失败）。计算描述的类型仍按 C65 未裁。

**C108 — 操作入口命名。** AddAttributes（同 Tag 已 Disabled 时视为唤醒，覆盖 C77 混合成组）；DisableAttributes（C49/C53）；ModifyResourceAmount(Tag, 带符号 Delta)，返回实际生效变化量（C23/C59/C61，不带 Damage/Heal 业务词）；SetCoreValues（C32/C81/C89）；ImportCoreValuesFromJson / ImportCoreValuesFromCsv / ImportCoreValuesFromDataTable / ImportCoreValuesFromCurveTable（C30/C80/C82/C83）；ApplyAttrMods / RemoveAttrMods / UpdateAttrMods，均以撤销锚点定位（C92/C93/C104；Update 表示只允许同形更新）。

**C109 — 通知载荷与订阅命名。** 可用性载荷 FTcsAttributeAvailabilityChangedPayload{Entity, AttributeTag, bAvailable}；数值载荷 FTcsEntityAttributesValueChangedPayload{Entity, Changes}，条目 FTcsAttributeValueChange{AttributeTag, OldValue, NewValue}。沿用用户提出的 EntityAttributesValueChanged 主干，去掉委托前缀 On；后缀用 Payload，与事件总线的“载荷 / PayloadType”用语一致，不用 Detail 以免与 FTcsAggregateDetail 撞义。订阅入口 SubscribeAttributeAvailability(Entity, AttributeTag) 与 SubscribeAttributesValueChanged(Entity)，数值订阅只按实体，限定 C99。

### 3.10 用户明确提出的编辑器校验要求（不另冒编号）
