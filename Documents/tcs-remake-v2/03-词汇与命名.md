# 词汇与命名

> **定位**：跨全族的**词汇纪律**与**命名规约**。与 [01-定位与判据](01-定位与判据.md) 同级——那份管「怎么写文档」，本文件管「怎么给东西取名」。
> **为什么单列一册**：这些规约不属于任何一个域——`Instance` 裸词禁令对 Attribute / Skill / State / Action 同等有效，`Def` 后缀横跨五个域的资产类。塞进任一域文档，其余域就看不到。

**审核状态图例**：✅ 已裁决并批准 ｜ ⚠️ 待审 ｜ ❓ 待调研

---

## 1. `Instance` MUST NOT 作裸词 ✅

> **`Instance` MUST NOT 作裸词出现；书写时 MUST 带种类前缀**（`BuffInstance` / `SkillInstance` / `ChainInstance`）。
> 核心基线那一层讲的是**通用池机制**，它不叫「Instance」。

**理由**：V1 的 `FTcsChainRun` 与 `FTcsBuffInstance` 在机制上是同一种东西——**都是 `TTcsInstancePool` 里的池元素本体**（池存 `TArray<TInstance>` 本体、不存句柄，见 [运行时实例](02-核心基线/运行时实例.md) §1.2.1）。所以 `Run → Instance` 不是引入新冲突，而是把已经在做的事说对。

**真正要防的不是「两个 Instance」，是「裸词 Instance」**：

| 说法 | 判定 |
|---|---|
| `BuffInstance` / `SkillInstance` / `ChainInstance` | ✅ 带前缀，分得清 |
| 裸说「Instance」指代核心基线那一层 | ❌ MUST NOT |

### 1.1 连带：成员名同样适用

`RunPool`（子系统成员）不能直接改叫 `InstancePool`——那会与通用模板 `TTcsInstancePool` 撞名。必须带种类前缀，改叫 `ChainInstancePool`。

---

## 2. `Def` / `DefAsset` 后缀统一为 `Def` ✅

V1 里同一件事有两种后缀：

| 资产类 | V1 后缀 | V2 写法 |
|---|---|---|
| `UTcsStateDef`（基类） | `Def` | 不变 |
| `UTcsSkillDef` | `Def` | 不变 |
| `UTcsBuffDefAsset` | `DefAsset` | **`UTcsBuffDef`** |
| `UTcsEffectChainDef` | `Def` | `UTcsActionChainDef`（域改名，见 §3） |
| `UTcsEffectTriggerDefAsset` | `DefAsset` | **`UTcsActionTriggerDef`** |
| `UTcsAttributeDef` / `UTcsAttrModDef` | `Def` | 不变 |

**判据**：后缀 `Def` 已是基类与多数派的写法；`DefAsset` 既与基类 `UTcsStateDef` 不一致，也不表达任何额外含义（`Def` 本身就是资产）。

> **非资产的结构体与资产类只差 `U` / `F` 前缀不算撞名**：`FTcsActionTriggerDef`（结构体）与 `UTcsActionTriggerDef`（资产）并存是 UE 常规。

## 3. 域改名：`Effect` → `Action` ✅

**模块**：`TcsEffect` → `TcsAction`；宏 `TCSEFFECT_API` → `TCSACTION_API`；目录 `Source/TcsEffect` → `Source/TcsAction`。

| V1 名 | V2 名 | 说明 |
|---|---|---|
| `UTcsEffectSubsystem` | `UTcsActionSubsystem` | 世界子系统 |
| `FTcsEffectChain` | `FTcsActionChain` | 链本体 |
| `UTcsEffectChainDef` | `UTcsActionChainDef` | 链定义资产 |
| `FTcsEffectStep` | `FTcsActionStep` | 步骤基类 |
| `FTcsEffectStepExecutorRegistry` | `FTcsActionStepExecutorRegistry` | 步骤执行器注册表 |
| `FTcsEffectStepExecutorRegistrar` | `FTcsActionStepExecutorRegistrar` | 静态自注册器 |
| `FTcsEffectContext` | `FTcsActionContext` | 步骤间传递的上下文（非反射） |
| `FTcsEffectTriggerDef` | `FTcsActionTriggerDef` | 触发条件定义 |
| `FTcsEffectTriggerInstance` | `FTcsActionTriggerInstance` | 触发条件实例 |
| `FTcsEffectTriggerHandle` | `FTcsActionTriggerHandle` | 触发条件句柄 |
| `UTcsEffectTriggerDefAsset` | `UTcsActionTriggerDef` | 触发条件定义资产（后缀按 §2 统一） |
| `UTcsStepExecutor` | `UTcsActionStepExecutor` | UObject 步骤执行器插槽（V1 本身无 `Effect` 前缀，本次补上） |

**函数**：`ExecuteChain` / `RunFrom` / `ReleaseRun` / `ResumeRun` / `IsRunActive` / `RunChildChainStep` 等含 `Run` 的入口按 §4 一并改名，逐条在实现阶段定。
