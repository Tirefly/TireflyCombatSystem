# 核心基线 · 事件总线（EventBus）

> **定位**：V2 五项核心基线之一（Entity / Instance / Clock / EventBus / NumericAggregator）。
> **回答什么问题**：**发生了什么**。

**审核状态图例**：✅ 已裁决并批准 ｜ ⚠️ 待审 ｜ ❓ 待调研

> **本文件的写法**：只写最终设计与已裁决的架构，不复述历史实现。

---

## 0. 本域只回答一件事

**「发生了什么」以 Tag 为路由，通知给关心它的人。**

### 0.1 投放语义

> **总线 MUST 把事件与其载荷准确、及时地送达本次派发的全部匹配订阅者；订阅是否"在册"以轮到它时为准。**
> **总线 MUST NOT 保存、缓存或重放任何载荷。**

| 要求 | 含义 |
|---|---|
| **准确** | 送到的是同一个 `Type` 与同一份 `Data`；不拷贝、不转换、不推测 |
| **及时** | 在 `Publish` 调用返回前送达，**MUST NOT 攒批到帧末**（§1.2 已裁不建帧末通道） |
| **全部匹配者** | 每个符合本次派发资格的匹配订阅，在**轮到它时仍有效**的前提下各调用一次；已进入执行的回调必须执行完毕，之后注销的订阅不再被访问；MUST NOT 因同一订阅者被调用多次而合并 |
| **不缓存** | 载荷只在调用期间有效（§1.1.8）；晚订阅者 MUST NOT 收到旧载荷 |

它**不**负责：

| 不做 | 归谁 |
|---|---|
| 事件的语义（什么算伤害、什么算死亡） | 各领域 |
| 业务层的顺序保证 | 各领域 |
| 「谁该关心这个事件」的判定 | 订阅方自己 |
| **状态快照 / 粘性事件**（记住上一次载荷给晚订阅者） | **不做**——那是状态查询，不是事件分发 |

## 1.1 事件总线 ✅

### 1.1.1 形态总览

| 项 | 设计 |
|---|---|
| 路由键 | `FGameplayTag` |
| 载荷寻址 | `const UScriptStruct*`（类型） + `const void*`（数据） |
| 底层回调 | **类型擦除的零堆分配函数对象** |
| 注册路径 | **两条**：C++ 直收回调 / 反射收 UObject + UFunction |
| 派发遍历 | **稳定下标 + `bAlive` 跳过 + 深度归零落地** |
| 频道匹配 | 精确匹配为默认，**层级匹配显式开启** |
| 每次派发分配 | **不含注册时为 0**（§1.1.6） |

### 1.1.2 载荷：类型擦除 + 注册期绑定

**派发侧只有一种形状**，所有载荷类型共用同一条派发循环：

```cpp
// 第一参数是捕获物缓冲地址：thunk 靠它还原自己的强类型上下文
using FTcsEventDispatchFn = void(*)(void* Capture, FGameplayTag Channel,
                                   const UScriptStruct* Type, const void* Data);
```

**语言与类型的差异在注册期被吸收**，不在派发热路径上分叉。两条路径的 thunk 捕获物都装进 `FTcsEventSink::Inline`，不额外增加槽位字段：

| 路径 | thunk 的捕获物 | 字节 | 落点 |
|---|---|---|---|
| C++ | 内联 `std::decay_t<TCallable>` | ≤ `sizeof(Inline)` | `Inline` |
| 反射 | `{ UObject*, UFunction* }` | 两个指针 | `Inline` |

**`FunctionName` MUST 在注册期解析成 `UFunction*` 并进入 thunk 捕获物，MUST NOT 成为槽位字段**：

> **Why Not 把 `FunctionName` 存进槽位**：注册期就能解析完，存字符串等于把一次查表推迟到每次派发。

**`PayloadType` 两条路径都填，MUST NOT 留空**：

| 路径 | 来源 |
|---|---|
| C++ | 模板参数 `FPayloadType::StaticStruct()` |
| 反射 | 调用方传入的 `UScriptStruct*` |

> **Why Not 让路径 A 留空（不校验）**：类型擦除后 `Data` 只有 `const void*`，不留类型标签就只能做 unchecked cast——同一频道发两种载荷即 UB。

### 1.1.3 底层回调：手写零堆分配函数对象 ✅

```cpp
struct FTcsEventSink
{
    // thunk：第一参数是捕获物缓冲地址（即 Inline）
    FTcsEventDispatchFn Func = nullptr;

    // 对捕获物执行析构
    void (*Destroy)(void*) = nullptr;

    // 捕获物的实际存储
    alignas(16) uint8 Inline[24] = {};

    // 直函数指针调用，不经过虚函数层
    void Invoke(FGameplayTag Channel, const UScriptStruct* Type, const void* Data)
    {
        Func(Inline, Channel, Type, Data);
    }

    // 销毁捕获物并清空函数指针
    void Reset()
    {
        if (Destroy) { Destroy(Inline); }
        Func = nullptr;
        Destroy = nullptr;
    }
};
```

**三个字段各司其职**：

| 字段 | 角色 |
|---|---|
| `Inline[24]` | 捕获物的**实际存储** |
| `Func` | 类型擦除的 thunk，**第一参数就是 `Inline`**；强类型还原由 thunk 自己 `static_cast` 完成 |
| `Destroy` | 对 `Inline` 执行捕获物析构 |

> **Why Not 缓存一个「已转型的捕获物指针」字段**：那是自引用，结构体一旦被容器按字节搬移就悬空。

**捕获物只构造一次，此后只允许字节搬移**：

| # | 不变量 |
|---|---|
| I1 | `FTcsEventSink` / `FTcsEventSlot` MUST 保持**平凡析构**；捕获物的析构**只**由 `Sink.Reset()` 显式触发，容器析构 MUST NOT 代劳 |
| I2 | 捕获物只构造一次，此后只允许位移动（源被遗弃、不再析构）；MUST NOT 复制后各自析构 |
| I3 | 捕获类型 MUST NOT 持有指向自身的指针或引用（lambda 天然满足） |

```cpp
// C++ 路径的 thunk：注册期把强类型回调塞进 Inline，派发期原样还原
template <typename FPayloadType, typename TCallable>
FTcsEventSink MakeSink(TCallable&& Callback)
{
    // 存储类型必须退化：去掉引用与 cv、数组退化为指针、函数退化为函数指针
    using FStoredCallable = std::decay_t<TCallable>;

    // 两条上限都取自本结构自己的缓冲——MUST NOT 写外部字面量
    static_assert(sizeof(FStoredCallable)  <= sizeof(FTcsEventSink::Inline),
                  "捕获物装不进内联缓冲，会退化成堆分配");
    static_assert(alignof(FStoredCallable) <= alignof(FTcsEventSink::Inline),
                  "捕获物的对齐要求超过内联缓冲");

    // 就地构造一次；此后只允许字节搬移（I2）
    ...
}
```

**三条设计约束**：

| # | 约束 | 理由 |
|---|---|---|
| ① | **捕获物尺寸与对齐的编译期断言**（上限取自 `FTcsEventSink::Inline`） | 保证**永远不堆分配**，不会因为捕获变大而静默退化 |
| ② | **直函数指针调用**，不引入虚函数层 | 派发少一次间接 |
| ③ | **不嵌套**（不把回调包进另一个回调） | 嵌套会让捕获物翻倍、堆分配不可避免 |

**关于 ① 的现实代价**：捕获装不下或对齐不足会**编译失败**。这是刻意的——替代路径是「捕获小数据（指针 / 索引），把大对象放外部」。

> **断言上限 MUST 取自 `sizeof` / `alignof(FTcsEventSink::Inline)`，MUST NOT 写字面量。**
> **Why Not 写 `24` / `16`**：该缓冲是本框架自己的成员，尺寸就是真值；外部 `TFunction` 的内联尺寸是 `#ifndef` 可覆盖、且可为 0（全部堆分配）的，拿它当判据必然错。

### 1.1.4 订阅：句柄式生命周期 ✅

```cpp
USTRUCT(BlueprintType)
struct FTcsEventSubscription
{
    // 身份（每总线自发号，永不复用；0 = 无效）
    UPROPERTY(BlueprintReadOnly, Category = "Tcs|Event")
    int64 SubscriptionId = 0;

    bool IsValid() const { return SubscriptionId != 0; }

    // 等价于总线上的 Unsubscribe(本句柄)；总线引用由持有者提供
    void Unsubscribe(UTcsEventBusSubsystem& Bus) const;
};
```

**句柄只带身份，不带定位段**——位置由总线的身份索引维护：

```cpp
// 总线内部：身份 → 位置
struct FTcsEventLocation
{
    FGameplayTag Channel;      // 该订阅所在的频道
    int32        Index   = -1; // bPending == false ⇒ Slots 下标；true ⇒ PendingAdds 下标
    bool         bPending = false;
};

TMap<int64, FTcsEventLocation> IdentityToLocation;
```

**注销时立即删除索引条目**；查不到即视为失效。

| 要求 | 理由 |
|---|---|
| 句柄**可被蓝图 / 脚本持有** | 脚本侧必须能主动注销，否则只能等 GC 兜底 |
| 句柄**必须是身份**（每总线自发号、永不复用） | 槽位下标会被回收复用，**MUST NOT** 用下标作身份 |
| 句柄**自带注销能力** | 调用方不必持有总线引用 |
| 句柄 **MUST NOT 缓存槽位下标** | 注册当刻未必有槽位（§1.1.6），且缓存值会在下标复用后失效 |

> **订阅身份与实例句柄同构**：都是「自发号、永不复用、`0` 无效」的身份。

**注销成本**：一次哈希查找拿到位置，再用下标直接命中——**平均 O(1)，不扫描**。

> **Why Not 只存身份、注销时扫描**：千级实体同时死亡时，扫描是 O(注销数 × 槽位数)，全挤在同一帧。

**批量注销**：所有者必须在销毁 / 撤销路径上把自己的订阅全部注销（§1.1.9）。

```cpp
void UnsubscribeAll(UTcsEventBusSubsystem& Bus,
                    TConstArrayView<FTcsEventSubscription> Handles);
```

> **Why Not 按所有者身份批量注销**：实体句柄、实例句柄、`UObject*` 三类身份互不统一，统一键必然退化为类型擦除。

### 1.1.5 两条注册路径 ✅

```cpp
// 路径 A：C++ 直收回调（满足铁律 3：不需要派生任何类型）
template <typename FPayloadType, typename TCallable>
FTcsEventSubscription Subscribe(
    FGameplayTag        Channel,
    TCallable&&         Callback,      // void(FGameplayTag, const FPayloadType&)
    ETcsEventMatch      Match = ETcsEventMatch::ExactMatch);

// 路径 B：反射（蓝图 / 脚本）
FTcsEventSubscription SubscribeReflected(
    FGameplayTag        Channel,
    UScriptStruct*      PayloadType,   // 期望的载荷类型
    UObject*            Sink,
    FName               FunctionName,
    ETcsEventMatch      Match = ETcsEventMatch::ExactMatch);
```

**路径 B 的过滤位置**：频道过滤与类型过滤**都在派发侧（C++）完成**，脚本虚拟机**不会收到不关心的频道**。

**两条路径共用同一套存储与同一个派发循环**，差别只在注册期的 thunk 如何构造。

**`UObject* Sink` 回答的是「脚本 VM 调用谁」，不是「实体是谁」**：反射路径必须有一个 `UObject` 作为调用目标，这与「框架不知道实体载体的形态」无关（`战斗实体.md` §5.2 的禁令只针对**实体与实例相关契约**），因此不构成例外。

**回调签名只有一种**：`(发布频道, 载荷)`。**订阅句柄不进入回调**——需要自注销时，由持有者对自己那句柄调 `Unsubscribe`（§1.1.6 已保证回调内注销安全）。

### 1.1.6 派发：稳定下标 + 身份索引 + 深度归零 ✅

**问题**：派发循环遍历订阅数组时，回调里增删订阅会导致迭代失效；派发中新增的订阅还会让数组扩容，搬走正在执行的捕获物。

**解法**：**槽位永不压缩**——注销只把该槽位置为不存活，下标交给 `FreeIndices` 复用。

#### 存储形态

```cpp
struct FTcsEventSlot
{
    FTcsEventSink        Sink;
    FGameplayTag         Channel;
    ETcsEventMatch       Match;
    const UScriptStruct* PayloadType;     // 两条路径都填；MUST NOT 为空
    int64                SubscriptionId;
    bool                 bAlive = false;
};

struct FTcsEventChannelState
{
    TArray<FTcsEventSlot> Slots;           // 稳定下标：MUST NOT 压缩
    TArray<int32>         FreeIndices;     // 空闲下标栈
    TArray<FTcsEventSlot> PendingAdds;     // 派发中新增：捕获物在此落脚
    TArray<int32>         PendingRelease;  // 派发中注销：深度归零时销毁并归还下标
    int32                 DispatchDepth = 0;
};

// 频道态独立分配：Channels 扩容只搬指针，频道态地址不变
TMap<FGameplayTag, TUniquePtr<FTcsEventChannelState>> Channels;
```

> **Why Not 直接存 `FTcsEventChannelState`**：`Publish` 持有频道态的引用跨越回调循环，回调里的注册会插入新频道、让容器扩容——引用随之悬空。

**`Slots` MUST 保持稳定下标，MUST NOT 压缩**——这是整个设计的支点。

| 选择 | 注销成本 | 稳定下标 | 结论 |
|---|---|---|---|
| `RemoveAtSwap` 压缩 | O(1) 但**下标全乱** | ❌ | 不可用 |
| 稳定下标 + `bAlive` 惰性回收 | **O(1)** | ✅ | 采用 |
| 只存身份、注销时扫描 | O(s) | ✅ | 不可用（千级并发注销） |

**频道条目只由注册创建，只增不减**：`Publish` 用 `Find`，从不创建频道；本频道与全部父频道都未注册时才直接返回。

> **Why Not 让 `Publish` 顺带创建频道**：无人订阅的频道不需要任何状态；顺带创建还等于「发布打错 tag 就悄悄长出频道」。

#### 四个入口

```cpp
// 本次派发的作用域：发布频道 + 全部父频道，只收已注册的频道
void CollectScope(FGameplayTag Channel,
                  TArray<FTcsEventChannelState*, TInlineAllocator<8>>& Out)
{
    if (FTcsEventChannelState* S = FindChannel(Channel)) { Out.Add(S); }
    for (FGameplayTag Parent = Channel.RequestDirectParent();
         Parent.IsValid();
         Parent = Parent.RequestDirectParent())
    {
        if (FTcsEventChannelState* S = FindChannel(Parent)) { Out.Add(S); }
    }
}

void Publish(FGameplayTag Channel, const UScriptStruct* Type, const void* Data)
{
    // 作用域在开始时定死：派发过程中才注册的频道不属于本次派发
    TArray<FTcsEventChannelState*, TInlineAllocator<8>> Scope;
    CollectScope(Channel, Scope);
    if (Scope.Num() == 0) { return; }                    // 本频道与父频道都无订阅

    // ① 升深：内层派发必须看到父频道也已在派发中
    for (FTcsEventChannelState* S : Scope) { S->DispatchDepth += 1; }

    // ② 遍历
    for (FTcsEventChannelState* S : Scope) { DispatchInto(*S, Channel, Type, Data); }

    // ③ 降深；每个频道在自己的深度归零时落地
    for (FTcsEventChannelState* S : Scope)
    {
        if (--S->DispatchDepth == 0) { Flush(*S); }
    }
}

void DispatchInto(FTcsEventChannelState& State, FGameplayTag Channel,
                  const UScriptStruct* Type, const void* Data)
{
    const int32 Count = State.Slots.Num();               // 锁定长度：遍历期间不增长
    for (int32 Index = 0; Index < Count; ++Index)
    {
        FTcsEventSlot& Slot = State.Slots[Index];
        if (!Slot.bAlive) { continue; }
        if (!Matches(Slot, Channel, Type)) { continue; }
        Slot.Sink.Invoke(Channel, Type, Data);
    }
}
```

**频道过滤全部由 `Matches` 承担**：原频道上精确订阅与层级订阅都命中；父频道上只有层级订阅命中——精确匹配拿 `Slot.Channel` 与**发布频道**比较，父频道的订阅天然不等。回调收到的永远是**原始发布频道**。

**作用域 MUST 在派发开始时定死**，两个理由：① 派发过程中才注册的频道没被升深，若在降深阶段被遍历到会被减成负数；② 那一刻注册的订阅若已就地落地，会被本次派发命中，违反「本拍不生效」。作用域数组持的是频道态指针——频道态独立分配（`TUniquePtr`），指针在 `Channels` 扩容后依然有效。

```cpp
// 注销：O(1)，一次哈希 + 一次下标
void Unsubscribe(FTcsEventSubscription Handle)
{
    FTcsEventLocation* Loc = IdentityToLocation.Find(Handle.SubscriptionId);
    if (!Loc) { return; }                                // 无效句柄 / 重复注销：幂等

    FTcsEventChannelState* State = FindChannel(Loc->Channel);
    const int32 Index    = Loc->Index;
    const bool  bPending = Loc->bPending;
    IdentityToLocation.Remove(Handle.SubscriptionId);

    if (bPending)
    {
        // 待添加项从未被派发，捕获物可当场销毁
        State->PendingAdds[Index].Sink.Reset();
        State->PendingAdds.RemoveAtSwap(Index, EAllowShrinking::No);
        ReindexPending(*State, Index);
        return;
    }

    FTcsEventSlot& Slot = State->Slots[Index];
    Slot.bAlive = false;

    if (State->DispatchDepth > 0)
    {
        // 可能正在执行：延后到深度归零再销毁与回收
        State->PendingRelease.Add(Index);
    }
    else
    {
        Slot.Sink.Reset();
        State->FreeIndices.Add(Index);
    }
}

// 换位后修正被移动项的索引
void ReindexPending(FTcsEventChannelState& State, int32 Index)
{
    if (!State.PendingAdds.IsValidIndex(Index)) { return; }
    if (FTcsEventLocation* Moved = IdentityToLocation.Find(State.PendingAdds[Index].SubscriptionId))
    {
        Moved->Index = Index;
    }
}
```

```cpp
// 注册：栈外就地落地；派发中入待添加队列，完全不碰 Slots
FTcsEventSubscription Subscribe(FGameplayTag Channel, ETcsEventMatch Match,
                                const UScriptStruct* PayloadType, FTcsEventSink Sink)
{
    FTcsEventChannelState& State = GetOrCreateChannel(Channel);   // 注册路径才创建频道
    const int64 Id = NextSubscriptionId.Allocate();               // 耗尽返回 0
    if (Id == 0) { return FTcsEventSubscription{}; }

    if (State.DispatchDepth == 0)
    {
        const int32 Index = AllocateSlot(State);
        State.Slots[Index] = FTcsEventSlot{ Sink, Channel, Match, PayloadType, Id, true };
        IdentityToLocation.Add(Id, { Channel, Index, false });
    }
    else
    {
        const int32 Index = State.PendingAdds.Add(
            FTcsEventSlot{ Sink, Channel, Match, PayloadType, Id, false });
        IdentityToLocation.Add(Id, { Channel, Index, true });
    }

    return FTcsEventSubscription{ Id };
}

int32 AllocateSlot(FTcsEventChannelState& State)
{
    if (State.FreeIndices.Num() > 0) { return State.FreeIndices.Pop(EAllowShrinking::No); }
    return State.Slots.AddDefaulted();
}
```

```cpp
// Flush：只在深度归零时调用。先回收再落地——待添加项优先复用刚归还的下标
void Flush(FTcsEventChannelState& State)
{
    for (int32 Index : State.PendingRelease)
    {
        State.Slots[Index].Sink.Reset();
        State.FreeIndices.Add(Index);
    }
    State.PendingRelease.Reset();

    for (int32 PendingIndex = 0; PendingIndex < State.PendingAdds.Num(); ++PendingIndex)
    {
        FTcsEventSlot& Pending = State.PendingAdds[PendingIndex];
        const int32 Index = AllocateSlot(State);
        State.Slots[Index] = Pending;                    // 字节搬移，源不再析构（I2）
        State.Slots[Index].bAlive = true;

        if (FTcsEventLocation* Loc = IdentityToLocation.Find(Pending.SubscriptionId))
        {
            Loc->Index    = Index;
            Loc->bPending = false;
        }
    }
    State.PendingAdds.Reset();                           // 平凡析构，不销毁捕获物（I1）
}
```

订阅号由 `TTcsIdCounter<int64>` 发放（[运行时实例](运行时实例.md) §1.2.4），从 1 起、永不复用、耗尽后返回空句柄。

**四条保证**：

| # | 保证 | 靠什么 |
|---|---|---|
| ① | 遍历期间槽位数组**不增长**，元素地址稳定 | 派发中新增只进 `PendingAdds`；锁定 `Count` |
| ② | 派发中注销的订阅，本次派发立即不再收到 | `bAlive` 在遍历时被检查 |
| ③ | 派发中新增的订阅**本拍不生效**（含嵌套同频道的内层派发） | 新增只在 `PendingAdds`，不进 `Slots`；作用域在派发开始时定死 |
| ④ | 新增统一在**深度归零**时落地 | 每个频道在自己的深度归零时 `Flush` |

**为什么 ③ 必须连内层也算**：若新增直接 append，内层派发重新锁长度时就会看到它们——「本拍不生效」的语义被嵌套破坏。

**深度计在「本次访问的每一个频道」上**：派发会遍历父频道，若只给发布频道计深，父频道上的订阅在回调里自注销时会被判定为「栈外」，当场销毁正在执行的捕获物。

**栈外注销直接生效**：只有 `DispatchDepth > 0` 时才进 `PendingRelease`。

**Flush 的时机只有一个：深度归零。** 派发入口**不做** flush——入口处的待添加列表天然为空（上一轮归零时已清），在那里加 flush 只会掩盖「某次没走到归零」的缺陷。

#### 下标不变量 ✅

| # | 不变量 |
|---|---|
| S1 | `FreeIndices` 中每个下标 MUST 满足 `Slots[i].bAlive == false` |
| S2 | 每个 `bAlive == false` 的下标 MUST 在 `FreeIndices` 中**恰好出现一次**（派发中待释放的阶段除外，见 S4） |
| S3 | 分配下标 MUST 先 `FreeIndices.Pop()`，栈空才 `AddDefaulted()`；MUST NOT 直接用 `Slots.Num()` 追加 |
| S4 | 派发中注销的槽位先进入 `PendingRelease`，深度归零时才销毁捕获物并归还下标 |
| S5 | `bAlive == true` ⇔ 身份索引中存在且仅存在一条指向该槽位的条目 |

#### 注销为什么是 O(1) ✅

**判据：`Unsubscribe` 的成本 MUST 与「该频道订阅数」无关。**

| 阶段 | 成本 | 说明 |
|---|---|---|
| 定位 | **平均 O(1)** | `IdentityToLocation` 哈希查找 |
| 摘除 | **O(1)** | 用索引直接命中 `Slots` 下标，不扫描 |
| 待添加项 | **O(1)** | `RemoveAtSwap` + 修正被换位项的索引 |

**「千级实体同帧死亡」的成本 = O(死亡数)**，不是 O(死亡数 × 订阅数)。

**本设计的唯一残余成本**：`Publish` 仍要扫过 `[0, Slots.Num())`，其中可能夹杂已不存活的槽位。

| 项 | 结论 |
|---|---|
| 上界 | `Slots.Num()` ≈ **该频道订阅数峰值**（空闲下标被复用，不会无限增长） |
| 每次派发成本 | O(峰值订阅数)，不是 O(历史累计注册数) |
| 是否可消除 | **不可**——稳定下标的必然代价 |
| 何时恶化 | 若某频道曾有过一次极大订阅峰，`Slots.Num()` 永久停在峰值 |

> **Why Not 定期压缩 `Slots`**：压缩会让所有存量订阅失效，只能逼所有调用方重新注册——代价远大于收益。

⇒ **接受这个上界**：它是「O(1) 注销」的对价，且以**订阅峰值**为界，与事件频率无关。

**零分配保证**：

> **不含注册的派发零分配**；含注册的派发，分配量与**本次注册次数**成正比，且只发生在「`PendingAdds` 追加」与「`Flush` 扩容 `Slots`」两处。
>
> 派发作用域数组用 `TInlineAllocator<8>`，tag 深度不超过 8 层时不分配。

> **Why Not 承诺「一次 `Publish` 调用内零分配」**：注册引起的扩容被推迟到 `Flush`，但它仍发生在同一次 `Publish` 里。

#### `Matches` 的定义 ✅

```cpp
bool Matches(const FTcsEventSlot& Slot, FGameplayTag Channel, const UScriptStruct* Type) const
{
    // ① 类型：MUST 精确相等。两条路径的 PayloadType 都非空（见 §1.1.2）
    if (Slot.PayloadType != Type) { return false; }

    // ② 频道：默认精确匹配；PartialMatch 才沿父链比较
    if (Slot.Match == ETcsEventMatch::ExactMatch) { return Slot.Channel == Channel; }
    return Channel.MatchesTag(Slot.Channel);
}
```

| 判据 | 约定 |
|---|---|
| 类型比较 | **指针相等**即可——`UScriptStruct*` 是注册期解析的唯一实例，不需要名字比较 |
| 类型 MUST NOT 放宽 | 子类 / 结构兼容一律**不做**：那会让订阅者收到它没声明能处理的结构 |
| `PayloadType` 为空 | **非法状态**，注册期就应被 `check` 挡住，不在此处兜底 |

### 1.1.7 频道层级匹配：显式开启 ✅

```cpp
enum class ETcsEventMatch : uint8
{
    ExactMatch,     // 默认：A.B 只收 A.B
    PartialMatch,   // 显式：A.B 收 A.B 与 A.B.*
};
```

**默认必须是 `ExactMatch`。**

| 理由 | 说明 |
|---|---|
| 精确匹配是「我就要这一条」的直白语义 | 层级匹配是「我要这一类」，是更强的假设 |
| 层级匹配有额外成本 | 需要沿 tag 父链逐层查找或预摊平 |
| 默认 MUST 是最省的形态 | 需要层级的调用方显式开启，成本可归因 |

### 1.1.8 载荷生命周期：受控借用 ✅

**契约**：载荷指针**只在派发调用期间有效**。

| 允许 | 禁止 |
|---|---|
| 在回调内**读**载荷 | 把载荷指针**存起来**延后使用 |
| 在回调内**拷贝**载荷到自己的容器 | 在回调内**修改**载荷 |
| 在回调内**发布新事件** | 在回调内**长时间阻塞** |

> **Why Not 值语义（每次拷贝）**：拷贝对高频事件是直接成本，而绝大多数订阅者只读。

**代价必须明确写进契约**：反射路径的消费者（蓝图 / 脚本）**MUST 当场拷贝**，否则悬空。

### 1.1.9 订阅生命周期闭合 ✅

**纪律**：施加时注册、撤销时注销，由**同一个所有者**配对完成。

**总线无法强制这条，但它是使用契约的一部分**：

| 错误形态 | 后果 |
|---|---|
| 只注册不注销 | 订阅永远增长，派发越来越慢 |
| 注册在 A 对象、注销在 B 对象 | 生命周期不一致，容易漏删 |
| 在回调里注册但不留句柄 | 无法注销 |
| **反射路径的对象先被销毁，订阅没注销** | **槽位里的 `UObject*` 已失效，派发会打到失效对象** |

**第四条 MUST 由注销路径解决**：

> **宿主 MUST 在对象销毁时注销它的全部订阅**（`UnsubscribeAll`，或逐个 `Unsubscribe`）。总线**不提供**对象存活查询，MUST NOT 在派发热路径上判断「订阅者还在不在」。

| Why Not 总线自己判失效 | 说明 |
|---|---|
| 需要每派发一次检查 | 那是把一次不可控的 GC 语义塞进每个事件的成本里 |
| 只能覆盖一半 | 弱引用只对反射路径的 `Sink` 有意义；C++ 路径的捕获物没有对象可查，两套语义会分裂 |
| 有唯一正确时机 | 对象销毁是**确定的**时刻，宿主在那里注销即可；派发期判断是**猜测** |

### 1.1.10 业务需求

| 游戏 | 特殊要求 |
|---|---|
| LAC | 跨实体联动 MUST 有序且可回放 |
| 第三人称动作 | 帧内 MUST 有序 |
| 幸存者 ARPG | 千级实体 × 高频事件 |

### 1.1.11 路由结构不预设

> **压测数据到手前，MUST NOT 为路由加按实体过滤的快路径，也 MUST NOT 改路线形态。**

缺什么：**「订阅者总数」与「实际匹配该频道的订阅者数」的比值**——见族外 `Documents/tcs-remake-v2-drafts/未决-核心基线.md` §4。

## 1.2 帧末派发通道：**不建** ✅

### 1.2.1 它要解决的问题

**防重入与无限连锁**：状态类事件（伤害 / 死亡）若在派发过程中再次触发同类事件，会形成重入。

### 1.2.2 不建的判据

> **没有事件分级清单，就不该有一个帧末通道。**

这个通道要成立，必须先有一张**分级表**：哪些事件立即派发、哪些帧末派发。**该表不存在**，于是通道的存在只是每帧一次空调用。

### 1.2.3 与动作游戏的冲突

动作游戏里「伤害判定 → 死亡 → 表现」MUST 在**同一帧**完成。延迟一拍破坏手感。

⇒ **帧末派发不是「更好的」派发，只是一个特定语义下的选择**，不能作为默认。

### 1.2.4 重开此通道的触发条件

> **先写清分级表，再加通道**；一次只加一条，且该条 MUST 当场有发布者。分级表不存在时 MUST NOT 建通道。
