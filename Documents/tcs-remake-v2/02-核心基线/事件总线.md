# 核心基线 · 事件总线（EventBus）

> **定位**：V2 核心基线之一（Entity / RuntimeInstance / Clock / EventBus / NumericAggregator / GameplayTag）。
> **回答什么问题**：**发生了什么**。

**审核状态图例**：✅ 已裁决并批准 ｜ ⚠️ 未定 ｜ ❓ 待调研

> **本文件的写法**：只写最终设计与已裁决的架构，不复述历史实现。

---

## 0. 本域只回答一件事

**「发生了什么」以 Tag 为路由，通知给关心它的人。**

### 0.1 投放语义

> **总线 MUST 把事件与其载荷准确、及时地送达本次派发的全部匹配订阅者；新增可见性按发布 Tag 判定（§1.1.6），订阅是否在册以轮到它时为准。**
> **总线 MUST NOT 保存、缓存或重放任何载荷。**

| 要求 | 含义 |
|---|---|
| **准确** | 送到的是同一个 `Type` 与同一份 `Data`；不拷贝、不转换、不推测 |
| **及时** | 在 `Publish` 调用返回前送达，**MUST NOT 攒批到帧末**（§1.2 已裁不建帧末通道） |
| **全部匹配者** | 每个符合本次派发资格的匹配订阅，在**轮到它时仍有效**的前提下各调用一次；已进入执行的回调必须执行完毕，之后注销的订阅不再被访问；MUST NOT 因同一订阅者被调用多次而合并 |
| **不缓存** | 载荷只在调用期间有效（§1.1.8）；晚订阅者 MUST NOT 收到旧载荷 |

它**不**负责：

| 不做 | 归谁 |
|---|---|
| 事件的语义（什么算伤害、什么算死亡） | 各领域 |
| 业务层的顺序保证 | 各领域 |
| 「谁该关心这个事件」的判定 | 订阅方自己 |
| **状态快照 / 粘性事件**（记住上一次载荷给晚订阅者） | **不做**——那是状态查询，不是事件分发 |

## 1.1 事件总线 ✅

### 1.1.1 形态总览

| 项 | 设计 |
|---|---|
| 路由键 | `FGameplayTag` |
| 载荷寻址 | `const UScriptStruct*`（类型） + `const void*`（数据） |
| 底层回调 | **每条订阅一个独立堆回调对象**，`FTcsEventSink` 用 `TUniquePtr` 独占持有（§1.1.3） |
| 注册路径 | **两条**：C++ 直收回调 / 反射收 UObject + UFunction |
| 派发遍历 | **稳定下标 + 发布 Tag 的订阅号上限 + `bAlive` 即时过滤**（§1.1.6） |
| 频道匹配 | 精确匹配为默认，**层级匹配显式开启** |
| 派发分配边界 | **调用既有回调不复制回调对象、不为其重新分配存储**；不承诺整次 `Publish` 零分配（§1.1.6） |

### 1.1.2 载荷：类型擦除 + 注册期绑定

**派发侧只有一种形状**：在确认可见、在册且匹配后，从 `FTcsEventSink` 借用已绑定的回调对象并调用 `Invoke`，两条注册路径与所有载荷类型共用同一条派发循环。语言与类型差异在注册期由不同的回调实现承接，不另加槽位字段：

| 路径 | 回调对象持有的上下文 |
|---|---|
| C++ | 从调用方传入的回调构造的 `std::decay_t<TCallable>`；调用时按注册期绑定的载荷类型读取 `Data` |
| 反射 | 注册期确定的 `{ UObject*, UFunction* }`；调用时用它们进入反射调用路径 |

**`FunctionName` MUST 在注册期解析成 `UFunction*` 并存入反射回调对象，MUST NOT 成为槽位字段**：

> **Why Not 把 `FunctionName` 存进槽位**：注册期就能解析完，存字符串等于把一次查表推迟到每次派发。

**`PayloadType` 两条路径都填，MUST NOT 留空**：

| 路径 | 来源 |
|---|---|
| C++ | 模板参数 `FPayloadType::StaticStruct()` |
| 反射 | 调用方传入的 `UScriptStruct*` |

> **Why Not 让路径 A 留空（不校验）**：类型擦除后 `Data` 只有 `const void*`，不留类型标签就只能做 unchecked cast——同一频道发两种载荷即 UB。

### 1.1.3 底层回调：类型擦除与独占所有权 ✅

**每条订阅在注册时独立构造一个堆上的回调对象，由总线独占持有。** `FTcsEventSink` 内部持有 `TUniquePtr<FTcsEventCallback>`，可为空、不可复制。C++ 与反射回调各自实现带虚析构的私有基类，直接存储 §1.1.2 所列上下文，不再套一层函数包装，不做小对象内联，也不使用共享所有权。

```cpp
// 总线私有的类型擦除接口；只有通过匹配的派发才能调用 Invoke。
struct FTcsEventCallback
{
	virtual ~FTcsEventCallback() = default;
	virtual void Invoke(
		FGameplayTag Channel,
		const UScriptStruct* Type,
		const void* Data) = 0;
};
```

`FTcsEventSink::BorrowCallback` 只借出指向堆回调对象的指针，不转移所有权；派发不得把槽位或持有者的引用带进用户回调。`IsEmpty` 只检查是否持有对象；`Reset` 释放对象并清空持有者，只能由 §1.1.6 的守卫销毁路径调用。槽位的移入、换位和扩容只搬持有者，不搬堆上的回调对象。地址稳定只保证回调对象本身，不延长它捕获的裸指针、引用或反射目标的寿命。

| # | 不变量 |
|---|---|
| I1 | 回调对象由总线独占。总线 MUST 经 §1.1.6 的销毁守卫将其恰好销毁一次；容器清理不得代替受守卫的销毁。 |
| I2 | **只允许移入空持有者**（新建或已清空）。迁移只转移指针，不复制或移动回调对象；移动后仍存在的源持有者必须为空。不得用移动赋值覆盖仍持有回调的目标：`TUniquePtr` 会在覆盖时销毁目标原对象，绕过守卫。 |
| I3 | 已存储的回调对象在销毁前地址保持稳定，已进入的回调必须执行完毕才可销毁。稳定的槽位下标本身不保证回调对象地址稳定。 |

### 1.1.4 订阅：句柄式生命周期 ✅

```cpp
USTRUCT(BlueprintType)
struct FTcsEventSubscription
{
	// 进程内唯一的订阅号；0 = 空句柄
	UPROPERTY(BlueprintReadOnly, Category = "Tcs|Event")
	int64 SubscriptionId = 0;

	// 只检查是不是空句柄，不查询订阅是否仍在册
	bool IsValid() const { return SubscriptionId != 0; }

	// 等价于 Bus.Unsubscribe(*this)；调用方必须显式提供总线
	void Unsubscribe(UTcsEventBusSubsystem& Bus) const;
};
```

**句柄只带 `SubscriptionId`，不带总线身份或槽位下标。** 所有总线实例共用一个进程级订阅号计数器，号码单调递增、永不复用；总线重建不重置计数器。位置只由该订阅所属总线的本地身份索引维护：

```cpp
// 当前总线的本地索引：订阅号 → 位置
struct FTcsEventLocation
{
	FGameplayTag Channel;      // 该订阅所在的频道
	int32        Index = -1;    // Slots 下标
};

TMap<int64, FTcsEventLocation> IdentityToLocation;
```

**注销只查调用方指定的总线。** 命中则立即删除索引条目；未命中（空句柄、错总线、重复注销或旧总线的句柄）不改状态，不查其他总线，也不自动转发。例如，A 发出 `#1`、B 发出 `#2`，把 `#1` 交给 B 不会影响 B 的 `#2`，也不会注销 A 的 `#1`。

| 要求 | 理由 |
|---|---|
| 句柄**可被蓝图 / 脚本持有** | 脚本侧必须能主动注销，否则只能等 GC 兜底 |
| 句柄**必须是身份**（进程内统一发号、永不复用） | 错总线不会误中同号订阅；槽位下标会复用，**MUST NOT** 用下标作身份 |
| 句柄提供注销便捷入口 | 调用方必须显式传入要操作的总线；便捷入口委托该总线的 `Unsubscribe` |
| 句柄 **MUST NOT 缓存槽位下标** | 下标会在回调销毁后被复用，不能代表订阅身份 |

> **发号语义见[运行时实例](运行时实例.md) §1.2.4。** 二者都遵循发号域内永不复用、`0` 无效；订阅号的发号域是进程，不是单个总线。

**注销成本**：一次哈希查找拿到位置，再用下标直接命中——**平均 O(1)，不扫描**。

> **Why Not 只存身份、注销时扫描**：千级实体同时死亡时，扫描是 O(注销数 × 槽位数)，全挤在同一帧。

**批量注销**：所有者必须在销毁 / 撤销路径上把自己的订阅全部注销（§1.1.9）。

```cpp
void UnsubscribeAll(UTcsEventBusSubsystem& Bus,
                    TConstArrayView<FTcsEventSubscription> Handles);
```

> **Why Not 按所有者身份批量注销**：实体句柄、实例句柄、`UObject*` 三类身份互不统一，统一键必然退化为类型擦除。

### 1.1.5 两条注册路径 ✅

```cpp
// 路径 A：C++ 直收回调（满足铁律 3：不需要派生任何类型）
template <typename FPayloadType, typename TCallable>
FTcsEventSubscription Subscribe(
    FGameplayTag        Channel,
    TCallable&&         Callback,      // void(FGameplayTag, const FPayloadType&)
    ETcsEventMatch      Match = ETcsEventMatch::ExactMatch);

// 路径 B：反射（蓝图 / 脚本）
FTcsEventSubscription SubscribeReflected(
    FGameplayTag        Channel,
    UScriptStruct*      PayloadType,   // 期望的载荷类型
    UObject*            Sink,
    FName               FunctionName,
    ETcsEventMatch      Match = ETcsEventMatch::ExactMatch);
```

**路径 B 的过滤位置**：频道过滤与类型过滤**都在派发侧（C++）完成**，脚本虚拟机**不会收到不关心的频道**。

**两条路径共用 `FTcsEventSink` 的所有权契约与同一个派发循环**；各自在注册期构造自己的回调对象。

**`UObject* Sink` 回答的是「脚本 VM 调用谁」，不是「实体是谁」**：反射路径必须有一个 `UObject` 作为调用目标，这与「框架不知道实体载体的形态」无关（`战斗实体.md` §5.2 的禁令只针对**实体与实例相关契约**），因此不构成例外。

**回调签名只有一种**：`(发布频道, 载荷)`。**订阅句柄不进入回调**——需要自注销时，由持有者对自己那句柄调 `Unsubscribe`（§1.1.6 已保证回调内注销安全）。

### 1.1.6 派发：按发布 Tag 限定可见性 ✅

#### 新增订阅可见性

- **按总线实例与发布 Tag 隔离**：某个 Tag 的最外层活跃 `Publish` 在入栈时冻结当时已成功注册的订阅号上限；重入同一个发布 Tag MUST 沿用此上限，直到该 Tag 的最外层调用退出。其他发布 Tag 若首次入栈，按自己入栈时的情况确定上限。
- **匹配与可见性分别判断**：订阅所在频道、父链和载荷类型只决定是否匹配，不决定订阅何时可见。订阅号不超出本次上限、轮到时仍在册且匹配的订阅，才执行回调。
- **注册立即落位，注销立即失效**：上限只隔离新注册的订阅，不保留已注销订阅，也不以帧末或频道桶的深度归零作为新增生效条件。

| 同一总线上的调用序列 | 新增父频道 `A` 的 `PartialMatch` 订阅（载荷类型匹配） |
|---|---|
| 外层 `Publish(A.B)` 的回调中注册该订阅 | 不收到这次外层 `A.B`；不论 `A` 桶原本是否存在 |
| 外层未退出，首次嵌套 `Publish(A.C)` | 收到；`A.C` 单独确定上限 |
| 外层未退出，直接或经 `A.C` 重入 `Publish(A.B)` | 不收到；沿用外层 `A.B` 的上限 |
| 最外层 `A.B` 退出后再次 `Publish(A.B)` | 若订阅仍在册，则收到 |

#### 存储形态

**槽位永不压缩**。注册可以复用空槽或扩容；派发跨回调只保留频道态指针、循环下标及正在调用的堆回调对象指针，不保留槽位引用或迭代器。下标稳定不等于元素地址稳定。

```cpp
struct FTcsEventSlot
{
	FTcsEventSink        Sink;
	FGameplayTag         Channel;
	ETcsEventMatch       Match;
	const UScriptStruct* PayloadType;     // 两条路径都填；MUST NOT 为空
	int64                SubscriptionId;
	bool                 bAlive = false;
};

struct FTcsEventChannelState
{
	TArray<FTcsEventSlot> Slots;           // 稳定下标：MUST NOT 压缩
	TArray<int32>         FreeIndices;     // 空闲下标栈
	TArray<int32>         PendingRelease;  // 已注销，等待桶内派发结束后销毁并归还下标
	int32                 DispatchDepth = 0;
};

struct FTcsActivePublish
{
	int32 Depth = 0;
	int64 VisibleThroughId = 0;
};

// 均为当前总线实例的内部状态；频道态独立分配，Channels 扩容不搬频道态
TMap<FGameplayTag, TUniquePtr<FTcsEventChannelState>> Channels;
TMap<FGameplayTag, FTcsActivePublish> ActivePublishes; // 键是发布 Tag，不是订阅桶
int64 LastRegisteredSubscriptionId = 0; // 只记录本总线最后一次成功注册的号
bool  bDestroyingCallback = false;      // Q2：回调销毁守卫
bool  bClosed = false;                  // 关闭终态；关闭后不可逆
```

> **Why Not 直接存 `FTcsEventChannelState`**：`Publish` 跨回调使用频道态指针，回调内注册可能插入新频道、使 `Channels` 扩容。频道态独立分配才能保持这些指针有效。

**频道条目只由注册创建，只增不减**：`Publish` 只查找原频道及父频道，不创建订阅桶。若没有任何桶可访问，直接返回；`ActivePublishes` 只为有派发路径的活跃调用记录边界，最外层退出即删除对应记录。

#### 回调销毁与重入边界 ✅

**注销立即使订阅失效，但不得中断已进入的回调。** 注销先移除身份索引并让槽位的 `bAlive` 失效，阻止后续调用。若同一个回调重入，内层自注销后，已经进入的内层和外层都可执行完；**最后一层在途调用返回之前绝不能销毁对象**。本节实现用订阅所在频道桶的 `DispatchDepth` 保守保护在途调用：活跃桶延后到深度归零时清理，不承诺在该回调最后一次返回的瞬间析构。执行中的普通回调仍可注册、注销和同步发布。

**总线销毁自己持有的订阅回调时，由这次销毁触发的析构代码 MUST NOT 直接或间接在同一个总线实例上注册、注销或发布。** 此限制针对回调对象（包括释放它持有的资源所触发的连带析构），不是频道条目的销毁，也不是禁止宿主在自己的撤销路径上显式注销。若流程结束时必须同时注销多条订阅，由该流程的所有者显式注销，不依赖回调析构触发业务联动。

- **销毁侧**：`DestroySubscriptionCallback` 表示总线内部的唯一销毁路径。调用 `Sink.Reset()` 前在**当前总线实例**上建立销毁守卫，返回后恢复状态。即时注销、回收延迟释放的槽位、注册失败后释放已构造的回调，以及总线关闭时销毁剩余回调，均走此路径。槽位必须在回调销毁完成、持有者已为空后才能交回 `FreeIndices`。移动赋值、清空容器与复用槽位均不得隐式销毁仍由总线持有的回调。
- **入口侧**：`Subscribe`（C++）、`SubscribeReflected`、`Unsubscribe`、`Publish` MUST 在读取或修改订阅状态之前**优先检查销毁守卫**，再检查关闭终态；注册路径还 MUST 在构造总线持有的回调对象之前检查。句柄与批量注销入口同样不得绕过检查。
- **拒绝语义**：销毁守卫生效时，所有入口（含关闭期残留回调析构触发的 `Unsubscribe`）MUST 给出诊断并拒绝请求：注册返回无效句柄，注销与发布直接返回，不改变订阅状态、不派发，也不把请求排队待执行。
- **关闭终态**：总线的关闭入口（如 `Deinitialize`）MUST 在**静止态**调用——所有频道 `DispatchDepth == 0`、`PendingRelease` 为空、`ActivePublishes` 为空且未处于销毁守卫内；否则断言报错，不得在回调尚未返回时销毁其回调对象。进入关闭后立即置 `bClosed = true` 并清空 `IdentityToLocation`，随后扫描全部频道的全部槽位，对每个 `!Slot.Sink.IsEmpty()` 置 `bAlive = false` 并经 `DestroySubscriptionCallback` 逐个销毁；确认所有槽位均为空后，再清空 `Channels` 与其余内部容器。关闭完成后成为不可逆终态：`Subscribe`（含 `SubscribeReflected`）与 `Publish` MUST 给出诊断并拒绝，`Unsubscribe`（含句柄便捷入口与 `UnsubscribeAll`）静默 no-op。

#### 派发、注册与注销伪代码

以下伪代码展示通过上述入口检查后的调用体。发布 Tag 的活跃深度只用于确定新增边界；频道桶的派发深度只用于保护回调销毁，二者不得互用。

```cpp
// 本次匹配候选：发布 Tag 对应的桶 + 已存在的父桶
void CollectScope(
	FGameplayTag Channel,
	TArray<FTcsEventChannelState*, TInlineAllocator<8>>& Out)
{
	if (FTcsEventChannelState* State = FindChannel(Channel)) { Out.Add(State); }
	for (FGameplayTag Parent = Channel.RequestDirectParent();
		Parent.IsValid();
		Parent = Parent.RequestDirectParent())
	{
		if (FTcsEventChannelState* State = FindChannel(Parent)) { Out.Add(State); }
	}
}

int64 BeginPublish(FGameplayTag Channel)
{
	FTcsActivePublish& Active = ActivePublishes.FindOrAdd(Channel);
	if (Active.Depth == 0) { Active.VisibleThroughId = LastRegisteredSubscriptionId; }
	++Active.Depth;
	return Active.VisibleThroughId;
}

void EndPublish(FGameplayTag Channel)
{
	if (--ActivePublishes.FindChecked(Channel).Depth == 0)
	{
		ActivePublishes.Remove(Channel);
	}
}

void Publish(
	FGameplayTag Channel,
	const UScriptStruct* Type,
	const void* Data)
{
	TArray<FTcsEventChannelState*, TInlineAllocator<8>> Scope;
	CollectScope(Channel, Scope);
	if (Scope.IsEmpty()) { return; } // 没有用户回调，也没有可重入的派发

	const int64 VisibleThroughId = BeginPublish(Channel);
	for (FTcsEventChannelState* State : Scope) { ++State->DispatchDepth; }
	for (FTcsEventChannelState* State : Scope)
	{
		DispatchInto(*State, Channel, Type, Data, VisibleThroughId);
	}
	for (FTcsEventChannelState* State : Scope)
	{
		if (--State->DispatchDepth == 0) { ReleaseRetiredSlots(*State); }
	}
	EndPublish(Channel);
}

void DispatchInto(
	FTcsEventChannelState& State,
	FGameplayTag Channel,
	const UScriptStruct* Type,
	const void* Data,
	int64 VisibleThroughId)
{
	const int32 Count = State.Slots.Num(); // 只限制扫描范围，不承担可见性
	for (int32 Index = 0; Index < Count; ++Index)
	{
		FTcsEventCallback* Callback = nullptr;
		{
			const FTcsEventSlot& Slot = State.Slots[Index];
			if (!Slot.bAlive || Slot.SubscriptionId > VisibleThroughId) { continue; }
			if (!Matches(Slot, Channel, Type)) { continue; }
			Callback = Slot.Sink.BorrowCallback();
		}
		Callback->Invoke(Channel, Type, Data); // 可能扩容 Slots；不再访问原槽位引用
	}
}
```

**作用域按每次 `Publish` 单独采集**：同一次调用须用同一组桶升深、遍历和降深，保护父桶中的在途回调；内层可以采集到新建的桶，但能否调用其中的订阅仍由对应发布 Tag 的上限决定。跨回调只持有上限的值，不借用 `ActivePublishes` 的条目，以免其他 Tag 入栈使映射扩容。

**频道过滤全部由 `Matches` 承担**：原频道上精确订阅与层级订阅都能匹配；父频道上只有层级订阅能匹配。类型仍须精确相等，回调收到的永远是**原始发布 Tag**。

进程级订阅号通过模块内唯一的出线入口 `AllocateSubscriptionId()` 发放；其原子计数器保存在定义该函数的 `.cpp` 匿名命名空间中，不由总线实例持有（[运行时实例](运行时实例.md) §1.2.4、§1.3.4）。

```cpp
// 模块内部声明；耗尽时返回 0
int64 AllocateSubscriptionId();

// 两条注册路径共用的内部落位步骤；调用方已通过销毁守卫检查
FTcsEventSubscription AddSubscription(
	FGameplayTag Channel,
	ETcsEventMatch Match,
	const UScriptStruct* PayloadType,
	FTcsEventSink Sink)
{
	const int64 Id = AllocateSubscriptionId();
	if (Id == 0)
	{
		DestroySubscriptionCallback(Sink);
		return FTcsEventSubscription{};
	}

	FTcsEventChannelState& State = GetOrCreateChannel(Channel);
	const int32 Index = AllocateSlot(State);
	State.Slots[Index] = FTcsEventSlot{ MoveTemp(Sink), Channel, Match, PayloadType, Id, true };
	IdentityToLocation.Add(Id, { Channel, Index });
	LastRegisteredSubscriptionId = Id; // 槽位和索引都写完，才属于已注册的订阅
	return FTcsEventSubscription{ Id };
}

int32 AllocateSlot(FTcsEventChannelState& State)
{
	const int32 Index = State.FreeIndices.Num() > 0
		? State.FreeIndices.Pop(EAllowShrinking::No)
		: State.Slots.AddDefaulted();
	check(!State.Slots[Index].bAlive && State.Slots[Index].Sink.IsEmpty());
	return Index;
}
```

```cpp
void FTcsEventSubscription::Unsubscribe(UTcsEventBusSubsystem& Bus) const
{
	Bus.Unsubscribe(*this); // 走指定总线的公开入口及销毁守卫
}

// 当前总线的注销体；入口已通过销毁守卫检查
void Unsubscribe(FTcsEventSubscription Handle)
{
	const FTcsEventLocation* Loc = IdentityToLocation.Find(Handle.SubscriptionId);
	if (!Loc) { return; } // 只查本地；错总线、旧句柄和重复注销均不改状态

	FTcsEventChannelState& State = *FindChannel(Loc->Channel);
	const int32 Index = Loc->Index;
	IdentityToLocation.Remove(Handle.SubscriptionId);
	State.Slots[Index].bAlive = false;

	if (State.DispatchDepth > 0)
	{
		State.PendingRelease.Add(Index);
	}
	else
	{
		ReleaseSlot(State, Index);
	}
}

void ReleaseSlot(FTcsEventChannelState& State, int32 Index)
{
	DestroySubscriptionCallback(State.Slots[Index].Sink);
	State.FreeIndices.Add(Index);
}

void ReleaseRetiredSlots(FTcsEventChannelState& State)
{
	for (int32 Index : State.PendingRelease) { ReleaseSlot(State, Index); }
	State.PendingRelease.Reset();
}

// 关闭入口（如 Deinitialize）：要求静止前置，逐槽经守卫销毁后再清容器
void Shutdown()
{
	if (bClosed) { return; } // 已关闭：幂等

	check(!bDestroyingCallback);
	check(ActivePublishes.IsEmpty());
	for (const TPair<FGameplayTag, TUniquePtr<FTcsEventChannelState>>& Pair : Channels)
	{
		check(Pair.Value->DispatchDepth == 0 && Pair.Value->PendingRelease.IsEmpty());
	}

	bClosed = true;
	IdentityToLocation.Reset();

	for (TPair<FGameplayTag, TUniquePtr<FTcsEventChannelState>>& Pair : Channels)
	{
		FTcsEventChannelState& State = *Pair.Value;
		for (FTcsEventSlot& Slot : State.Slots)
		{
			Slot.bAlive = false;
			if (!Slot.Sink.IsEmpty())
			{
				DestroySubscriptionCallback(Slot.Sink);
			}
		}
		State.FreeIndices.Reset();
		State.PendingRelease.Reset();
	}

	// 此时所有回调对象均已走完守卫销毁，容器清空不再隐式触发任何回调析构
	Channels.Reset();
	ActivePublishes.Reset();
}
```

订阅号耗尽时，注册在修改频道、槽位和本地索引之前失败，返回空句柄；已构造的回调仍走销毁守卫。**派发不读取进程级计数器。** 发布上限只取本总线的 `LastRegisteredSubscriptionId`，其他总线发号不会抬高它。上限与槽位下标无关：即使新订阅复用扫描范围内的空槽，它的订阅号也大于此前冻结的上限；同 Tag 重入重新采集到新桶或看到更大的槽位数组，同样不会命中它。注销不回退总线的订阅号上限。

#### 下标不变量 ✅

| # | 不变量 |
|---|---|
| S1 | `FreeIndices` 中每个下标 MUST 满足 `Slots[i].bAlive == false` 且 `Slots[i].Sink.IsEmpty()`；不可把仅标为不存活、仍持有回调的槽位交回 |
| S2 | 稳定状态下，每个 `bAlive == false` 的下标 MUST 在 `FreeIndices` 或 `PendingRelease` 中恰好出现一次 |
| S3 | 分配下标 MUST 先 `FreeIndices.Pop()`，栈空才 `AddDefaulted()`；MUST NOT 直接用 `Slots.Num()` 追加 |
| S4 | 活跃桶中注销的槽位先进入 `PendingRelease`，深度归零时才销毁回调并归还下标；该深度不限制新订阅的可见性 |
| S5 | `bAlive == true` ⇔ 身份索引中存在且仅存在一条指向该槽位的条目 |

#### 成本与分配边界 ✅

- **注销不扫描槽位**：一次身份索引查找和一次下标定位即摘除，索引查找平均 O(1)；回收和销毁是独立步骤。
- **派发按槽位数组的历史峰值扫描**：可能经过空洞、待释放槽和超出本次上限的新订阅。活跃桶中已注销但尚未销毁的槽位不能复用，因此峰值不等于同时在册的订阅数峰值。保持稳定下标，不为压缩而搬动存量槽位。
- **调用已有回调不复制回调对象，也不为其重新分配存储**；不承诺整次 `Publish` 零分配。首次进入一个发布 Tag 时活跃表可能扩容，作用域超出内联容量或回收数组扩容也可能分配；回调内注册另需构造回调对象，创建频道或扩容 `Slots` 也可能分配。

#### `Matches` 的定义 ✅

```cpp
bool Matches(const FTcsEventSlot& Slot, FGameplayTag Channel, const UScriptStruct* Type) const
{
    // ① 类型：MUST 精确相等。两条路径的 PayloadType 都非空（见 §1.1.2）
    if (Slot.PayloadType != Type) { return false; }

    // ② 频道：默认精确匹配；PartialMatch 才沿父链比较
    if (Slot.Match == ETcsEventMatch::ExactMatch) { return Slot.Channel == Channel; }
    return Channel.MatchesTag(Slot.Channel);
}
```

| 判据 | 约定 |
|---|---|
| 类型比较 | **指针相等**即可——`UScriptStruct*` 是注册期解析的唯一实例，不需要名字比较 |
| 类型 MUST NOT 放宽 | 子类 / 结构兼容一律**不做**：那会让订阅者收到它没声明能处理的结构 |
| `PayloadType` 为空 | **非法状态**，注册期就应被 `check` 挡住，不在此处兜底 |

### 1.1.7 频道层级匹配：显式开启 ✅

```cpp
enum class ETcsEventMatch : uint8
{
    ExactMatch,     // 默认：A.B 只收 A.B
    PartialMatch,   // 显式：A.B 收 A.B 与 A.B.*
};
```

**默认必须是 `ExactMatch`。**

| 理由 | 说明 |
|---|---|
| 精确匹配是「我就要这一条」的直白语义 | 层级匹配是「我要这一类」，是更强的假设 |
| 层级匹配有额外成本 | 需要沿 tag 父链逐层查找或预摊平 |
| 默认 MUST 是最省的形态 | 需要层级的调用方显式开启，成本可归因 |

### 1.1.8 载荷生命周期：受控借用 ✅

**契约**：载荷指针**只在派发调用期间有效**。

| 允许 | 禁止 |
|---|---|
| 在回调内**读**载荷 | 把载荷指针**存起来**延后使用 |
| 在回调内**拷贝**载荷到自己的容器 | 在回调内**修改**载荷 |
| 在回调内**发布新事件** | 在回调内**长时间阻塞** |

> **Why Not 值语义（每次拷贝）**：拷贝对高频事件是直接成本，而绝大多数订阅者只读。

**代价必须明确写进契约**：反射路径的消费者（蓝图 / 脚本）**MUST 当场拷贝**，否则悬空。

### 1.1.9 订阅生命周期闭合 ✅

**纪律**：施加时注册、撤销时注销，由**同一个所有者**配对完成。

**总线无法强制这条，但它是使用契约的一部分**：

| 错误形态 | 后果 |
|---|---|
| 只注册不注销 | 订阅永远增长，派发越来越慢 |
| 注册在 A 对象、注销在 B 对象 | 生命周期不一致，容易漏删 |
| 在回调里注册但不留句柄 | 无法注销 |
| **反射路径的对象先被销毁，订阅没注销** | **反射回调对象里的 `UObject*` 已失效，派发会打到失效对象** |

**第四条 MUST 由注销路径解决**：

> **宿主 MUST 在反射订阅对象失效前显式注销它的全部订阅**（`UnsubscribeAll`，或逐个 `Unsubscribe`），不能依赖总线销毁回调时触发注销（§1.1.6）。总线**不提供**对象存活查询，MUST NOT 在派发热路径上判断「订阅者还在不在」。

| Why Not 总线自己判失效 | 说明 |
|---|---|
| 需要每派发一次检查 | 那是把一次不可控的 GC 语义塞进每个事件的成本里 |
| 只能覆盖一半 | 弱引用只对反射路径的 `Sink` 有意义；C++ 路径的捕获物没有对象可查，两套语义会分裂 |
| 有唯一正确时机 | 对象销毁是**确定的**时刻，宿主在那里注销即可；派发期判断是**猜测** |

### 1.1.10 业务需求

| 游戏 | 特殊要求 |
|---|---|
| LAC | 跨实体联动 MUST 有序且可回放 |
| 第三人称动作 | 帧内 MUST 有序 |
| 幸存者 ARPG | 千级实体 × 高频事件 |

### 1.1.11 路由结构不预设

> **压测数据到手前，MUST NOT 为路由加按实体过滤的快路径，也 MUST NOT 改路线形态。**

缺什么：**「订阅者总数」与「实际匹配该频道的订阅者数」的比值**——见族外 `Documents/tcs-remake-v2-drafts/未决-核心基线.md` §4。

## 1.2 帧末派发通道：**不建** ✅

### 1.2.1 它要解决的问题

**防重入与无限连锁**：状态类事件（伤害 / 死亡）若在派发过程中再次触发同类事件，会形成重入。

### 1.2.2 不建的判据

> **没有事件分级清单，就不该有一个帧末通道。**

这个通道要成立，必须先有一张**分级表**：哪些事件立即派发、哪些帧末派发。**该表不存在**，于是通道的存在只是每帧一次空调用。

### 1.2.3 与动作游戏的冲突

动作游戏里「伤害判定 → 死亡 → 表现」MUST 在**同一帧**完成。延迟一拍破坏手感。

⇒ **帧末派发不是「更好的」派发，只是一个特定语义下的选择**，不能作为默认。

### 1.2.4 重开此通道的触发条件

> **先写清分级表，再加通道**；一次只加一条，且该条 MUST 当场有发布者。分级表不存在时 MUST NOT 建通道。

### 1.2.5 被否的是「通道」，不是「合并语义」 ✅

「帧末」这个词常被用来指**三件互不相关的事**，本节否掉的只是其中一件：

| # | 用途 | 目的 | 本节处置 |
|---|---|---|---|
| ① | **总线帧末派发通道** | 结构性切断重入与无限连锁 | **不建**（§1.2.2） |
| ② | **领域自身的延迟安全点** | 某领域在帧末或安全点统一收口脏项 / 补发 | **不由总线提供**——归各领域自行裁决与承载，与本节无关 |
| ③ | **表现层同帧合并去重** | 一帧 N 次同类提示合成一条 | **语义成立，但不由总线承担** |

> **为什么不能由一条通道同时满足**：三件事对延迟的要求互不相容——① 要「结构性切断重入」、③ 要「同帧合并去重」，两者都指向「晚一拍」，但**晚的理由与作用域不同**：① 是全局重入，③ 只在某一接收侧。一条全局通道无法同时满足两种不同作用域的延迟要求。

> **③ 为什么不该由总线提供**：合并去重是**消费域自己的语义**——只需在它的接收侧按帧聚合。总线若开第二条通道，等于替**所有**订阅者决定「晚一拍」，那是全局延迟，不是合并。
> ⇒ **③ MUST NOT 被援引为「恢复帧末通道」的理由**。
