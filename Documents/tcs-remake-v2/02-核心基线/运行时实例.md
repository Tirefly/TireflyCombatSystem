# 核心基线 · 运行时实例（Instance）

> **定位**：V2 五项核心基线之一（Entity / Instance / Clock / EventBus / NumericAggregator）。
> **回答什么问题**：**每帧在跑的那些东西怎么装、怎么复用、怎么防悬空、怎么成组撤销**。

**图例**：✅ 已裁决 ｜ ⚠️ 待审 ｜ ❓ 待调研

> **本文件只写最终设计。** Why Not 一律一句话。

---

## 0. 本域的三样东西

| 东西 | 回答什么 | 生命周期 |
|---|---|---|
| **实例句柄** | 这个实例是谁 | 进程级发号 |
| **实例池** | 实例怎么装、怎么复用、怎么防悬空 | 进程级 |
| **来源句柄** | 这一批实例是哪一次施加产生的、要一起撤 | 进程级发号，实例级归属 |

三者正交：句柄答**身份**，池管**槽位**，来源答**归属**。

## 1.1 实例句柄 ✅

### 1.1.1 形态：三段，不是模板

```cpp
USTRUCT(BlueprintType)
struct FTcsBuffInstanceHandle
{
    // 池标识（寻址：哪个池）
    UPROPERTY(BlueprintReadOnly, Category = "Tcs|State")
    int32 PoolId = 0;

    // 槽位下标（寻址：池内哪个槽）
    UPROPERTY(BlueprintReadOnly, Category = "Tcs|State")
    int32 Index = -1;

    // 实例身份（每池自发号，永不复用；0 = 无实例）
    UPROPERTY(BlueprintReadOnly, Category = "Tcs|State")
    int64 InstanceId = 0;

    // 只答「三段是否非空」，不答「实例是否仍在册」——在册与否只有池能答
    bool IsValid() const { return Index >= 0 && InstanceId != 0; }

    friend bool operator==(const FTcsBuffInstanceHandle& A, const FTcsBuffInstanceHandle& B)
    {
        return A.PoolId == B.PoolId && A.Index == B.Index && A.InstanceId == B.InstanceId;
    }
};
```

**每种句柄各写一份**（`FTcsSkillInstanceHandle` / `FTcsSkillEntryHandle` / …），字段与成员逐字同构，只是类型名不同。

| 段 | 职责 | 校验角色 |
|---|---|---|
| `PoolId` | 寻址 | 池不存在 ⇒ 无效 |
| `Index` | 寻址 | 越界或空闲槽 ⇒ 无效 |
| `InstanceId` | **身份** | **决定项**：与槽当前值不符 ⇒ 无效 |

> **判据：前两段换性能，第三段换正确性。**

### 1.1.2 每种句柄是一个独立 `USTRUCT`，MUST NOT 用模板 ✅

> **句柄 MUST NOT 是模板类型。** 每个句柄是独立的 `USTRUCT`，类型安全由类型本身保证。

> **Why Not 模板**：模板不可反射，逼出「平展副本 + GetInner/SetInner」胶水层；类型安全由独立 `USTRUCT` 本身给出。

> **泛型处理句柄是非法诉求**——那等于放弃类型安全。

### 1.1.3 `InstanceId` 是身份，不是版本号 ✅

> **`InstanceId` 由每个池自发号，池内永不复用；`0` = 无实例。**

**句柄的身份 = `(PoolId, InstanceId)`，这一对才是进程唯一且永不复用。**

> **`InstanceId` 单独 MUST NOT 被当作全局唯一。** 它的作用域是池。

**占用判据只有一条**：`InstanceId == 0` ⇒ 空闲。MUST NOT 另设位图或奇偶位。

### 1.1.4 需要句柄的类型 ✅

> **只有同时满足两条才需要句柄：① 跨容器 / 跨调用边界被引用；② 槽位会复用。**

| 类型 | 需要 | 判据 |
|---|---|---|
| Buff 实例 | ✅ | 双条满足 |
| Skill 实例 | ✅ | 双条满足 |
| Skill 账本条目 | ✅ | 双条满足 |

> **其余类型是否要句柄，未决**（见族外 `未决-核心基线.md`）。在裁决前 MUST NOT 为它们建句柄。

### 1.1.5 `InstanceId` 宽度：`int64` ✅

> **所有池的 `InstanceId` MUST 统一用 `int64`**，MUST NOT 按池定宽。

**Why Not 按池定宽**：句柄要跨模块传递，两种宽度会让泛型、序列化与反射一起分叉。

## 1.2 实例池 `TTcsInstancePool` ✅

### 1.2.1 形态

**稠密数组 + FreeList + `InstanceId` 防悬空。**

```cpp
template <typename TInstance, typename THandle>
class TTcsInstancePool
{
public:
    // 建池时领一个进程唯一的 PoolId（永不复用，池销毁即作废）
    explicit TTcsInstancePool(int32 InPoolId) : PoolId(InPoolId) {}

    // 分配：优先复用 FreeList 尾部；每池独立发号，不共享全局计数器
    THandle Allocate()
    {
        int32 SlotIndex;
        if (FreeList.Num() > 0)
        {
            SlotIndex = FreeList.Pop(EAllowShrinking::No);
        }
        else
        {
            SlotIndex = Instances.AddDefaulted();
            InstanceIds.Add(0);
        }

        // 复用槽位 MUST 重置实例本体：上一任的残留字段 MUST NOT 被新实例继承
        Instances[SlotIndex] = TInstance{};

        InstanceIds[SlotIndex] = NextInstanceId++;   // 每池自发号，永不复用
        return THandle{ PoolId, SlotIndex, InstanceIds[SlotIndex] };
    }

    // 释放：InstanceId 置 0 即空闲，槽位压回 FreeList
    void Free(THandle Handle)
    {
        if (!IsValid(Handle)) { return; }
        InstanceIds[Handle.Index] = 0;
        FreeList.Push(Handle.Index);
    }

    // 有效性：一次 InstanceId 比较——唯一决定项
    bool IsValid(THandle Handle) const
    {
        return Handle.PoolId == PoolId
            && Instances.IsValidIndex(Handle.Index)
            && InstanceIds[Handle.Index] == Handle.InstanceId
            && Handle.InstanceId != 0;
    }

    // 解析：无效返回 nullptr（查询面，不 ensure）
    const TInstance* Resolve(THandle Handle) const
    {
        return IsValid(Handle) ? &Instances[Handle.Index] : nullptr;
    }

    // 遍历：顺序扫稠密数组，跳过空闲槽
    void ForEach(TFunctionRef<void(const TInstance&)> Visitor) const
    {
        for (int32 SlotIndex = 0; SlotIndex < Instances.Num(); ++SlotIndex)
        {
            if (InstanceIds[SlotIndex] != 0) { Visitor(Instances[SlotIndex]); }
        }
    }

private:
    int32 PoolId = 0;                    // 进程唯一、永不复用
    int64 NextInstanceId = 1;            // 每池独立计数器
    TArray<TInstance> Instances;         // 稠密数组（含空闲洞）
    TArray<int64> InstanceIds;           // 每槽当前身份（0 = 空闲）
    TArray<int32> FreeList;              // 空闲槽栈
};
```

| 操作 | 代价 |
|---|---|
| 遍历有效实例 | 顺序扫稠密数组，跳过 `InstanceId == 0` |
| 校验单个句柄 | 一次 `InstanceId` 比较 |
| 分配 | FreeList 弹栈 → **重置槽位本体** → 取新 `InstanceId` |
| 释放 | `InstanceId` 置 0 后压回 FreeList |

> **`Allocate` MUST 重置 `Instances[SlotIndex]`**：槽位复用意味着上一任实例的字段还在，不重置会让新实例继承旧数据。
> **Why Not 在 `Free` 时清**：`Free` 只做「失效」（置 `InstanceId = 0`），清数据属于分配职责——失效瞬间读到的实例内容对**仍在持有该句柄的调用方**仍有诊断价值。

### 1.2.2 池的两职责 ✅

| 职责 | 内容 |
|---|---|
| **槽位复用** | 从 FreeList 拿槽位、归还槽位 |
| **身份发号** | 给实例发一个池内永不复用的 `InstanceId` |

> **判据：跨池区分由 `PoolId` 承担。** 每个池的 `InstanceId` 独立计数，MUST NOT 共享全局计数器。

### 1.2.3 `PoolId` 的发号 ✅

| 项 | 结论 |
|---|---|
| 粒度 | **每个池实例一个 `PoolId`**（每个实体桶 + 每个系统池各有一个） |
| 唯一性 | **进程唯一、永不复用** |
| 发号 | 全局原子递增，出线实现 |
| 生命周期 | 池销毁后该 `PoolId` **作废**，不退还 |

> **判据**：`PoolId` 复用会让旧句柄命中新池。它的发号速率 = 池创建速率，远低于实例分配。

## 1.3 来源句柄 `FTcsSourceHandle` ✅

### 1.3.1 形态

```cpp
// 非反射裸 struct：不进细节面板、不进资产
struct FTcsSourceHandle
{
    // 进程唯一、永不复用；0 = 无效
    uint64 Id = 0;

    bool IsValid() const { return Id != 0; }

    friend bool operator==(FTcsSourceHandle A, FTcsSourceHandle B) { return A.Id == B.Id; }
};

// 发号器：出线实现（Allocate() 在 .cpp，计数器住该文件匿名 namespace）
struct FTcsSourceHandleRegistry
{
    FTcsSourceHandle Allocate();   // 原子递增，从 1 起
};
```

| 属性 | 值 |
|---|---|
| 存储 | `uint64` |
| 分配 | 原子递增，出线实现 |
| 唯一性 | **进程唯一**、**永不复用** |
| 是否反射 | **否**（裸 `struct`，不进资产） |

> **宽度与另外两种句柄不同的原因**：它不进反射，可以用 `uint64`；实体句柄与实例句柄要进反射，MUST 用 `int64`。

> ⚠️ **待查**：此处原写「UHT 不支持 `uint64` 作属性类型」，该理由**未经核实且可能不成立**（UE 5.8 `UhtUInt64Property.cs` 有 `uint64` 关键字支持）。受影响的只是**理由**，结论 `int64` 不变。见族外 `未决-核心基线.md` §7。

### 1.3.2 归属：Instance，不是 Entity ✅

| # | 判据（一句话） |
|---|---|
| ① | 它只挂在实例上——「哪次施加产生了这批实例」 |
| ② | 定义侧 MUST NOT 有它：同一份定义，甲靠装备给、乙靠天赋给 ⇒ 来源因实例而异 |
| ③ | 它是生命周期概念而非身份概念：只回答「这批东西要一起撤」 |

### 1.3.3 一柄两角：施加方来源 vs 撤销锚点 ✅

| 角色 | 语义 | 用途 | 撤销时 |
|---|---|---|---|
| **施加方来源** | 谁施加的 | 续杯判据、叠层判据 | **MUST NOT** 当撤销锚点 |
| **撤销锚点** | 哪一次施加产生的 | 级联撤销 | 按它精确摘除 |

> **Why Not 合并**：一个来源可施加多个不同定义，单号撤销会互相误摘。

### 1.3.4 进程唯一的实现纪律 ✅

**发号 MUST 出线**：`Allocate()` 定义在 `.cpp`，计数器住该文件的匿名 namespace。

> **判据**：内联变量在 MSVC 上不跨 DLL 合并 ⇒ 每个镜像各一份计数器、跨模块重号，且症状随构建配置漂移。

> 这条对**所有**「进程唯一发号」设施一律适用（实体句柄、`PoolId` 同理）。

### 1.3.5 设计克制 ✅

> **只做归属，不承载因果链。**

因果链由对象图天然边承载；来源句柄对来源的内容一无所知。

> **Why Not 承载因果**：一旦开始「顺便多记」，它会持续长大成内部小世界。

## 1.4 观测面 ✅

| 变量 | 读数 |
|---|---|
| 池槽位占用 | 跨池已分配槽位总数 |
| 到期堆深度 | 有效条目数 |

## 已裁定（速查）

| 项 | 结论 |
|---|---|
| 句柄形态 | **三段**：`PoolId` + `Index` + `InstanceId` |
| 句柄载体 | **每种一个独立 `USTRUCT`**，MUST NOT 用模板 |
| 身份 | **`(PoolId, InstanceId)` 进程唯一永不复用**；`InstanceId` 单独不全局唯一 |
| 占用判据 | **只有 `InstanceId == 0`**；MUST NOT 另设位图或奇偶位 |
| `InstanceId` 宽度 | **统一 `int64`**，MUST NOT 按池定宽 |
| `PoolId` | **每池实例一个**，全局发号、永不复用、销毁作废 |
| 句柄门槛 | 跨边界引用 **且** 槽位复用，两条同时满足 |
| 池形态 | **稠密数组 + FreeList** |
| 池的两职责 | **必须分开**：槽位复用 / 身份发号 |
| 来源句柄归属 | **Instance**（不归 Entity） |
| 来源 vs 锚点 | **两个号，不可合并** |
| 进程唯一发号 | **MUST 出线实现** |
| 设计克制 | **只做归属，不承载因果链** |
| 观测面 | **无参对**；应成体系提供 |
