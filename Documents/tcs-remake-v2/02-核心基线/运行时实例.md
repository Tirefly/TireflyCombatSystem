# 核心基线 · 运行时实例（Instance）

> **定位**：V2 五项核心基线之一（Entity / Instance / Clock / EventBus / NumericAggregator）。
> **回答什么问题**：**每帧在跑的那些东西怎么装、怎么复用、怎么防悬空、怎么成组撤销**。

**图例**：✅ 已裁决 ｜ ⚠️ 待审 ｜ ❓ 待调研

> **本文件只写最终设计。** Why Not 一律一句话。

---

## 0. 本域的三样东西

| 东西 | 回答什么 | 生命周期 |
|---|---|---|
| **实例句柄** | 这个实例是谁 | 进程级发号 |
| **实例池** | 实例怎么装、怎么复用、怎么防悬空 | 进程级 |
| **来源句柄** | 这一批实例是哪一次施加产生的、要一起撤 | 进程级发号，实例级归属 |

三者正交：句柄答**身份**，池管**槽位**，来源答**归属**。

## 1.1 实例句柄 ✅

### 1.1.1 形态：三段，不是模板

```cpp
USTRUCT(BlueprintType)
struct FTcsBuffInstanceHandle
{
    // 池标识（寻址：哪个池；从 1 起发号，0 = 无效池）
    UPROPERTY(BlueprintReadOnly, Category = "Tcs|State")
    int32 PoolId = 0;

    // 槽位下标（寻址：池内哪个槽）
    UPROPERTY(BlueprintReadOnly, Category = "Tcs|State")
    int32 Index = -1;

    // 实例身份（每池自发号，从 1 起，永不复用；0 = 无实例）
    UPROPERTY(BlueprintReadOnly, Category = "Tcs|State")
    int64 InstanceId = 0;

    // 只答「三段是否成形」，不答「实例是否仍在册」——在册与否只有池能答
    bool IsValid() const { return PoolId != 0 && Index >= 0 && InstanceId != 0; }

    friend bool operator==(const FTcsBuffInstanceHandle& A, const FTcsBuffInstanceHandle& B)
    {
        return A.PoolId == B.PoolId && A.Index == B.Index && A.InstanceId == B.InstanceId;
    }
};
```

**每种句柄各写一份**（`FTcsSkillInstanceHandle` / `FTcsSkillEntryHandle` / …），字段与成员逐字同构，只是类型名不同。

| 段 | 职责 | 校验角色 |
|---|---|---|
| `PoolId` | 寻址 | 池不存在 ⇒ 无效 |
| `Index` | 寻址 | 越界或空闲槽 ⇒ 无效 |
| `InstanceId` | **身份** | **决定项**：与槽当前值不符 ⇒ 无效 |

> **判据：前两段换性能，第三段换正确性。**

**两种「有效」MUST 分开**：

| 判定 | 谁答 | 回答什么 |
|---|---|---|
| **格式有效** | 句柄自己的 `IsValid()` | 这是不是一个**成形的**句柄（三段都非空） |
| **在册有效** | 池的 `IsValid(Handle)` | 这个实例**现在还在不在**（`PoolId` 相符 + 下标未越界 + `InstanceIds[Index] == InstanceId`） |

句柄的 `IsValid` 只用于空句柄早退，**MUST NOT** 被当成存活判据。

### 1.1.2 每种句柄是一个独立 `USTRUCT`，MUST NOT 用模板 ✅

> **句柄 MUST NOT 是模板类型。** 每个句柄是独立的 `USTRUCT`，类型安全由类型本身保证。

> **Why Not 模板**：模板不可反射，逼出「平展副本 + GetInner/SetInner」胶水层；类型安全由独立 `USTRUCT` 本身给出。

> **泛型处理句柄是非法诉求**——那等于放弃类型安全。

### 1.1.3 `InstanceId` 是身份，不是版本号 ✅

> **`InstanceId` 由每个池自发号，池内永不复用；`0` = 无实例。**

**句柄的身份 = `(PoolId, InstanceId)`，这一对才是进程唯一且永不复用。**

> **`InstanceId` 单独 MUST NOT 被当作全局唯一。** 它的作用域是池。

**占用判据只有一条**：`InstanceId == 0` ⇒ 空闲。MUST NOT 另设位图或奇偶位。

### 1.1.4 需要句柄的类型 ✅

> **只有同时满足两条才需要句柄：① 跨容器 / 跨调用边界被引用；② 槽位会复用。**

| 类型 | 需要 | 判据 |
|---|---|---|
| Buff 实例 | ✅ | 双条满足 |
| Skill 实例 | ✅ | 双条满足 |
| Skill 账本条目 | ✅ | 双条满足 |

> **其余类型是否要句柄，未决**（见族外 `未决-核心基线.md`）。在裁决前 MUST NOT 为它们建句柄。

### 1.1.5 `InstanceId` 宽度：`int64` ✅

> **所有池的 `InstanceId` MUST 统一用 `int64`**，MUST NOT 按池定宽。

**Why Not 按池定宽**：句柄要跨模块传递，两种宽度会让泛型、序列化与反射一起分叉。

### 1.1.6 句柄 → 实例：定位是领域义务 ✅

> **基线不提供「句柄 → 实例本体」的通用定位器。**

**领域义务**：持有实例池的领域 MUST 提供一个**从句柄出发的静态入口**，供无 `this` 的回调使用。

| 项 | 说明 |
|---|---|
| 入口形态 | 静态函数或进程级单例，`Handle → 池 / 实例` |
| 为什么安全 | `PoolId` 进程唯一、永不复用 ⇒ 入口可以断言「`Handle.PoolId` 就是自己」 |
| 为什么是义务不是基线机制 | 基线层没有任何机制需要「遍历所有池」；而到期回调的捕获预算（`统一时钟.md` §1.2.5）禁止它捕获池指针 ⇒ 只能由领域静态入口补上这一环 |

**Why Not 基线级 `PoolId → 池` 注册表**：

| 判据 | 结论 |
|---|---|
| 铁律 ① 真实消费者 | 无——没有任何**基线**机制需要跨池遍历 |
| 铁律 ② 两个实现者 | 只有到期回调一个消费者 |
| 能力 | 池是模板、句柄按池独立成类型 ⇒ 注册表只能类型擦除到「校验」，拿不到实例本体 |
| 代价 | 虚基类 + 注册/注销生命周期 + 注销竞态，换来的只是省掉每域一个静态函数 |

## 1.2 实例池 `TTcsInstancePool` ✅

### 1.2.1 形态

**稠密数组 + FreeList + `InstanceId` 防悬空。**

```cpp
template <typename TInstance, typename THandle>
class TTcsInstancePool
{
public:
    // 建池时自领一个进程唯一的 PoolId（从 1 起，永不复用，池销毁即作废）
    TTcsInstancePool() : PoolId(AllocatePoolId()) {}

    // 身份型对象：不可复制、不可移动——复制会让两个池共用一个 PoolId
    TTcsInstancePool(const TTcsInstancePool&)            = delete;
    TTcsInstancePool& operator=(const TTcsInstancePool&) = delete;

    // 分配：优先复用 FreeList 尾部；每池独立发号，不共享全局计数器
    THandle Allocate()
    {
        // 先判耗尽：失败不得改动任何状态，否则会先弹出一个槽位再失败，槽位永久泄漏
        const int64 NewInstanceId = NextInstanceId.Allocate();
        if (NewInstanceId == 0) { return THandle{}; }

        int32 SlotIndex;
        if (FreeList.Num() > 0)
        {
            SlotIndex = FreeList.Pop(EAllowShrinking::No);
        }
        else
        {
            SlotIndex = Instances.AddDefaulted();
            InstanceIds.Add(0);
        }

        // 复用槽位 MUST 重置实例本体：上一任的残留字段 MUST NOT 被新实例继承
        Instances[SlotIndex] = TInstance{};

        InstanceIds[SlotIndex] = NewInstanceId;
        return THandle{ PoolId, SlotIndex, NewInstanceId };
    }

    // 释放：InstanceId 置 0 即空闲，槽位压回 FreeList；不销毁实例本体
    void Free(THandle Handle)
    {
        if (!IsValid(Handle)) { return; }
        InstanceIds[Handle.Index] = 0;
        FreeList.Push(Handle.Index);
    }

    // 有效性：一次 InstanceId 比较——唯一决定项
    bool IsValid(THandle Handle) const
    {
        return Handle.PoolId == PoolId
            && Instances.IsValidIndex(Handle.Index)
            && InstanceIds[Handle.Index] == Handle.InstanceId
            && Handle.InstanceId != 0;
    }

    // 解析：无效返回 nullptr（查询面，不 ensure）；返回值在下一次 Allocate 之前有效
    const TInstance* Resolve(THandle Handle) const
    {
        return IsValid(Handle) ? &Instances[Handle.Index] : nullptr;
    }

    // 可变访问：无效返回 nullptr；返回值同受借用契约约束
    TInstance* FindMutable(THandle Handle)
    {
        return IsValid(Handle) ? &Instances[Handle.Index] : nullptr;
    }

    // 遍历：锁定长度，只给句柄——循环不持有任何会被搬迁的元素地址
    void ForEach(TFunctionRef<void(THandle)> Visitor) const
    {
        const int32 Count = Instances.Num();          // 锁定：遍历期间新增的不访问
        for (int32 SlotIndex = 0; SlotIndex < Count; ++SlotIndex)
        {
            if (InstanceIds[SlotIndex] == 0) { continue; }
            Visitor(THandle{ PoolId, SlotIndex, InstanceIds[SlotIndex] });
        }
    }

private:
    int32 PoolId = 0;                    // 由 AllocatePoolId() 发放；从 1 起，0 = 无效
    TTcsIdCounter<int64> NextInstanceId; // 每池独立发号，耗尽即永久失效
    TArray<TInstance> Instances;         // 稠密数组（含空闲洞）
    TArray<int64> InstanceIds;           // 每槽当前身份（0 = 空闲）
    TArray<int32> FreeList;              // 空闲槽栈
};
```

| 操作 | 代价 |
|---|---|
| 遍历有效实例 | 顺序扫稠密数组，跳过 `InstanceId == 0` |
| 校验单个句柄 | 一次 `InstanceId` 比较 |
| 分配 | FreeList 弹栈 → **重置槽位本体** → 取新 `InstanceId` |
| 释放 | `InstanceId` 置 0 后压回 FreeList |

> **`Allocate` MUST 重置 `Instances[SlotIndex]`**：槽位复用意味着上一任实例的字段还在，不重置会让新实例继承旧数据。
> **Why Not 在 `Free` 时清**：`Allocate` 反正要重置，`Free` 再清是同一份工作的重复；而 `Free` 是批量路径（千级实体同帧死亡），每次多做一次重置没有收益。

**代价**：空闲槽会保留上一任实例持有的资源，直到该槽被复用——不构成泄漏，池销毁时一并释放。

**诊断**：`Free` 之后 API 一律不可读（`Resolve` 返回 `nullptr`）；要看上一任的残留内容，直接在调试器里检查 `Instances[SlotIndex]`。

#### 借用与遍历契约

> **`Resolve` / `FindMutable` 的返回值 MUST 在下次 `Allocate` 之前用完。**
> `Free` 不移动元素，不使其失效（但该实例已作废）；池销毁使全部借用失效。

| 操作 | 遍历中可否调用 | 理由 |
|---|---|---|
| `Free` | **可以** | 只置 `InstanceIds[Index] = 0` 并压 `FreeList`，不移动数组 |
| `Allocate` | **可以** | `ForEach` 锁定 `Count` 且只传句柄，循环不持有元素地址；新增元素落在 `Count` 之外，**本拍不生效** |
| `Resolve` / `FindMutable` | 可以 | 返回值在本次回调内用完即可 |

**`ForEach` MUST 锁定 `Instances.Num()`**，MUST NOT 每轮重算长度——否则遍历中新增的元素会被同轮访问。

> **Why 只传句柄、不传元素引用**：引用会在 `Allocate` 扩容时悬空，而循环跨越整个回调，本身就违反了上面的借用规则。传句柄后循环不再持有任何数组地址，`Allocate` 因此可以在遍历中合法发生。

#### 池元素的 `UObject` 引用

池用 `TArray<TInstance>` 按值存实例，GC 看不见里面的 `UObject` 引用。

> **池元素若持有强 `UObject` 引用，池的拥有者 MUST 在 `AddReferencedObjects` 里遍历池并追踪。**

这是池的通用义务，不针对某一类实例。当前各池只持弱引用，故未暴露；一旦引入强引用而不追踪，对象会被静默回收——表现为「步骤不生效」而不是崩溃。

### 1.2.2 池的两职责 ✅

| 职责 | 内容 |
|---|---|
| **槽位复用** | 从 FreeList 拿槽位、归还槽位 |
| **身份发号** | 给实例发一个池内永不复用的 `InstanceId` |

> **判据：跨池区分由 `PoolId` 承担。** 每个池的 `InstanceId` 独立计数，MUST NOT 共享全局计数器。

### 1.2.3 `PoolId` 的发号 ✅

| 项 | 结论 |
|---|---|
| 粒度 | **每个池实例一个 `PoolId`**（每个实体桶 + 每个系统池各有一个） |
| 唯一性 | **进程唯一、永不复用** |
| 发号 | 由池自领（`AllocatePoolId()`），全局原子递增，**从 1 起**；`0` = 无效池 |
| 生命周期 | 池销毁后该 `PoolId` **作废**，不退还 |

> **判据**：`PoolId` 复用会让旧句柄命中新池。它的发号速率 = 池创建速率，远低于实例分配。

### 1.2.4 发号器 ✅

**五个计数器共用一套语义**：`PoolId`、`InstanceId`、`EntityId`、`SourceHandle.Id`、`SubscriptionId`。

| 计数器 | 宽度 | 作用域 | 起始 | 耗尽后果 |
|---|---|---|---|---|
| `PoolId` | `int32` | 进程 | 1 | 池创建失败，返回无效池 |
| `InstanceId` | `int64` | 每池 | 1 | 该池 `Allocate()` 返回空句柄，槽位不动 |
| `EntityId` | `int64` | 进程 | 1 | 实体注册失败，返回空句柄 |
| `SourceHandle.Id` | `uint64` | 进程 | 1 | 来源创建失败，返回空句柄 |
| `SubscriptionId` | `int64` | 每总线 | 1 | 订阅注册失败，返回空句柄 |

**四条硬规则**：

> - 发号器 MUST 在发号前拦截溢出，MUST NOT 依赖有符号溢出的行为。
> - 耗尽即**永久失效**：返回 `0`（唯一无效值），此后不再发号，MUST NOT 回绕复用。
> - MUST 在**任何状态修改之前**判耗尽——否则会先弹出一个槽位再失败，槽位永久泄漏。
> - **发号器是全局副作用，MUST NOT 假设它可重放**：将来引入预测回滚 / 确定性重放时，发号结果 MUST 进快照，或回滚区间内 MUST NOT 分配新号。

```cpp
// 发号原语：从 1 起、单调递增、耗尽后永久失效
template <typename TInt>
class TTcsIdCounter
{
public:
    // 返回 0 表示已耗尽；调用方 MUST 当失败处理
    TInt Allocate()
    {
        check(Next != 0);                                  // 开发期炸在发号点
        if (Next == 0) { return 0; }                       // Shipping 下也不回绕
        const TInt Id = Next;
        Next = (Id == std::numeric_limits<TInt>::max()) ? 0 : static_cast<TInt>(Id + 1);
        return Id;
    }

private:
    TInt Next = 1;
};
```

进程级的三家（`PoolId` / `EntityId` / `SourceHandle`）另出原子版本，语义相同；发号实现 MUST 出线（§1.3.4）。

## 1.3 来源句柄 `FTcsSourceHandle` ✅

### 1.3.1 形态

```cpp
// 非反射裸 struct：不进细节面板、不进资产
struct FTcsSourceHandle
{
    // 进程唯一、永不复用；0 = 无效
    uint64 Id = 0;

    // 框架内置来源的保留值（如派生属性自动挂载的修正器）。
    // 发号器从 1 递增，永不会分配到此值。
    static constexpr uint64 kBuiltinId = TNumericLimits<uint64>::Max();

    bool IsValid()   const { return Id != 0; }
    bool IsBuiltin() const { return Id == kBuiltinId; }

    static FTcsSourceHandle MakeBuiltin() { return FTcsSourceHandle{ kBuiltinId }; }

    friend bool operator==(const FTcsSourceHandle& A, const FTcsSourceHandle& B) { return A.Id == B.Id; }
};

// 发号器：出线实现（Allocate() 在 .cpp，计数器住该文件匿名 namespace）
// **与 kBuiltinId 无关**：它只发 1..∞ 的号，保留值是标记而非编号。
struct FTcsSourceHandleRegistry
{
    FTcsSourceHandle Allocate();   // 原子递增，从 1 起
};
```

| 属性 | 值 |
|---|---|
| 存储 | `uint64` |
| 分配 | 原子递增，出线实现 |
| 唯一性 | **进程唯一**、**永不复用** |
| 是否反射 | **否**（裸 `struct`，不进资产） |
| 保留值 | `kBuiltinId = UINT64_MAX`，只由 `MakeBuiltin()` 产生 |

> **宽度不同的原因**：`FTcsSourceHandle` 不进反射也不进蓝图，用 `uint64` 拿满量程；实体句柄与实例句柄要能被蓝图读写，而蓝图侧没有 `uint64` 引脚类型，MUST 用 `int64`。

> **Why Not 统一用 `uint64`**：UHT 认 `uint64` 作属性类型，但 `EdGraphSchema_K2` 只把 `FInt64Property` 映射成引脚，对 `FUInt64Property` 没有任何映射分支——蓝图用不了的句柄等于不许进蓝图。

### 1.3.2 归属：Instance，不是 Entity ✅

| # | 判据（一句话） |
|---|---|
| ① | 它只挂在实例上——「哪次施加产生了这批实例」 |
| ② | 定义侧 MUST NOT 有它：同一份定义，甲靠装备给、乙靠天赋给 ⇒ 来源因实例而异 |
| ③ | 它是生命周期概念而非身份概念：只回答「这批东西要一起撤」 |

### 1.3.3 一柄三角：施加方来源 / 撤销锚点 / 内置来源 ✅

| 角色 | 语义 | 用途 | 撤销时 |
|---|---|---|---|
| **施加方来源** | 谁施加的 | 续杯判据、叠层判据 | **MUST NOT** 当撤销锚点 |
| **撤销锚点** | 哪一次施加产生的 | 级联撤销 | 按它精确摘除 |
| **内置来源** | 框架自己挂的（如派生属性自动挂载的修正器） | 标识「这条不归任何外部施加者」 | **不可单独撤销**——只随实例销毁 |

> **Why Not 合并**：一个来源可施加多个不同定义，单号撤销会互相误摘。
> **内置来源是第三种角色，不是前两者的特例**：它既不回答「谁施加的」（没有施加者），也不参与级联撤销（它随实例生死）。所有内置来源共用 `kBuiltinId` ⇒ **MUST NOT** 依赖它做精准摘除。

### 1.3.4 进程唯一的实现纪律 ✅

**发号 MUST 出线**：`Allocate()` 定义在 `.cpp`，计数器住该文件的匿名 namespace。

> **判据**：内联变量在 MSVC 上不跨 DLL 合并 ⇒ 每个镜像各一份计数器、跨模块重号，且症状随构建配置漂移。

> 这条对**所有**「进程唯一发号」设施一律适用（实体句柄、`PoolId` 同理）。

### 1.3.5 设计克制 ✅

> **只做归属，不承载因果链。**

因果链由对象图天然边承载；来源句柄对来源的内容一无所知。

> **Why Not 承载因果**：一旦开始「顺便多记」，它会持续长大成内部小世界。

## 已裁定（速查）

| 项 | 结论 |
|---|---|
| 句柄形态 | **三段**：`PoolId` + `Index` + `InstanceId` |
| 句柄载体 | **每种一个独立 `USTRUCT`**，MUST NOT 用模板 |
| 身份 | **`(PoolId, InstanceId)` 进程唯一永不复用**；`InstanceId` 单独不全局唯一 |
| 占用判据 | **只有 `InstanceId == 0`**；MUST NOT 另设位图或奇偶位 |
| `InstanceId` 宽度 | **统一 `int64`**，MUST NOT 按池定宽 |
| 句柄 → 实例定位 | **领域义务**：域 MUST 给静态入口；基线不提供通用定位器，也不建 `PoolId → 池` 注册表 |
| `PoolId` | **每池实例一个**，由池**自领**（`AllocatePoolId()`），从 1 起、永不复用、销毁作废 |
| 池的复制 | **MUST NOT 复制或移动**——复制会让两个池共用一个 `PoolId` |
| 句柄门槛 | 跨边界引用 **且** 槽位复用，两条同时满足 |
| 池形态 | **稠密数组 + FreeList** |
| 池的两职责 | **必须分开**：槽位复用 / 身份发号 |
| 发号器 | **从 1 起、防溢出、耗尽永久失效**；MUST 在状态修改前判定；**不可重放** |
| 借用 | `Resolve` / `FindMutable` 的返回值 MUST 在下次 `Allocate` 前用完 |
| 遍历 | `ForEach` **锁定长度、只传句柄**；遍历中 `Free` 与 `Allocate` 均合法 |
| 可变访问 | **只有 `FindMutable(THandle)`**，不设 `ForEachMutable` |
| GC 追踪 | 池元素持强 `UObject` 引用时，拥有者 MUST 在 `AddReferencedObjects` 里追踪 |
| 来源句柄归属 | **Instance**（不归 Entity） |
| 来源 vs 锚点 | **两个号，不可合并** |
| 进程唯一发号 | **MUST 出线实现** |
| 设计克制 | **只做归属，不承载因果链** |
| 观测面 | **无参对**；应成体系提供 |
