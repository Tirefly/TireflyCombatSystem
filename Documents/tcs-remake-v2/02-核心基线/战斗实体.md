# 核心基线 · 战斗实体（Entity）

> **V2 五项核心基线之一**（Entity / Instance / Clock / EventBus / NumericAggregator）。回答：**谁**。
> 本文件全部已裁决，只写契约。

---

## 0. 边界

| 问题 | 归属 |
|---|---|
| 一个战斗实体叫什么（身份） | **本域** |
| 世界里有哪些实体、它在哪 | 宿主（经本域契约回答） |
| 它活着吗 / 能不能操作 / 系统就绪了吗 | 宿主与各领域 |
| 实体身上挂什么（属性 / 状态 / 技能） | 各领域 |

框架只定义两样东西：**一个身份句柄**、**一份查询契约**。实体本体归宿主。

## 1. 身份句柄 `FTcsCombatEntityHandle`

```cpp
// 独立 USTRUCT，MUST NOT 是模板
USTRUCT(BlueprintType)
struct FTcsCombatEntityHandle
{
    GENERATED_BODY()

    // 实体身份（单调递增、进程内永不复用；0 = 无效）
    UPROPERTY(BlueprintReadOnly, Category = "Combat Entity")
    int64 Id = 0;

    // 只答「曾被发号」，不答「现在还在」
    bool IsValid() const { return Id != 0; }

    friend bool operator==(const FTcsCombatEntityHandle& A, const FTcsCombatEntityHandle& B)
    {
        return A.Id == B.Id;
    }
};

// 发号器：进程唯一，出线实现（Allocate() 的实现在 .cpp，计数器住该文件匿名 namespace）
struct FTcsCombatEntityHandleRegistry
{
    // 进程内原子递增，从 1 起，永不复用
    FTcsCombatEntityHandle Allocate();
};
```

| 项 | 约定 |
|---|---|
| 形态 | 一个 `int64 Id`，**单段** |
| 载体 | **独立 `USTRUCT`**，MUST NOT 是模板 |
| Id 分配 | 单调递增、**永不复用**；从 1 起 |
| 无效值 | **只有 `0`**（默认构造即无效） |
| 判定 | `IsValid()` ⇔ `Id != 0`（只答「曾被发号」，不答「现在还在」） |
| 传递 | **一律按值**（含返回值、形参） |
| 反射 | `BlueprintType`：进事件载荷 / Def 引用 / 链上下文；不进资产 |

**段数由「会不会复用」决定**：槽位复用 ⇒ 需要「寻址 + 身份」两段（见 [运行时实例](运行时实例.md) §1.1）；Id 永不复用 ⇒ 只需身份一段。

**MUST NOT 用模板**：模板不可反射，会逼出「平展副本 + 转换函数」的胶水层；类型安全由「不同类型即不同 `USTRUCT`」保证，不需要模板。

**按值传递**：持有者注销后把自己那份置 `Id = 0` 即可本地拦住；改指针会让无效化时机失控。

**发号器**：独立、进程唯一、出线实现（`Allocate()` 在 `.cpp`，计数器住该文件匿名 namespace）。内联变量在 MSVC 上不跨 DLL 合并 ⇒ 重号，症状随构建配置漂移。

## 2. 目标有效性

框架**不提供**「这个实体还在吗」的查询。有效性只有一条答案来源：**施加口允许失败**。

### 2.1 延迟施加的三形态

| 形态 | 例 | 目标消失意味着 | 处置 |
|---|---|---|---|
| **A 延迟施加** | `WaitDelay(3s)` 后对旧目标施加 | 本次施加无法成立 | 施加**返回失败**，是正常回执（Log 不是 Warning） |
| **B 周期跳** | DoT 每 1 秒结算持有者 | 实例本应已随持有者消失 | 由**注销路径**保证，施加口不检查 |
| **C 投射物 / 引导** | 火球飞行后命中；引导每跳重选 | 本次未命中 | **目标在命中时刻确定**，不作发射时的输入 |

### 2.2 级联清理是硬保证

> **注销实体 MUST 级联清理其名下全部运行时实例。**

形态 B 由此**不需要任何目标有效性判定**：实例在持有者消失时一并消失，周期回调走不到「目标已消失」。反之，若周期实例仍存活，那是注销路径的缺陷。

### 2.3 施加失败只有一种读数

「目标已消失」「句柄从未存在」「存档损坏」在框架侧是**同一个结果**：施加失败。区分它们需要发号器保留历史，那是无界内存。

## 3. 查询契约 `ITcsEntityQuery`

```cpp
class ITcsEntityQuery
{
    // 遍历：稳定序，逐实体回调。不转移容器所有权
    virtual void EnumerateEntities(TFunctionRef<void(FTcsCombatEntityHandle)> Visitor) = 0;

    // 定位：取不到（实体未知 / 无位置概念）返回 false
    virtual bool GetLocation(FTcsCombatEntityHandle Entity, FVector& OutLocation) = 0;
};
```

契约只装**「宿主有、框架没有」**的事实：世界的成员名单、世界的空间分布。

**遍历契约**：① 顺序 MUST 有定义（稳定序）；② 用 Visitor 回调，不返回内部容器视图；③ 遍历期间不得增删实体，句柄只在本次遍历内保证有效。失效由注销路径处理，不混进遍历。

**它是 (a) 类依赖倒置缝**：核心不能反向依赖宿主，故不受「2 个实现者」限制（[01-定位与判据](../01-定位与判据.md) 铁律 2）。唯一的实现者是设计意图。

## 4. 存储形态判定规则

本节裁决**按什么判形态**，不裁决用什么形态——载体形态留给实现阶段。

### 4.1 两条互相独立的轴

| 轴 | 取值 | 由什么决定 |
|---|---|---|
| **本体形态** | 值类型 / `UObject` | 是否需要 GC 引用、资产反射实例化、蓝图派生 |
| **存储形态** | 行存 AoS / 列存 SoA | **该类型的字段是否全部定长** |

**战斗运行期数据默认值类型**。值类型 + 虚函数是合法组合；`USTRUCT` 同样可反射，反射需求不构成升格理由。

### 4.2 存储形态：按字段结构判定

| 字段构成 | 存储形态 |
|---|---|
| 全部定长标量（数值、句柄、枚举、定长时间戳） | **列存可选** |
| 含 `TArray` / `TMap` / `FString` | **必须行存** |
| 含虚函数（多态基类） | **必须行存**（虚表不可拆） |
| 含宿主自定义片段（`FInstancedStruct` 等） | **必须行存**（内层类型编译期未知） |

列存只在「按字段批量扫全体」时赢；**两种形态并存在同一系统里是常态**。

### 4.3 契约只收句柄、元素引用或 Visitor

跨域契约**不暴露容器**——一旦暴露，`TArray` 视图就把存储形态钉死，列存与行存无法互换。按字段批量回调（`Visitor(Handle, double Health)`）同样把字段名写进契约，慎用。

## 5. 载体形态

### 5.1 数量决定载体

**数量决定能不能用 `AActor`；「它是不是战斗实体」决定不了。** 同一款游戏内载体 MUST 按各实体自己的量级混合：

| 实体 | 数量级 | 载体 |
|---|---|---|
| 杂兵 / 召唤物 | 数十～数千 | 纯数据体（值类型 + 系统驱动） |
| 玩家 / Boss | 各 1 | `ACharacter` / `APawn` |
| 陨石 / 火焰区域 | 数十 | 纯数据体 |

⇒ 实体用什么载体是**每个实体各自的实现选择**，不是框架的裁决。

### 5.2 框架只持句柄

「句柄 → 载体」的映射由**宿主**维护：宿主自己的映射表，或依赖本框架的下游插件。框架永远只需要句柄——它不知道也无法知道背后是 `AActor`、`UObject` 还是纯数据结构体。

因此契约形参只出现句柄，`AActor*` / `UObject*` 不进入任何契约。

### 5.3 表现、反馈、位移、区域归宿主

| 需求 | 归属 |
|---|---|
| 表现播放（拖尾、光效） | 表现层（宿主） |
| 受击反馈（硬直、击飞、闪白、震屏） | 宿主，或依赖本框架的独立插件 |
| 位移与物理（挑空、击退、坠落） | 宿主 |
| 伤害区域（持续灼烧的火焰） | 效果域生成的区域实体 |

下游插件（例 `TcsHitReaction`）合法且鼓励——它看得见多类载体，而 TCS 结构上看不见。它也是 TCS 的验收标准：下游插件要伸手进 TCS 内部才能工作 ⇒ 对外面不够；下游插件能要求 TCS 加钩子 ⇒ 边界破了。

### 5.4 判定与动作由宿主提供

| | 框架做 | 宿主做 |
|---|---|---|
| 判定 | 调宿主给的谓词 `bool f(Handle)` | 提供实现（体型 / 阵营 / 类型… 都在宿主侧） |
| 动作 | 只按顺序调用 | 在自己的效果 / 行为里实现（挑空 / 击退 / 位移…） |

框架不认识「体型」这个词，也不需要——它只需要一个 `bool f(Handle)`。固定属性集会把宿主词汇绑进契约，且只能在「加维度」与「改维度」之间二选一。

## 6. 批处理后端

框架**不绑定任何一种**批处理后端（Mass / 自建 SoA / 普通数组），也不为运行期类型强制「可平凡拷贝」。

| 框架负责 | 宿主负责 |
|---|---|
| 定义类型与判定规则（§4） | 用不用 Mass、用在哪一层 |
| 契约不暴露容器（§4.3） | 在框架类型与 Mass 片段之间做投影 |

> **Why Not 强制全局可平凡拷贝**：那把「用不用 Mass」这个宿主选择变成了框架对所有类型的硬约束。
> **Why Not 选一个默认后端**：后端是宿主的实现选择，绑死任一个就把另一个排除。
> **Why Not 由框架做投影层**：投影需要知道 Mass 的片段类型，那是 Mass 的词汇。

Mass 的「可平凡拷贝」只作用于**进入 Mass 的那部分数据**，且它留了显式 opt-out 出口——它不构成框架的全局约束。

## 7. 边界清单

容易越界、被反复提议、但已裁决不进本域的能力：

| 不进本域 | 归属 |
|---|---|
| 存活查询 | 宿主本体论 |
| 可操作查询 | 依赖操作类型（眩晕禁施法但可掉血），per-entity 布尔语义残缺 |
| 各域系统就绪判据 | 各领域（问的是**系统**不是实体） |
| 增量枚举（本帧变化） | 不做——会把「帧」的时间观强加给非帧驱动宿主 |
| 范围枚举 | **TcsTargeting**（形状是目标选择的词汇） |
| 键值枚举（按队伍 / 类型剪枝） | 不做——队伍 / 类型是宿主词汇 |

范围查询用 `EnumerateEntities` + `GetLocation` 即可组合，**不需要改本契约**；若 O(n) 成瓶颈，宿主换一个带空间索引的实现，契约与调用方都不动。
