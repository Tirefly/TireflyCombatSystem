# 跨基线时序校验

> **本文件不是新机制，是一次检验**：把核心基线串成一条完整链路，看它们能不能拼起来。
> 任何一步拼不上，都是某一项基线的缺陷。

## 示例符号约定

本文件的示例跨了基线、领域与示意，三类符号必须分清：

| 类别 | 例子 | 性质 |
|---|---|---|
| **基线契约** | `Heap.Push` / `Cancel` / `AdvanceTo`、`TTcsInstancePool::Allocate` / `IsValid` / `Free`、`Bus->Publish` | 有正文定义，可依赖 |
| **他基线契约** | `ITcsEntityQuery::EnumerateEntities` / `GetLocation`、`EvaluateAggregatedValue` | 归对应基线文档，形态以那份为准 |
| **领域占位符号** | `SkillSubsystem`、`SkillPool`、`ChainInstancePool`、`ChainDomain::FindPool`、`BuffBucket`、`BuffDomain::FindPool`、`BuffDomain`、`ResumeChainInstance`、`OnBuffExpired`、`OnBuffPeriodic`、`Attr`、`Attr->BaseValue` / `CachedCurrent`、`CollectAggregateEntries`、`ApplyValueDomain`、`Query`、`Shape` / `Center` / `Scale`、`Event.Skill.Cast`、`FTcsSkillCastEvent` | **仅示意调用形状，不构成本文件的机制**；其字段、时刻与语义均由领域裁，本文件不作保证 |

> **示例 MUST NOT 被当作机制存在性的依据。** 示例里出现 `BuffDomain::BroadcastPeriodic`，不等于系统该有一个全局 `BuffDomain`——领域的真身由 Phase B 的领域文档裁。
> **句柄 → 实例的定位**是领域义务，见 [运行时实例](运行时实例.md) §1.1.6；基线不提供通用定位器。

## 场景

玩家对目标释放一个**施加减速 Buff 并造成持续伤害**的技能。

| 参数 | 值 |
|---|---|
| 技能 | 瞬发，无前摇 |
| Buff | 持续 5 秒，每 0.5 秒跳一次伤害，挂一条减速修正器 |
| 目标 | 由形状判定选出 |

---

## 总时间轴

| 时刻 | 步骤 | 由谁驱动 |
|---|---|---|
| `T0`（本帧） | T0 发起 · T1 建运行态 · T2.1 入堆 `WaitDelay 0.3s`（`DueTime = T0 + 0.3`） | 宿主调用栈 |
| `Now < T0+0.3` 期间 | 链**挂起**，不执行任何步骤 | — |
| 首个 `Now >= T0+0.3` 的推进帧（记作 `Now_due`） | T2.2 选目标 · T2.3 施加 Buff；Buff 的 5 秒与 0.5 秒**自当前 `Now_due` 起算**（离散帧步长下不回溯补差） | 到期回调（T5 的 `AdvanceTo`） |
| 此后每帧 | T5 泵三步 → 到期回调推进 Buff | World Tick 头部 |
| 实体销毁时 | T6 级联清理 | 销毁路径 |

> **T 编号是依赖顺序，不是时间顺序。** 只有上表钉住的时刻是基线契约；T3 / T4 落在哪一拍、`FTcsSkillCastEvent` 携带什么，都属领域，本文件不裁决，示例也不作保证。

## T0 · 宿主发起

```text
宿主 → SkillSubsystem.TryActivate({ Entity = 7 }, Skill.Fireball)
```

| 用到 | 基线 |
|---|---|
| `FTcsCombatEntityHandle{ Id = 7 }` | **Entity** |

技能域按实体句柄找到账本桶，再找到 `Skill.Fireball` 的条目。冷却真值住在**账本条目**上，不是到期堆。

> **Entity 只提供身份**：框架不知道实体 7 还在不在，也不知道它是否可施法。这些是技能域自己的门禁。

## T1 · 建运行态

```cpp
// 施法运行态
const FTcsSkillInstanceHandle Skill = SkillPool.Allocate();
//   → { PoolId = 41, Index = 0, InstanceId = 1 }

// 效果链运行态
const FTcsChainInstanceHandle Chain = ChainInstancePool.Allocate();
//   → { PoolId = 87, Index = 3, InstanceId = 12 }
```

| 用到 | 基线 |
|---|---|
| 两次 `Allocate()`，各自从**自己的池**发号 | **RuntimeInstance** |

`PoolId` 由池创建时领（进程唯一、永不复用），所以两个句柄即便 `Index` 相同也不会混淆。

## T2 · 链执行

**时刻**见「总时间轴」。以下三条规矩对整条链路成立：

> **等待步骤的恢复只发生在 `AdvanceTo` 内**，不存在「下一帧自动恢复」。
> **所有的「从何时起算」一律用当前 `Now`**——时钟是唯一时间来源，任何域 MUST NOT 用自己记的开始时间去算到期。
> **恢复前 MUST 先校验链句柄**（`战斗实体.md` §2.2）：否则会对着已失效的链跑后续步骤。

### T2.1 延迟步骤入堆

```cpp
// WaitDelay 0.3 秒：载荷由捕获自带，堆不携带载荷。只捕 Chain，this 不入捕获
FTcsChainInstance* ChainInstance = ChainDomain::FindPool(Chain.PoolId)->FindMutable(Chain);   // 领域按 PoolId 定位入口，见 运行时实例 §1.1.6

// 锚点写回链运行态——与 T2.3 的 Buff 锚点同形。不写回就撤不掉（统一时钟 §1.2.3）
ChainInstance->Anchors.Wait = Heap.Push(Now + 0.3, [Chain]()
{
	// 恢复前先校验：池可能已销毁，或链已被级联注销
	if (auto* Pool = ChainDomain::FindPool(Chain.PoolId))
	{
		if (FTcsChainInstance* ChainInstance = Pool->FindMutable(Chain)) { ResumeChainInstance(*ChainInstance); }
	}
});
```

| 用到 | 基线 |
|---|---|
| `Heap.Push(DueTime, TCallable&&)` | **Clock**（模板入口擦除前直接做内联预算 `static_assert`） |
| 只捕 `Chain`，`this` 不入捕获 | Clock 的捕获预算 |
| 返回值写回 `Anchors.Wait` | **Clock**（锚点归消费者） |

> **`this` 不进去**：`TFunction` 的内联尺寸不可作为设计前提（可覆盖、可关闭），见 [统一时钟](统一时钟.md) §1.2.5。
> **写法**：只捕 `Chain`，其余从它解析出的对象里读。捕获量由模板 `Push` 的 `static_assert` 守住。

### T2.2 选目标

> 以下两步发生在首个满足 `Now >= T0+0.3` 的推进帧内，由 T2.1 的到期回调驱动。此时 `Now` 为该帧推进后的时钟值 `Now_due`（离散帧步长下通常略大于 `T0+0.3`；后续相对时长一律从当前 `Now` 起算，不回溯补差）。

```cpp
TArray<FTcsCombatEntityHandle> Targets;   // 本次施法的目标集
Query->EnumerateEntities([&](FTcsCombatEntityHandle Candidate)
{
    FVector Location;
    if (Query->GetLocation(Candidate, Location) && Shape.IsInside(Center, Location, Scale))
    {
        Targets.Add(Candidate);
    }
});
```

| 用到 | 基线 |
|---|---|
| `EnumerateEntities` + `GetLocation` | **Entity**（唯一的两支） |

形状判定住 TcsTargeting，**不枚举世界、只判点**。

### T2.3 施加 Buff

```cpp
const FTcsBuffInstanceHandle Buff = BuffBucket.Allocate();
//   → { PoolId = 102, Index = 0, InstanceId = 1 }
FTcsBuffInstance* BuffInst = BuffDomain::FindPool(Buff.PoolId)->FindMutable(Buff);   // 领域按 PoolId 定位入口，见 运行时实例 §1.1.6

// 时段条目：5 秒后走完整移除链。只捕 Buff，this 不入捕获。锚点写回实例
BuffInst->Anchors.Expire = Heap.Push(Now + 5.0, [Buff]() { OnBuffExpired(Buff); });

// 周期条目：0.5 秒后跳一次，并重新入堆
BuffInst->Anchors.Periodic = Heap.Push(Now + 0.5, [Buff]() { OnBuffPeriodic(Buff); });
```

| 用到 | 基线 |
|---|---|
| `BuffBucket.Allocate()` | **RuntimeInstance** |
| 两个 `Heap.Push`，各只捕一个句柄 | **Clock** |
| 两次返回值写回 `Anchors` | **Clock**（锚点归消费者，T6 靠它撤销） |

> **`this` MUST NOT 进捕获**：每多捕一个东西就多一份越线风险，而越线不可见。回调走成员函数 + 从实例读上下文。

本示例假定属性侧在挂上减速修正器后结算并缓存结果。收集、缓存和更新时点属于属性侧，不是聚合器的保证。

## T4 · 广播

```cpp
// Payload 栈上构造，只在本次派发期间有效
FTcsSkillCastEvent Payload{ .Caster = Entity, .SkillTag = Skill.Fireball };
```

| 用到 | 基线 |
|---|---|

## T5 · 时钟推进（下一帧起）

```text
World Tick 头部 → 泵三步：

  ① 取步长
  ② 时钟推进
  ③ 到期堆 AdvanceTo(Now)
```

> **泵里不冲洗事件**：总线同步派发、不建帧末通道（`事件总线.md` §1.2），帧边界没有待冲刷对象。

`AdvanceTo` 的内容：

```text
① 换出：全部到期条目进临时列表，槽位标记为「已换出」，暂不归还
② 逐条出队，每条先看是否仍有效：
   · 已被 Cancel → 跳过，归还槽位（不回调）
   · 仍有效 → 回调，回调结束后归还槽位
        · 周期条目 → BuffBucket.IsValid(Buff) 命中 → 广播 Periodic
                     → 广播可能引发级联注销，故【广播后重新校验】
                     → 仍有效 → 重入堆并覆写 Anchors.Periodic
                     → 已失效 → 不再入堆
        · 时段条目 → BuffBucket.IsValid(Buff) 命中 → 完整移除链：
              撤修正器 → 属性立即重算 → 广播 Removed → Free(Buff)（InstanceId 置 0）
```

> **同拍/同刻次序**：堆序键 `(DueTime, SlotId)`，同一拍内先到期的先回调，仅 `DueTime` 严格相等时按入堆先后回调（`统一时钟.md` §1.2.2）。
> **槽位归还时机**：`Taken` 态的槽位推迟到离开临时列表且回调返回（或已取消跳过）后才归还，所以回调里重新入堆**拿不到**待回调或在途回调的槽位（`统一时钟.md` §1.2.3 E1）。

| 用到 | 基线 |
|---|---|
| 泵序不可换 | **Clock** |
| 到期回调里 `IsValid(Buff)` / `Free(Buff)` | **RuntimeInstance**（`TTcsInstancePool` 的两个成员） |

> **「查不到怎么办」是 Buff 域的业务**——堆不给任何统一信号。

#### 在途回调与级联注销

`AdvanceTo` 的回调执行期间，级联注销可能由回调自己触发：

```text
回调 Buff A 的周期条目
  └─ 广播 Periodic
       └─ 监听者结算伤害 → 宿主实体死亡 → 注销
            └─ 级联清理 Free(A) → InstanceIds[A.Index] = 0
  ← 回调继续执行，仍用广播之前取到的 TInstance*
```

`Free` 不销毁实例本体，所以此时读到的仍是「失效但有效」的旧数据。**真正的危险是槽位在同一个回调链里被 `Allocate` 复用**——那一刻读到的会变成另一个实例的数据，不崩、不报错。

⇒ 契约见 `战斗实体.md` §2.2：在途回调 MUST 在可能引发级联注销的操作之后重新校验句柄。

## T6 · 实体注销

```text
实体销毁 → 级联清理（MUST NOT 在 Free 后再解引用实例读锚点）：
  ① 清理该实体名下的 Buff / Skill 实例与链运行态：
     对每个实例先读取（快照）其持有的锚点组（Anchors.*），再执行 Free(Handle) 使实例立即逻辑失效
     （或先按锚点 Cancel 再 Free；若 Free 在前，MUST 凭提前保存的锚点快照取消，不得在 Free 后再访问槽位）
  ② 按锚点快照逐条取消到期条目：
       Cancel(Anchors.Expire) / Cancel(Anchors.Periodic) / Cancel(Anchors.Wait)
  ③ 桶销毁，其 PoolId 作废（永不复用）
```

> **「Cancel 该实体的全部条目」不是堆的能力**：`Cancel` 只收**单个 `FTcsExpiryHandle`**。实体→到期条目的映射由**领域**持有（实例内记锚点），堆不知道谁是实体。
> **Why Not 让堆支持按实体批量取消**：那会把实体这个概念塞进堆的接口，违反 [统一时钟](统一时钟.md) §1.2.4「接口里 MUST NOT 出现任何业务类型」。
> **重复 `Cancel` 是正常路径**：同一锚点可能被多条清理路径各取消一次，堆对陈旧句柄无操作、不报错（`统一时钟.md` §1.2.3）。
> **陈旧锚点也是正常路径**：周期条目每拍重入堆都覆写 `Anchors.Periodic`，而该条目出队时旧锚点已经失效——`Cancel` 它同样是 no-op。

| 用到 | 基线 |
|---|---|
| 「实体消失 ⇒ 实例跟着消失」 | **Entity + RuntimeInstance** 的硬保证 |

## 检验结果

### 通过的部分

| 环节 | 结论 |
|---|---|
| Entity → RuntimeInstance | 句柄可作桶键；`PoolId` 让跨桶不撞 |
| RuntimeInstance → Clock | `Heap.Push` 捕获句柄即可，堆无需认识类型 |
| Clock → RuntimeInstance | 到期回调经**领域按 `Handle.PoolId` 定位入口**找到目标池并做 `Pool->IsValid(Handle)` 自校验（`运行时实例.md` §1.1.6；回调不持有池指针、不假设全进程单池） |
| RuntimeInstance → NumericAggregator | 修正器摊平成条目，**句柄取 `.Id` 填 `OrderSeq`**（句柄本身留在域侧） |
| 全链 → EventBus | 每个阶段边界都有对应事件，载荷是受控借用 |
| 注销闭合 | 实体注销级联清理到期条目与实例 |

### 已核对的三个边界

#### 问题 1：`TFunction` 的内联尺寸不可作为设计前提

| 不可依赖的理由 | 来源 |
|---|---|
| 尺寸可被 `#define` 覆盖 | `CoreDefines.h:46`（`#ifndef` 保护） |
| 内联存储可整体关闭 | `Function.h:25`（未定义或 `0` ⇒ 全堆分配） |
| 判的是 `sizeof(OwnedObj)`，含 vptr | `Function.h:223` + `Function.h:73` |

⇒ **结论：不记录「捕获上限是 N 字节」，而是把编译期断言直接放在唯一公开模板 `Push` 上（不提供可绕过的擦除版 `Push` 或外置工厂）。**

应对：**只捕获实例句柄，实体从实例里读**（实例本身持 `Entity` 字段）；`this` 不入捕获。

> **已裁**：回调**只捕获实例句柄**，实体从实例里读。领域文档实现时按此写，MUST NOT 另设载荷通道。

#### 问题 2：`FTcsSourceHandle` 从哪来，链路里没有交代

T2.3 挂修正器时需要 `Source`（域侧用它作撤销锚点 + UI 归因），但**链路里没有一步产生它**。

| 归属 | 状态 |
|---|---|
| 谁发 `Source` | 施加方（Buff 域） |
| 何时发 | 施加时 |
| 链路里未出现的原因 | 它属于领域内部，不是基线间的接口 |
| **聚合器需要它吗** | **不需要**——只接 `Source.Id` 作为 `OrderSeq`（《数值聚合器》§3.2） |

> **已裁**：这不是缺口，是基线的正确边界。领域的施加路径 MUST 自己发 `Source`，且发放责任落在**状态与修正域**。

> **2026-11-11 补充**：聚合器不再持有 `FTcsSourceHandle`，条目上只有 `uint64 OrderSeq`。所以这条问题现在更清楚——`Source` **完全是领域的事**，基线之间根本不传它。

#### 问题 3：`EnumerateEntities` 与 `GetLocation` 的两次查找

T2.2 的选目标对每个实体调一次 `EnumerateEntities` 回调 + **一次 `GetLocation`**。

| 规模 | 代价 |
|---|---|
| 5000 实体 | 5000 次虚函数调用 + 5000 次定位 |

⇒ **该成本是契约的固有成本，实现侧优化不掉**：`EnumerateEntities` 没有范围参数，带空间索引的宿主实现同样要访问全部实体。要剪枝只能由消费者自建空间结构（归 `TcsTargeting`），或另立带范围的契约——两者都不在本契约内。

> **已裁**：本契约不承诺透明加速。千级实体下的实际代价见族外 `未决-核心基线.md` §4，与总线路由一起压测。**重开条件**：压测确认该路径成为瓶颈时，才决定给本契约加范围查询，或由消费者自建索引。

---

## 结论

**核心基线的接口契约在静态拼装推演上可以闭合。** 三步接口衔接（Entity→RuntimeInstance→Clock→RuntimeInstance）契约彼此匹配；本结论仅代表文档级静态契约推演，不等同于代码实现、编译或运行期性能验收。

**三个已核对的边界**（都不是缺陷）：

| # | 边界 | 结论 |
|---|---|---|
| 1 | 到期回调的捕获预算 | 唯一模板 `Push` 在擦除前以 `static_assert` 守住不退化堆分配（惯例只捕单个实例句柄），不记录字节数 |
| 2 | `Source` 发号责任 | 落状态与修正域，施加路径自记；交给聚合器时只填 `.Id`（《数值聚合器》§3.2） |
| 3 | 遍历 + 定位的千级实体成本 | 「每实体一次虚调用」是当前无范围参数契约的固有成本，实现侧无法透明剪枝；千级实体代价待压测，必要时由消费者自建空间索引或另立带范围的契约 |
