# 核心基线 · 统一时钟（Clock）

> **定位**：V2 核心基线之一（Entity / Instance / Clock / EventBus / NumericAggregator / GameplayTag）。
> **回答什么问题**：**什么时候**。

**图例**：✅ 已裁决 ｜ ⚠️ 待审 ｜ ❓ 待调研

> **本文件只写最终设计与已裁决的架构。** 不写历史实现；Why Not 一律一句话。

## 1.1 战斗时钟与泵 ✅

### 1.1.1 形态

| 项 | 设计 |
|---|---|
| 时间表示 | 一个 `FTcsClock` 值类型，由系统持有 |
| 取时入口 | **唯一**。代码 MUST NOT 直接取 wall-clock |
| 泵点 | World Tick 的**头部**（`OnWorldTickStart`）——`LevelTick.cpp:1522` 广播它，`:1821` 才 `TickObjects`，故确实先于当帧业务逻辑 |

> **Why Not 尾部**：Tickable 自 tick 在尾部，太晚——到期必须在当帧业务逻辑之前完成。

### 1.1.2 泵的三步序 ✅

```text
① 取步长
② 时钟推进
③ 到期堆 AdvanceTo
```

**顺序不可调换**：

| 约束 | 理由 |
|---|---|
| 时钟必须先推进 | 否则到期没有时间基准 |

> **泵里没有「事件派发冲洗」这一步。** 总线是同步派发（[事件总线](事件总线.md) §1.2「帧末派发通道：**不建**」）：`Publish` 在返回前已送达，帧边界上**没有任何待冲刷的对象**。在这里放一步空调用不产生任何行为，只是每帧一次空转。
> **重开条件**：将来若真有域需要「帧末延迟工作」，由**该域带来消费者与分级依据**并单独裁决，而不是在泵里预留空钩子。
> **这不是「帧末」被整体否掉**：属性域的安全点与表现层的同帧合并都归各自域、不经总线，见 [事件总线](事件总线.md) §1.2.5。

### 1.1.3 不设 per-component tick ✅

> 周期行为全部由**到期堆 + 事件总线**驱动，MUST NOT 引入「每帧遍历所有实体/组件调 Tick」这一层。

**Why Not**：千级实体下逐组件 tick 是「每帧 N 次虚调用」，随实体数线性增长；而无 per-component tick 的帧成本 = **到期项数**。

### 1.1.4 时间源不设接口 ✅

> **不提供可注入的时间源抽象，直接给具体实现。**

**判据**（[01-定位与判据](../01-定位与判据.md) 铁律 2）：它是**策略插槽**不是倒置缝——没有任何宿主需要「换一种时间轴」，零替代实现 ⇒ 不建接口。

**暂停 / 缩放**属于 `FTcsClock` 的字段语义，**不构成**建时间源接口的理由。

## 1.2 到期堆 `FTcsExpiryHeap` ✅

### 1.2.1 形态

**最小堆 + 池化条目 + 惰性取消**——取消即时失效，堆内残留条目出队时凭失效句柄跳过（「惰性」指堆里的节点，不指取消本身）。

```cpp
// 取消锚点（不含任何业务类型）：寻址段 + 身份段，与实例句柄同风格
struct FTcsExpiryHandle
{
    int32 Index  = -1;     // 寻址：堆内哪个槽位
    int64 SlotId = 0;      // 身份：单调递增、永不复用；0 = 无效

    bool IsValid() const { return SlotId != 0; }
};

class FTcsExpiryHeap
{
public:
    // 入堆：只登记「什么时候」与「到点做什么」。载荷由 OnDue 的捕获自带。
    // 注册口 MUST 经 MakeExpiryTask 构造——断言只能在擦除前做，见 §1.2.5
    // 堆序键 = (DueTime, SlotId)：同一时刻按入堆先后回调，见 §1.2.2
    FTcsExpiryHandle Push(double DueTime, TFunction<void()> OnDue);

    // 取消：令条目失效，生效后保证不再回调（含已换出未回调的条目），见 §1.2.3
    void Cancel(FTcsExpiryHandle Handle);

    // 推进：先换出全部到期条目，再逐条回调。MUST NOT 重入
    void AdvanceTo(double Now);
};
```

**接口里 MUST NOT 出现任何业务类型**：没有实体句柄、没有实例句柄、没有裸数字 ID。

### 1.2.2 核心纪律：先换出，再回调 ✅

```text
AdvanceTo(Now)：
    把到期的条目全部从堆里【换出】到临时列表
    再逐条回调
```

| Why Not 边遍历边回调 | 后果 |
|---|---|
| 成本无界 | 一次 `AdvanceTo` 被自激拉长 |
| 结果依赖实现 | 到期顺序变成「取决于新条目什么时候被插进来」 |

> **两条都要留**：它们不是同一条理由的复述——**成本**是性能后果，**结果依赖实现**是可复现性后果，各自独立成立，且后者违反「确定性、可回放」（[01-定位与判据](../01-定位与判据.md) §1）。按 §5.4，「各自独立成立的多条致命理由」不算罗列。

**`AdvanceTo` 是等待类回调的唯一恢复点。** 链、序列、任何「过一会儿再做」的步骤，都只能由到期回调在本函数里恢复，MUST NOT 另立「下一帧自动恢复」的通道。

> **起点一律用当前的 `Now`**：任何域 MUST NOT 用自己记下的开始时间去算到期。

**堆序键 = `(DueTime, SlotId)`。** `SlotId` 单调递增、永不复用，**它自己就是入堆顺序** ⇒ 相同时刻的条目按入堆先后回调，不需要额外的序号字段。

> **为什么必须定同刻次序**：最小堆对相等的 `DueTime` 没有稳定顺序。留白会让回放对不上——[01-定位与判据](../01-定位与判据.md) 把 LAC 定为「**确定性、可回放**」的基准消费者。

> **回调中新建的条目归下一拍**——帧成本有界。**归哪一拍**与插入时序无关；**同一拍内**按入堆先后。

### 1.2.3 槽位态与取消窗口 ✅

**槽位三态**：

| 态 | 含义 | `Cancel` 效果 |
|---|---|---|
| `Free` | 空闲，可分配 | 不命中（`SlotId` 已失配） |
| `Armed` | 在堆内，等待到期 | 置失效，**立即归还** |
| `Taken` | 已换出，在本次临时列表里 | 置失效，**归还推迟到它离开临时列表** |

> **E1（承重不变量）**：槽位归还的唯一前提是**没有任何容器再可能访问它的 `Index`**——堆内残留已按 `SlotId` 失配、临时列表已走过。
> 这条同时封死「回调里 `Push` 复用待回调槽位」：`Taken` 尚未归还 ⇒ free list 里没有它。

**取消窗口**：`Cancel` 生效后**保证不再回调**，含已换出、尚未回调的条目。

| Why Not 让「已到期」压过 `Cancel` | 后果 |
|---|---|
| 窗口边界由实现细节决定 | 语义随换出批次大小漂移，消费者写不出稳定逻辑 |

> **`Cancel` 的全部意义就是「别让它发生」。** 惰性取消的自然读法是：有效期内一定回调，失效后一定不回调。

**三种输入**：

| 输入 | 处理 |
|---|---|
| `SlotId == 0` | 无操作 |
| `Index` 越界，或 `Slots[Index].SlotId != Handle.SlotId` | 无操作（陈旧句柄） |
| 命中 | 按三态表处理 |

> **无效句柄 MUST NOT 触发断言或报错**：级联清理里重复 `Cancel` 是正常路径（`00-跨基线时序.md` T6）。

**锚点归消费者所有**：`Push` 的返回值 MUST 被调用方保存。

| 规矩 | 理由 |
|---|---|
| 堆不记「谁提交了哪条」 | 记了等于把归属塞进堆，正是 §1.2.4 三条 MUST NOT ② 禁止的东西 |
| `Cancel` 是唯一撤销入口 | **不保存锚点 = 永远撤不掉**，条目只能到点空转一次 |
| 重入堆 MUST 覆写同一锚点槽位 | 旧锚点已随条目出队失效，`Cancel` 它是 no-op，覆写安全 |
| 一个实例可有多条条目 | 锚点是一组，槽位形态由领域定，基线不设上限 |

> **回调里重入堆之前 MUST 先校验句柄有效**（`战斗实体.md` §2.2）：否则会造出无人取消的孤儿条目。

**`AdvanceTo` MUST NOT 重入。** 临时列表是单个成员缓冲区，回调里再次调用会覆写它，并让「回调中新建的条目归下一拍」失效。实现 MUST 用运行期断言拦下。

### 1.2.4 载荷由回调捕获自带 ✅

> **到期堆 MUST NOT 携带任何载荷，也 MUST NOT 告诉回调「是谁到期了」。** 回调通过捕获自带上文。

```cpp
// 消费者侧写法：只捕自己的句柄，其余从池里读
const FTcsBuffInstanceHandle Handle = Instance->Handle;
Heap.Push(DueTime, MakeExpiryTask([Handle]()
{
    // 查不到怎么办是消费者自己的业务，堆不代劳
    // BuffPool() 是【领域静态入口】，见「运行时实例」§1.1.6 的领域义务
    if (BuffPool().IsValid(Handle)) { BuffDomain::BroadcastPeriodic(Handle); }
}));
```

> **示例符号**：`BuffPool()` / `BuffDomain` 是**领域占位符号**，只示意调用形状，不构成本文档的机制（约定见 `00-跨基线时序.md` 的「示例符号约定」）。

> **`this` 不入捕获**：`[this, Handle]` 就是两个捕获物，已越过 §1.2.5 的预算。回调里用不上 `this`——池由**领域的静态入口**按句柄定位（`运行时实例.md` §1.1.6 的领域义务），不依赖回调自己的成员。

| # | 判据（一句话） |
|---|---|
| ① | 到期时要做的事完全由消费者决定，而它要的正好是它自己的句柄 |
| ② | 回调本来就知道自己是谁——堆再「告诉」一遍是多余的信息通道 |
| ③ | 通用载荷必然退化成裸数字或裸字节，等于把问题原封不动换了个类型 |

**三条 MUST NOT**：

| # | 条文 |
|---|---|
| ① | 堆的接口 MUST NOT 出现任何业务类型（句柄、ID、枚举） |
| ② | 条目 MUST NOT 持有 OwnerId 一类「归属」字段 |
| ③ | 堆 MUST NOT 为「查不到」提供任何统一信号 |

### 1.2.5 捕获预算 ✅

> **到期回调 MUST NOT 捕获超过一个句柄。** 需要更多上下文时，从那个句柄解析出的对象里读。

**这个预算恰好卡在默认配置的内联容量上，不是保守估计**：

| 捕获 | 捕获物字节 | `OwnedObject`（+8 虚表指针） | 对比默认 24 字节缓冲 |
|---|---|---|---|
| `[Handle]`（`int32` + `int32` + `int64`） | 16 | 24 | **恰好内联** ✓ |
| `[this, Handle]` | 24 | 32 | **走堆** ✗ |

> **为什么偏偏是「一个句柄」**：不是拍的。多捕一个 8 字节指针就越线，而越线不可见。

> **`TFunction` 的内联尺寸 MUST NOT 被当作设计前提。**

| 为什么不能依赖它 | 来源 |
|---|---|
| 尺寸是 `#ifndef` 可覆盖的 | `CoreDefines.h:46`（默认 24，见 `CoreDefines.h:47`） |
| 内联存储可能整体关闭（全部转堆分配） | `Function.h:25-31`：未定义或为 0 ⇒ `TFUNCTION_USES_INLINE_STORAGE = 0`，此时 `TFUNCTION_INLINE_SIZE` **也不定义** |
| 承载捕获物的是带虚析构的基类子对象 | `Function.h:73` + `Function.h:223`：判据是 `sizeof(OwnedObj)`，含 vptr |

⇒ **MUST 用编译期断言守住，MUST NOT 记录「上限是 N 字节」。**

**断言只能落在构造点。** `Push(double, TFunction<void()>)` 的形参里没有原始捕获类型的任何痕迹，函数体内无对象可断言 ⇒ 注册口收**工厂**，工厂在擦除前拿到 `std::decay_t<TCallable>`。与总线的 `MakeSink` 同形态。

```cpp
// 判据由实现自身的常量导出，不写外部字面量。与引擎自己的判据逐字同构（Function.h:223）
template <typename TCallable>
TFunction<void()> MakeExpiryTask(TCallable&& Callable)
{
    // 与 TFunction 内部一致地取 decay：Function.h:215 用 std::decay_t<FunctorType>
    // 不 decay 就会量到引用类型，断言失效
    using TDecayed = std::decay_t<TCallable>;

    // TFUNCTION_USES_INLINE_STORAGE 两个分支都定义，可无条件断言
    static_assert(TFUNCTION_USES_INLINE_STORAGE != 0,
        "TCS 要求开启 TFunction 内联存储（NUM_TFUNCTION_INLINE_BYTES > 0）");

#if TFUNCTION_USES_INLINE_STORAGE
    // 量的是「被放进缓冲区的那个对象」，不是「装缓冲区的 TFunction」——后者恒大于真实预算
    static_assert(
        sizeof(UE::Core::Private::Function::TFunction_OwnedObject<TDecayed, false, false>) <= TFUNCTION_INLINE_SIZE,
        "到期回调的捕获物会退化成堆分配");

    // 防御性：缓冲只保证 16 字节对齐，而引擎判据只看尺寸不看对齐
    static_assert(
        alignof(UE::Core::Private::Function::TFunction_OwnedObject<TDecayed, false, false>) <= TFUNCTION_INLINE_ALIGNMENT,
        "捕获物对齐超过内联缓冲");
#endif

    return TFunction<void()>(Forward<TCallable>(Callable));
}
```

| 断言 | 挡什么 |
|---|---|
| `TFUNCTION_USES_INLINE_STORAGE != 0` | 整个配置把内联存储关了——此时连一个句柄都要走堆，前提已失效 |
| `sizeof(OwnedObject) <= TFUNCTION_INLINE_SIZE` | 捕获物超预算 ⇒ 引擎静默转堆分配 |
| `alignof(OwnedObject) <= TFUNCTION_INLINE_ALIGNMENT` | 捕获物对齐超过缓冲 |

> **MUST NOT 改用 `sizeof(TCapture) <= sizeof(TFunction<void()>)` 这类「结构性上界」。** 那是 `TFunction` 的整个外壳尺寸（24 字节缓冲**再加** 8 字节堆指针），恒大于真实预算，会**放行**真正走堆的捕获物——失败模式是静默，比编不过更坏。

> **依赖说明**：`TFunction_OwnedObject` 住在 `UE::Core::Private::Function`（`Function.h:36`），类型在公共头里有完整定义，`sizeof` 从外部可用；但它**不是稳定性契约**。
> **重开条件**：该类型若在后续引擎版本不可用，回族外台账重新裁决，MUST NOT 自行降级为结构性上界。

⇒ **正确写法是捕获句柄、从对象里读其余字段**（实例本身持 `Entity` / `Source` 等归属），而不是把需要的字段一起捕进来。

> **Why Not 只写成建议**：这个分配**不可见**——无编译错误、无日志、无计数器，只能靠抓分配栈事后定位。
> **不包 `static_assert` 的注册口就是缺陷。**

### 1.2.6 已知边界 ✅

> **「帧对齐」与「动作取消窗口」是到期堆表达不了的。** 这是 V2 必须承认的边界。

动作游戏需要**与动画通知对齐的时刻**与**取消窗口**（动作语义：某段动画窗口内可打断），绝对时刻到期不足以表达；该能力归属行为域，不是时钟域的扩展点。

> **术语区分**：本节的「取消窗口」指**动作语义**；§1.2.3 的「取消窗口」指**到期条目的取消时机**。两者无关，MUST NOT 混用。

## 已裁定（速查）

| 项 | 结论 |
|---|---|
| 唯一取时入口 | **是**，禁 wall-clock |
| 泵点 | **World Tick 头部** |
| 泵序 | **取步长 → 推进 → 到期**，不可换；帧边界没有可冲洗对象 |
| per-component tick | **不设** |
| 时间源接口 | **不建**（策略插槽，零替代实现） |
| 到期纪律 | **先换出，再回调**；回调中新建的条目归下一拍 |
| 同刻次序 | **按入堆先后**——堆序键 `(DueTime, SlotId)`；`SlotId` 单调递增即入堆顺序，零额外字段 |
| 取消窗口 | **生效后一定不回调**，含已换出未回调的条目；槽位按三态归还（E1） |
| 无效句柄 | **无操作**，MUST NOT 断言或报错（重复 `Cancel` 是正常路径） |
| 重入 | **`AdvanceTo` MUST NOT 重入**，运行期断言拦下 |
| 锚点归属 | **归消费者**——`Push` 返回值 MUST 保存；重入堆 MUST 覆写同一槽位；不保存就撤不掉 |
| 到期堆载荷 | **不携带任何载荷**；回调通过 `TFunction` 捕获自带上文 |
| 归属字段 | **删除**（`OwnerId` 一类字段 MUST NOT 存在） |
| 「查不到」信号 | **不提供**——属消费者业务 |
| 捕获预算 | **一个句柄**；判据 MUST 由实现常量导出并写成 `static_assert`，MUST NOT 记录「上限 N 字节」——`TFunction` 内联尺寸可覆盖、可关闭 |
| 断言落点 | **工厂 `MakeExpiryTask`**（擦除前），量的是 `OwnedObject` 而非 `TFunction` 外壳；结构性上界 MUST NOT 使用 |
| 到期堆的表达边界 | **帧对齐与动作取消窗口表达不了**，归行为域 |
