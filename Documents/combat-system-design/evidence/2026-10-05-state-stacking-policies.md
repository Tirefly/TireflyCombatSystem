## 4. 本轮装置与验收记录（1 处实现缺陷 + 1 处非本轮文案偏差）

### 4.1 实现缺陷：`ScheduleTime` 的"刷新恒回满额"

- **现象**：写 22l（不动时长档）前读实现才发现——`ScheduleTime` 在刷新路径上**无条件**用 `EvaluateTotalDuration` 覆写 `DurationRemaining`，即 `EStackDurationPolicy::ESD_None` 这一档**在实现上从未存在**（Task 3 落 `ScheduleTime` 时该轴还是"只落形状"）。
- **判据**：这是**实现缺陷**而非"计划没写"——规格 §3.2/§3.3 明写该轴两档语义，且计划 Step 3 要求"按 `StackDurationPolicy` 决定剩余时长"。
- **修法**：在时间重挂点读轴——`ESD_None` ⇒ **不覆写** `DurationRemaining`（`PushExpiry` 按字段值排到期时刻 ⇒ 天然"保留剩余"）；`ESD_RefreshRemainingToTotal` / 首挂 ⇒ 回满额。
- **验证**：22k / 22l 两档读数可分（8.000 vs 3.000）✓。

### 4.2 非本轮引入的文案偏差（如实登记，未改）

- **现象**：拒绝面检查 I 的内联文案写"预期 2 条 Warning"，实测该检查只产生 **1 条**（`时长操作被拒：定义未在本世界登记`，L3420）。
- **为什么不改**：该文案属"进日志的字符串"，改了就必须重编重跑整轮；而它**不是验收锚点**（装置头部的状态面总数 9 与实测一致 ✓）。故**保持原样**、登记台账，交 Task 8 的收口对账一趟处理。
- **判据**：Task 4 的重跑纪律针对的是**头部文案**（验收锚点）；把非锚点的逐检查注记也拖进重跑，会让"重跑"从纪律退化成仪式。

### 4.3 一处实施期设计发现（已改装置与规格）

**`EGB_PerTag` 与 `GroupTag` 裁撤**：组键基座**必须含 `DefTag`**（一条实例 = 一个定义的数据），而分组词取自定义自身 ⇒ 同一 `DefTag` 内恒定 ⇒ 该档与 `None` 完全同义。它唯一有意义的读法（"不同定义共享一个组、层数上限跨定义累计"）要求**组内允许多条实例**——那是"层 = 独立实例"的另一套模型，本轮明确不采用。⇒ 裁撤该档与字段，登记台账 `STAT-7`，并同步修订提案 / 规格 delta / 装置检查清单（**用户当场拍板**）。

## 5. 如实边界（MUST NOT 外推）

1. **`EVS_PerStackValue` 零行为**（台账 `STAT-6`）：本轮它只落枚举值与注释，行为与 `KeepMax` 一致——装置**未覆盖其行为面**（因为实现上确实没有）。
2. **"跨定义共享层数组"不可表达**（台账 `STAT-7`）：`PerTag` 档已裁撤；要它就得改层模型。
3. **逐层来源归属不可表达**（台账 `STAT-8`）：叠层路径只保留实例的**首个来源**为级联锚点（`Source` 不动是 Task 4 的纪律），新来源只参与"续杯 / 叠层"判定 ⇒ "按来源只摘某一层 / 按来源退一层"今天做不到。
4. **legacy `NoMerge` 只能近似**：`None + ∞` 得到的是"一条实例、层数累加、默认轴下数值与时长都不变"；真正"每次独立成实例"要用 Custom 决策 Fragment（本轮样本即此用法）。
5. **`GroupBy = PerSource` 下 `Stacked` 不可达**：同组必然同来源 ⇒ 该组合只能 `Applied` / `Refreshed`（`MaxStacks` 在该组合下无实际约束力）。这是模型推论，不是缺陷。
6. **Custom Fragment 只验了 `IsSameGroup`**：`ShouldAccept` 的拒绝路径与 `ResolveStacks` 的层数接管**均未实测**（样本只覆写了一个方法）。三者的中性默认行为与虚分派结构由编译与内建路径间接覆盖，但"宿主覆写后接口真的按预期分派"只对 `IsSameGroup` 有证据。
7. **`OPK_AttributeScaled` 的 `AddValues` 缩放未验**：物化边界对两种操作数都做了按层成倍（字面量乘值、换算乘系数），但本轮装置只用字面量模板 ⇒ 换算形态的那一行是**代码已写、行为未验**。
8. **替换路径的重入未压测**：`Replace` 先走完整移除链（会广播 `Removed`）再建新条，代码按 Task 4 的重入纪律写了"重取桶"的守卫，但**没有**"订阅者在 `Removed` 回调里注销单位"这类极端夹具。
9. **时长两档用 `SetRemaining` 压缩剩余构造**（§1.5 已说明），**不是**真等时钟走完 5 秒——`ExtendDuration` / `SetRemaining` 与到期堆的交互本身归 Task 3 的证据。
10. **组键只用单单位验证**：全部读数来自**一个**被施加方的桶（另一单位只当第二个发起者）；"跨单位不互相影响"由基座含 `Unit` 的代码保证，未做跨单位同时施压的对照。
11. **单机单世界单 PIE 会话**：全部为编辑器内 PIE、单进程；无网络、无多世界、无 Shipping 运行期验证（Shipping 只验编译）。
12. **检查 I 的内联文案偏差**（§4.2）：非本轮引入、非验收锚点、保持原样登记。

## 6. 引擎与机制事实（供后续轮）

1. **裸 `FInstancedStruct` + 手写 `meta = (BaseStruct = "/Script/<模块>.<类型>")` 能过 UHT 与编译器**（本轮实证）：策略逃逸位不需要 `TInstancedStruct<T>`——后者的脚本层空壳问题（2026-09-24 换型）在"宿主策略"这个场景下同样致命（宿主侧 C# 要能挂策略）。
2. **"解析一次"是配置错误 Warning 的计数纪律**：把"找成员"与"出决策"拆成两次调用，会让**同一次施加**刷出 2 条重复 Warning（每处各解析一次载荷）。⇒ 凡"解析失败要留红字"的载荷，**一次流程只解析一次**（本轮把两者合成单一入口 `ResolveStackDecision(Request, Bucket, Policy)`）。
3. **`ScheduleTime` 类的"重挂点"是轴的必读处**：任何"刷新对 X 的作用"的轴，都必须在**重挂 X 的那一处**读——在别处补语义会出现"轴写了、代码不读"的静默失效（本轮 `ESD_None` 的实证）。
4. **"层数先落、数值后算"是硬顺序**：数值叠加轴在**物化边界**按 `Instance.Stacks` 成倍，故层数必须在本帧物化之前写入实例；反过来（先物化后写层数）会让本次叠层的数值停留在旧层数——一处没有编译期保护的顺序依赖，靠注释与装置读数钉住。
5. **装置新增检查时优先复用共享屏显段**：独立段基址（如 `Stacking(49)`）会与延迟段的基址（60）在屏显上重叠；共享 `Screen(10)` 段的游标天然不撞（日志行才是证据锚点，屏显只是给人看的）。
