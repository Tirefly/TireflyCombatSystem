## 1. 为什么必须退役「单位」而不是保留为"中文行文专用"

**旧裁定的原文**（`log-04-integration-m6.md:46`，2026-09-02 v2 修正）：

> **命名**：军官组件定名 `UCombatEntityComponent`；句柄同步更名 `FCombatEntityHandle`（与组件一致；**文档行文"单位（Entity）"不变**）。

⇒ 也就是说：**代码改了、行文没改**，于是形成"同一个概念两个词"的长期状态。本次裁定的判据是：
**该状态本身就是二义性来源**——读者必须靠上下文判断"单位"与"Entity"是不是同一个东西，
而这正是 `MEM-20261013-09` 记录的"同词异义 / 同义异词 ⇒ 误判关系"的温床。

**一处必须点名的连带风险（本裁决要消除的正是它）**：
「**两级单位**」中的"单位"**不是** Entity 的同义替换——它指的是"两类注册载体"。
⇒ 若不改名，后人读「两级单位」时会与"实体（Entity）"混为一谈；
**改为「两级实体」后，`D6-2` 的语义（Mass 小兵 + 全功能军官皆为实体载体）反而更准确**。

## 4. 实施纪律（由本裁决直接推出，MUST 守）

1. **先出假命中隔离清单**（本文 §2 即其载体；实施轮 MUST 按它设排除集），**MUST NOT 边改边发现**（裁决⑧）；
2. **脚本改写按"不可信操作"对待**（`MEM-20261001-09`）：先**整份备份到库外** → 加断言（`old.Length >= 4`、出现次数符合预期）→ **避免嵌套数组**（PowerShell 会静默展平）→ 改后**查不变量**（关键字符计数 / 括号奇偶 / 表格竖线数 / 文件名误伤）；
3. **MUST NOT 用 `-replace` + `Set-Content` 改源码**（`MEM-20260826-04`：会毁 UTF-8 与行尾）；源码改名的正解 = **机械可校验的批量操作走脚本 + 语义改写走编辑工具**（`MEM-20261003-11`），且改后**双配置编译**验证；
4. **冻结物加注记而非改正文**（裁决⑦）：注记形如
   > **术语订正（2026-10-14）**：本文原用「单位 / `Unit`」，该词已退役，现统一为「**实体 / `Entity`**」（见 `DEC-2026-10-14-entity-vocabulary`）。**正文为当时原话，保留不改。**
5. **收尾必须做"两词并存"反查**：全库 grep `\bUnit\b` 与 `单位`，
   逐处判定它属「活载体漏改」还是「冻结物真历史」——**冻结物真历史是唯一合法残留**。

## 5. ★ 实施期实证：一处**跨仓误伤**（MUST 读，防后人重犯）

**首次实施把 LAC 仓的 9 份文件一起改了**，其中多处**不属于 TCS 术语面**：

| 误改 | 原文 | 问题 |
|---|---|---|
| `格数单位` → `格数实体` | `docs/superpowers/**`（**TGFS 棋盘导航插件**的规格） | "单位"在这里是**计量义**（"以格为单位"）⇒ 语义完全错 |
| `TbnsNavUnitInfoProvider.h` → `…Entity…` | 同上（**另一个插件的类型名**） | 跨插件改名；该类型不属 TCS |
| `BR_WaitingStationaryUnit` → `…Entity` | 同上（**枚举值名**） | 同上 |
| `Category = "…|Unit"` → `"…|Entity"` | 同上（**UE 反射分类名**） | 同上 |
| `最小挑战单位` → `最小挑战实体` | `Documents/GameDesign/**`（LAC **策划文档**） | 这里"单位"是**流程量词**（"最小挑战单元"），不是 Entity |
| `杀光玩家方单位` → `玩家方实体` | `Documents/ProjectBaseline/**` | LAC 的"单位"是**棋子/战斗单位**的中文说法，与 TCS 的 `Entity` 概念不同层 |

**根因** = **把"含该词"当成"该词属于本概念"**，并让批量脚本**跨过了仓边界**——
同 `MEM-20261013-09`（词形相似 ≠ 语义相关）的根因，是它**当天的第三次**复犯。

**⇒ 由此推出两条本裁决的实施纪律（MUST，补入 §4）**：

6. **改名范围 MUST 按"概念归属"划，MUST NOT 按"词形出现"划**——`Unit` 在别处可能是
   计量单位（`格数单位`）、流程量词（`最小挑战单位`）、或**别的插件自己的概念**
   （`TbnsNav*` / `BR_WaitingStationaryUnit`）。**判据 = 该词所在的那个符号/句子，
   其语义是否就是 TCS 的实体**；答不出即**不属于本次范围**。
7. **MUST NOT 让命名类脚本跨仓**——TCS 与 LAC 是**两个仓、两套术语面**。LAC 侧的术语由
   LAC 自己的设计文档裁定；TCS 术语改名**只覆盖 TCS 仓**（LAC 侧只有**用到 TCS 类型**的
   宿主代码/装置需要跟随，且逐个判定）。

**处置（已完成）**：9 份误伤文件**用库外备份逐份还原**（不用 `git checkout`——那会丢掉
文件里可能存在的其他未提交改动），还原后 `git status` 确认 9 份全部干净。
