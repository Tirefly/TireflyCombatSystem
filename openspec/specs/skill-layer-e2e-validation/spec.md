# skill-layer-e2e-validation Specification

## Purpose

M5 技能层的**端到端竖切验收面**：把六个已各自取证的能力（`skill-def-asset` / `skill-registry` / `skill-cast-runtime` / `skill-param-chain` / `skill-cast-phases` 与属性账本）串成**一条真正跨到底的链**——真定义 → 授予 → 激活（六道具名门禁）→ 参数链折叠 → 起主链 → **链真改属性账本** → 四枚 `TcsEvent.Cast.*` → **三路终结（完成 / 打断 / 顶替）各按 `RunSource` 摘净**。

**为什么需要它**：六个能力各有独立证据，却**没有任何一条证据跨过它们的耦合点**——尤其是施法终结时的属性回收（台账 `CHAIN-7`）：它在单元面只能验到"回收函数被调了"，而真正要证的是"**该摘的摘净、不该摘的常驻**"。本能力把这条链固定成可复算的验收矩阵，并规定**读数取"属性现值 + 账本条目数"成对**、以及**同一次施法内的阴性对照**（另挂一条非本次来源的条目，验"没摘过头"）。

**边界**：本能力管**验收面本身**（命令形状与屏显段、三路读数的取法、跨帧时轴纪律、复现性摘要的不变量口径、两条执行路线的分工与边界登记义务），**不管**技能层各能力的实现语义——那些由各自的 `skill-*` 能力承载。装置住宿主仓（LAC `Source/TcsDev/`），属**宿主验收装置**而非插件运行时；跨帧等待骨架亦住宿主私有面，**未提升为插件契约**。

## Requirements

### Requirement: 技能层端到端竖切矩阵

项目 MUST 提供一条可在 PIE 中运行的宿主验收装置命令 `Tcs.Test.SkillLayer.Run`，让**一条真内容技能资产**
走完 Q-7 剧本全程：内容资产驱动的定义解析 → `GrantSkill` 授予 → `TryActivate` 逐道门禁 →
参数链带式折叠生效 → 起 `CastChainId` 主链 → 链内 `ModifyAttribute` 真改属性账本 →
`TcsEvent.Cast.*` 事件链可见 → 按终结点终结 → `RevokeSkill` 级联摘净。

该竖切 MUST 由**内容资产**（技能定义资产 + 效果链资产 + 修正器模板资产）驱动，
MUST NOT 以运行期手搓定义充当唯一路径；装置 MUST 为每个环节输出可检索的通过/失败行，
且在常规命令中保持零非预期红字。装置 MUST NOT 复用或加厚既有技能的验收资产
（`DA_SkillDef_E2E` / `DA_SkillDef_E2E_Second`）——它们的字段取值被 Task 1 / Task 2 的
既有读数钉死，改动即使既有能力的验收面失效。

#### Scenario: 真内容资产驱动的技能定义被发现并装配

- **WHEN** 在编辑器 PIE 中运行 `Tcs.Test.SkillLayer.Run`
- **THEN** 定义库就绪行含本变更新增的技能定义条数、装配行含技能定义已装配条数，
  且 `UTcsSkillSubsystem::GetRegisteredSkillDef` 按 `DefTag` 命中，其内容与定义库缓存**同一份**

#### Scenario: 授予到激活的门禁序列全程可读

- **WHEN** 装置以真内容资产的身份词调用 `GrantSkill` 后调用 `TryActivate`
- **THEN** 账本条目数由 0 增至 1、激活返回成功、`TcsEvent.Cast.Started` 恰一次，
  且该次激活的 `FTcsSkillInstance.RunSource` 有效

#### Scenario: 参数链折叠的结果真的进了本次施法的快照

- **WHEN** 该技能定义的 `ParamChainRows` 含至少两个不同运算带的行、且这些行的 `Source`
  为本次施法运行句柄
- **THEN** 折叠后的数值可从施法运行态的参数账本读出，且该读数与按五带合成顺序手算的结果一致；
  **判据 MUST 让"折叠生效"与"落兜底值"两个可能读数互不相同**

#### Scenario: 链真改属性账本且事件链可见

- **WHEN** 主链内挂 `ModifyAttribute` 的步骤执行
- **THEN** 目标属性现值按链写入的量变化、该属性上的账本条目数增加，
  且 `PhaseChanged` / `Completed` / `Interrupted` 三枚事件各自只在对应路径产生一次

#### Scenario: 撤销技能按来源级联摘净

- **WHEN** 装置调用 `RevokeSkill`（或 `RevokeSkillBySource`）撤销该条目
- **THEN** 该实体的账本条目数回到授予前的读数、该条目物化的参数链条目被摘净、
  且其它条目与其它实体的读数不变（**级联不越界**必须由对照实体读数证明）

### Requirement: 技能层拒绝面独立取证

项目 MUST 提供独立命令 `Tcs.Test.SkillLayer.Reject`，集中承载技能层的拒绝面，
使常规命令得以保持零非预期红字。拒绝面 MUST 至少覆盖：未登记定义的身份词、
未授予即激活、已撤销条目上的激活、悬空施法运行句柄上的查询与终结、
不可打断段上的打断与顶替、世界拆解后的门面访问。

每条拒绝 MUST 断言"**被拒 + 返回了那个具名值 + 留痕级别与实测一致**"，
MUST NOT 把 `Log` 级留痕当作 `Warning` 级断言，MUST NOT 以"计数器增加了"代替
"确实没有建条目 / 没有改账本 / 没有发事件"。命令 MUST 自带屏显声明"红字为预期"。

#### Scenario: 未授予即激活被拒且零副作用

- **WHEN** 对一个已登记定义但未授予该技能的实体调用 `TryActivate`
- **THEN** 返回具名的"未学该技能"结果、账本条目数不变、`TcsEvent.Cast.Started` 零次、不触发 `ensure`

#### Scenario: 悬空运行句柄的查询与终结静默返回

- **WHEN** 对一个已终结并归还池槽位的 `FTcsSkillInstanceHandle` 调查询口与终结口
- **THEN** 查询口返回保守值、终结口返回 `false`，均不触发 `ensure`，且不重复广播、不重复归还槽位

#### Scenario: 不可打断段上的打断与顶替各自被拒

- **WHEN** 当前时段不可打断时分别调用 `CancelCast` 与顶替路径的激活
- **THEN** 两者都被拒：打断返回 `false` 且运行态仍可解析、在飞读数不变；
  顶替返回具名的"已在飞"结果——**顶替门禁 MUST 走查询契约**（直读定义开关的实现必失败）

### Requirement: `CHAIN-7` 三路回收读数

证据文档 MUST 给出 `CHAIN-7`（链挂的账本条目随施法生命周期回收）的**三路闭合读数**——
**完成**（含瞬发当刻完成）、**打断**、**顶替**——每一路各取一读数。读数 MUST 取
**「属性现值 + 该属性上的账本条目数」成对**，MUST NOT 取"回收函数被调用了几次"
（后者在"调了但摘错 `Source`"时仍会全绿）。三路 MUST 各自可判，
MUST NOT 只验"完成"一路就 claim 统一终结例程成立。

对照组 MUST 为 R5 实测的"**常驻停在 X−5**"形态：**同一次施法内**，
由主链挂的条目随终结被摘净，而**非本次施法来源挂的条目仍常驻**——
该阴性对照 MUST 与三路读数在同一份证据里成对出现。

#### Scenario: 完成路径回退且条目数归零

- **WHEN** 一条真挂 `ModifyAttribute` 的主链随技能激活起链、把属性改掉，随后该次施法完成终结
- **THEN** 该属性回到链写入之前的现值、该属性上的账本条目数回到 0，
  且读数与"非本次来源的条目仍常驻"这条对照**互不掩盖**

#### Scenario: 打断路径与顶替路径同样回退

- **WHEN** 同上，但分别在**打断**（`CancelCast`）与**顶替**（同类技能再次激活）两个终结点终结
- **THEN** 两条路径下属性**同样**回到写入之前的现值、条目数同样回到 0——
  **三路读数各自可判**；只验一路无法发现"多份清理漂移"这一本需求要防的形态

#### Scenario: 瞬发技能的完成路径也回退

- **WHEN** 技能定义为**空时段表**（瞬发），链在激活当刻起并把属性改掉
- **THEN** 完成终结在激活流程末尾发生，属性回到写入之前的现值、条目数回到 0，
  且该 run 不滞留池中（在飞读数不增、账本 `RunHandles` 不留其句柄）

### Requirement: 跨帧判据的时轴与双路线取证纪律

跨帧判据（"等到某件事发生"）MUST 挂在**被测物自己的时轴**上。
具体地：取样时刻 MUST 依据**战斗时钟**（`FTcsClock.Elapsed`，按 `ScaledDt` 累加）判定，
MUST NOT 用 `FTimerManager` 的**未缩放真实时间**当取样依据——两者不同步，
且无头模式**首帧 `DeltaSeconds` 是常规帧的百倍量级**（首帧一次性补上加载期），
故"按固定墙钟秒数赌取样时刻"在两条路线上会得出不同结论。

轮询判据 MUST **轮询被测事件本身**（如"该运行态已从池中消失"），
MUST NOT 轮询一个与它相邻但不相同的量。超时 MUST **报 FAIL**、
MUST NOT 静默跳过或把"没等到"记为通过。

跨帧回调的一切捕获 MUST 为**值或弱引用**，MUST NOT 按引用捕获命令函数的形参或栈上局部量；
跨帧判据用到的计数器 MUST 有明确的跨帧持有者，MUST NOT 依赖任何栈帧存活。

**取证路线纪律**：凡改动含跨帧回调 / 捕获 / 持有期延长者，
取证 MUST **两条路线都跑**——无头 `UnrealEditor-Cmd` 与**编辑器内 PIE**，
MUST NOT 用前者替代后者。"无头全绿"**不构成**"验证过"。

#### Scenario: 跨帧等待挂在战斗时钟时轴上

- **WHEN** 装置需要等到一个时段到期或一个运行态终结
- **THEN** 取样依据是战斗时钟时轴，而**排定与观察的间隔**由轮询被测事件本身决定，
  不是由固定的墙钟秒数决定；两条路线上判据结论一致

#### Scenario: 超时如实报失败

- **WHEN** 轮询在预设上限内没有观察到被测事件
- **THEN** 装置报 `FAIL` 并给出已观察拍数与上限，MUST NOT 静默返回、
  MUST NOT 把未观察到记为通过

#### Scenario: 两条执行路线都必须跑

- **WHEN** 本变更的任意判据取读数
- **THEN** 无头与编辑器 PIE 两条路线各自成证：无头路线承担回归面与不依赖内容发现的判据，
  编辑器 PIE 路线承担内容资产驱动面；**仅有一条路线的读数 MUST 在证据里标为半边覆盖**

### Requirement: 双面读数与边界登记纪律

证据文档 MUST 同时给出**属性面**读数（属性现值与账本条目数）与**事件面**读数
（`TcsEvent.Cast.*` 四枚的广播计数），MUST NOT 以单面读数推断另一面的结论。
证据文档 MUST 记录装置输出冻结快照的字节数、行数与 SHA-256，以及关键日志行的引用，
MUST NOT 引用持续增长的实时日志行号——行号引用 MUST 在**已固定的快照**内可复现。

证据文档 MUST 附一份边界清单，逐条标注该边界是**已实测**还是**未覆盖**，
MUST NOT 以推断冒充实测。清单 MUST 至少覆盖：单机 / 单世界 / 单 PIE 进程的前提；
无头路线 `AssetRegistry` 发现 0 条资产这一机制限制及其承接轮次；
编辑器 PIE 读数由人工执行的取证形态；`CQM_Custom` / `MCS_Custom` 两处具名未实现；
子链挂的条目按设计常驻这一残留边界；Shipping 只验编译；以及"两轮读数只在
不变量上逐字一致、进程内单调量与帧驱动量本就不同"这一复现性判据的收窄。

#### Scenario: 属性面与事件面各自成证

- **WHEN** 证据文档记录竖切的每个环节
- **THEN** 属性面的通过由属性现值与条目数支持、事件面的通过由事件计数支持，
  不得由另一面的读数代替

#### Scenario: 未覆盖项不得隐去

- **WHEN** 某能力面本轮未被内容资产驱动，或某档位在本轮具名未实现
- **THEN** 清单中该项标注为"未覆盖"并给出理由与承接轮次，MUST NOT 记为通过

#### Scenario: 复现性判据只比不变量

- **WHEN** 判定两轮读数是否可复现
- **THEN** 判据是**摘要行逐字相同 + 各检查结论相同**；
  进程内单调计数器（来源句柄 id）与帧驱动量（轮询拍数）MUST NOT 进入该判据，
  快照的字节数与 mtime 只作 provenance、MUST NOT 当复现性判据
